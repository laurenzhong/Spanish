| 撤销点击后有加载时间、可以无限点击撤销（撤销又能再撤销），撤销卡片需要倒计时横条 | 已修：Toast 动作支持异步 —— 点击后进入 pending（按钮 `disabled` + `aria-busy`、文案变「撤销中…」、暂停自动消失计时），结算后才关闭；`read-shelf` 的撤销改为 **silent** 调用（更新状态与服务端但**不再推送新 toast**），因此不存在第二个「撤销」可点；Toast 卡片新增 `role="presentation"` 的**倒计时横条**（`transform: scaleX(1→0)`，随 `durationMs` 内联设置，`prefers-reduced-motion` 下由全局规则自动收敛）。测试：`toast.test.tsx` 11 例、`article-library.test.tsx` 12 例全绿（含"同 tick 双击只触发一次""撤销只发一次 POST 且不产生第二个撤销"） |

## 1. 前置：起一个带 E2E 登录的服务器

既有 dev server（3000 端口）**没有** `AUTH_E2E_ENABLED=1`，因此产品页只能看到登录页。复核产品页需要自己起一个：

```powershell
# 端口按需替换（例如 3300），distDir 单独一份，避免与别人的 .next 冲突
$env:AUTH_E2E_ENABLED = "1"; $env:NEXT_DIST_DIR = ".next-visual"
node node_modules/next/dist/bin/next dev --port 3300
```

浏览器侧写入测试会话（值就是用户 id；本仓库 e2e 约定见 `docs/authentication.md`）：

```js
await context.addCookies([{
  name: "spanish-e2e-user",
  value: "00000000-0000-4000-8000-000000000001",
  url: "http://127.0.0.1:3300",
}]);
```

注意：
- 该开关只在非 production 生效，禁止在手工部署里打开；
- 页面渲染会读真实库（只读）；若要跑探针，参考 `docs/tasks/PERF-SWEEP-001.md` 的注意事项（首次点击会叠加 dev 编译时间，需先热身）。
