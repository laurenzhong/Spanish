# 项目执行约束

本文件承接根目录 [AGENTS.md](../AGENTS.md) 的完整约束，适用于本仓库及其 worktree。路径若以 `docs/`、`src/`、`app/` 或 `apps/` 开头，均相对仓库根目录。它规定必须遵守的边界；领域文档解释具体实现，不另建一套约束。

## 1. 协作与任务范围

- `PROJECT_STATUS.md` 是当前阶段、任务分配和下一步的权威入口。
- 自主领取仅限状态为 `ready` 且没有其他负责人或活动分支的任务；用户直接指定的任务核对并发负责人无冲突后即可执行，不必等待 ready 登记，不据此重排其他任务。简单问答无需登记任务。
- 一个分支只处理一个任务 ID，分支名称优先使用状态页指定名称。
- 不修改其他模型负责的任务状态，不重新排列全局任务队列。
- 分支内发现超出范围的依赖时停止扩张，将决策交给协调者或用户；仅暂停依赖该决策的部分，继续完成范围内不受影响的工作。
- 分支完成后提供结构化交接：Commit、修改文件、测试、限制和建议下一步。
- 分支负责人在任务交接或重要状态变化时更新本分支状态页，记录 Commit、范围、测试、限制和下一步；不要求每个实现提交后追加文档提交。当前提交可用任务 ID 和提交标题定位，避免为记录自身 hash 反复提交。合并者负责在 `main` 对账、更新合并结论和分配下一任务，不维护额外平行日志。
- 跨多个会话的复杂任务才创建 `docs/tasks/<TASK-ID>.md`，并从状态页链接。

## 2. 产品不变量

任何实现不得破坏以下规则：

- 登录后的“学习”页必须直接展示真实可用的视频与播客资料库；不显示 Hero、“开始学习”“继续学习”或唯一任务 CTA，也不要求先选择时长、模式或内容类型。每张内容卡本身就是等权、真实的开始入口。
- 听说是核心；读写是静默环境下的延续，不等价于口语证据。
- 用户完整表达前不得纠错或打断。
- 评分以语境成功为先，不要求匹配唯一参考句。
- 自然替代表达可以完成交际任务。
- 打字不能提高发音、语流或真实口头反应。
- 词汇与短语考察不要求口头回答；选择、判断、语境填空和少量完整输入只更新适用的词句能力。
- 跟读证据只更新跟读表现，不能替代自主表达或交流运用证据。
- 低置信度转写和技术失败不能产生负面能力证据。
- 熟练度 `mastery` 与可信度 `confidence` 分离。
- 学习时长只用于热力图，不参与能力评分。
- AI 好友首先自然回应用户，教学目标只能创造机会，不能控制对话。
- 私密关系记忆默认不向其他角色共享。
- 角色不得把虚构房源、地点、线下约见或现实行动说成真实存在。
- 用户直接询问角色是否为 AI 时必须如实回答。

## 3. Alpha 范围

未经用户明确批准，不提前实现：

- 支付、订阅或商业额度。
- 完整内容管理后台。
- 实时双向语音通话。
- 大规模角色商城或开放角色创建。
- 独立微服务和复杂消息队列。
- Flutter 或原生移动/桌面客户端的功能同步与商店发布；当前个人 Alpha 只做响应式 Web/PWA 与 iPhone Safari。
- 本地离线 ASR 或用户音频媒体库。

这些能力是延后，不是永久取消。需要时先更新设计或 ADR，再进入实施计划。

当前允许实现仅供项目所有者使用的轻量“内容工作流”，用于白名单来源、候选审核、双维度批准、发布和撤下；它不是通用 CMS，不开放角色、用户、权限或页面搭建能力。

## 4. 架构规则

- 使用单仓库和远程模块化单体，不随意创建新的服务边界或新 Git 仓库。
- 目录优先按业务 feature 组织。
- 服务端 `domain` 保持纯 TypeScript，不依赖 React、Next.js、Drizzle、Supabase 或供应商 SDK。
- 当前活动客户端只有 Next.js 响应式 Web/PWA，覆盖桌面浏览器与 iPhone Safari；现有 Flutter 客户端保留在 `apps/mobile`，暂停功能同步，不删除或假称与 Web 等价。
- `content-acquisition`、`media` 和 `lexicon-corpus` 是独立业务模块；文章继续使用现有 article 模型，旧 `content_packs` 只作为历史兼容载体，不继续扩展为通用媒体库。
- 继续维护明确 DTO、OpenAPI/JSON Schema 和稳定错误码，为未来恢复多客户端保留边界；当前不要求 TypeScript/Dart 功能同步。
- 客户端状态不能成为能力事实；评分、证据、画像、记忆权限和角色安全必须由服务端重新校验。
- 未经新的 ADR，不新增 Flutter 平台插件、Swift/Kotlin/Windows 桥接或原生页面。
- Route Handler 只负责鉴权、Zod 校验、调用 application 用例和协议转换。
- React 组件不直接访问数据库，不承载复杂业务流程。
- Application 层定义事务边界并调用 repository/provider 接口。
- 模块不能直接写其他模块拥有的数据表。
- `shared` 只能包含真正无业务含义的通用能力，不能变成杂物目录。
- 公共接口使用明确 DTO，不把数据库行类型扩散到 UI 和其他模块。
- 先允许局部重复，模式稳定后再抽象；不要预建万能框架。

## 5. 状态与异步可靠性

- 复杂训练流程必须使用可测试的状态机或纯编排器。
- 每次录音、转写、评估和聊天生成使用 `attemptId`/`generationId`。
- 旧 generation 的回调不得更新当前状态。
- 副作用必须可取消，并显式处理取消、超时、重试和异常断流。
- 谁创建资源谁负责释放；录音、流、定时器和对象 URL 都要有明确生命周期。
- 没有显式 `done` 的消息流不能当作成功完成。
- 写操作必须考虑幂等；重试不能重复生成证据、消息记忆或供应商费用。
- 错误、加载、空状态和恢复路径必须显式设计。

## 6. 数据规则

- PostgreSQL 是学习证据、画像和关系记忆的权威来源。
- `evidence_events` 只追加，不原地修改历史评分。
- `user_skill_states` 是可重算快照，不是原始事实。
- 每条尝试保存实际内容版本、算法版本和供应商信息。
- 客户端不能直接写证据、画像和关系记忆。
- 所有用户私有数据必须受 RLS 和服务端所有权检查保护。
- 数据库结构只通过版本化迁移变更。
- 不手工修改生产数据库来绕过迁移。
- 删除或匿名化用户数据时遵循文档化顺序并报告结果。

## 7. 语音、AI 与供应商

- 业务模块只依赖内部 provider 接口。
- API 密钥只存在服务端。
- 供应商响应必须转换为内部类型并通过 Zod 校验。
- 记录供应商、模型版本、延迟、请求 ID、置信度和估算成本。
- 普通聊天不默认调用高成本严格发音评分。
- 地点、活动、交通和房源信息必须可验证；无法验证时只能给一般建议。
- LLM 输出不能直接写入画像、人物圣经或关系记忆，必须经过规则和权限检查。
- Prompt 不是安全边界；关键不变量必须由代码校验。

## 8. 内容规则

- 正式内容遵循 `docs/content-authoring.md`。
- 自动采集只允许所有者配置的白名单来源；每日任务最多把素材推进到候选审核库，不能自动直接发布。
- 无字幕媒体只有在来源、相关性、语言、时长、权利和预算门禁通过后才能生成 ASR 草稿；临时音频在成功、失败、取消或超时后立即删除。
- 核心表达必须包含语境、语用、变式、提示、标签权值和审核状态。
- 未审核内容不能在生产环境发布。
- 当前仅供项目所有者本人使用的产品阶段，由 Codex 独立完成核心表达/语用的 `es-ES` 语言审核与中文教学说明的 `zh-CN` 教学审核；记录必须使用 `codex-ai-owner-authorized-review` 并明确 AI 身份，不得描述为真人、母语者或教学专家签字。
- 产品开始邀请、允许或面向其他真实用户使用前，必须新增 ADR 重新决定外部母语与教学复核门槛；当前所有者授权不得自动扩展到多人产品。
- 内容导入必须先完整校验，再事务写入；失败时不得部分发布。
- 已产生学习证据的内容版本不能静默覆盖。
- 外刊和第三方内容必须保存来源与许可；禁止未经授权复制全文。
- 非盈利、个人使用或尚未发布不取消来源、平台条款、许可、署名和撤下义务；不得绕过付费墙、访问控制、DRM 或平台下载限制。
- 所有者指定视频下载统一使用 yt-dlp，安装匹配的官方 EJS 依赖并启用支持的 JavaScript runtime；浏览器仅用于播放验收，不使用 SourceBuffer 抓取或录屏替代下载。授权本地原文件导入及自有存储完整性读取按媒体运行手册处理。
- AI 生成内容仍先进入草稿，不因生成者与审核者同为 Codex 而自动获得发布资格；必须经过独立的双维度审核、版本化修订和完整校验。

## 9. 角色与记忆规则

- 人物圣经和单个用户的关系记忆分开存储。
- 角色固定事实版本化，新增事实先做冲突检查。
- 必须区分“人物设定存在”和“已经向当前用户透露”。
- 候选记忆保存来源、置信度、敏感级别和共享范围。
- 教学画像不能被当作角色间闲聊资料。
- 新角色获得用户信息前需要明确共享许可。
- 记忆冲突时暂停写入，不能让模型自行编造解释。
- 只有完整完成的聊天轮可以提取长期记忆。

## 10. 测试要求

所有功能和修复遵循 [测试策略](testing-strategy.md)。

最低要求：

- 新领域规则有单元测试。
- 状态机变更覆盖合法、非法、失败和过期回调。
- 数据访问变更覆盖 RLS、幂等或事务边界。
- 供应商适配器有契约测试和 fake。
- 关键用户路径变更更新 Playwright 测试。
- 行为缺陷优先用现有或新增回归测试复现；已有测试足以覆盖时不重复增加。纯文字、样式等低风险修改采用适当静态或视觉检查，不削弱上述领域、状态机、权限与事务测试要求。

禁止：

- 删除测试或放宽关键断言来通过 CI。
- 用真实收费供应商运行默认测试。
- 用页面快照替代评分和状态流转断言。

按变更影响选择检查；开发中优先运行相关测试，未修改代码的文档任务只做静态检查。下列是命令入口，不是每轮必跑清单：

```powershell
pnpm lint
pnpm typecheck
pnpm test --run
```

涉及 Flutter 客户端时还需运行：

```powershell
flutter analyze
flutter test
```

在没有 Mac/Xcode 的环境中，不得把 Flutter 公共测试通过表述为 iOS 编译或真机验证通过。

跨模块、迁移或发布候选还需运行：

```powershell
pnpm test:e2e
pnpm build
```

## 11. 隐私与日志

- 普通录音评测完成后删除。
- 长期保存录音必须由用户明确确认。
- 日志不得写入原始录音、完整私密对话、访问令牌、API 密钥或长期有效签名 URL。
- 使用 hash 或内部 ID 关联用户，不在普通诊断日志记录邮箱和姓名。
- 新增埋点前说明用途、字段和保留时间。
- 使用用户数据改进模型需要单独、明确同意。

## 12. Git 与文件安全

- 保留用户和其他代理的已有改动，不覆盖无关文件。
- 不使用 `git reset --hard`、强制 checkout 或未授权清理。
- 不提交 `.env`、密钥、录音、生产数据或本地参考仓库。
- 不提交 Apple 签名证书、provisioning profile、私钥或未加密商店凭据。
- 提交保持单一目的，标题使用清晰英文前缀，例如 `docs:`、`feat:`、`fix:`、`test:`、`refactor:`。
- 提交后的状态同步按第 1 节执行；新增子任务、调整顺序或改变范围时，同时更新实施计划和相关架构、隐私或测试文档。
- 当前仓库未复制 Echo-Loop 源码或资源。用户说明自己曾参与贡献并得到作者允许，后续可以建立专门任务评估复用；实际复制前必须在仓库记录授权人、授权形式、文件/提交范围、商业与闭源许可、署名要求，以及其他贡献者代码是否被覆盖。无法证明额外授权覆盖的部分继续按 AGPL-3.0 处理。

## 13. 文档与 ADR

以下变更必须同步更新文档：

- 产品不变量或 Alpha 范围。
- 模块边界和公共接口。
- 数据模型和迁移策略。
- 评分、画像或推荐算法语义。
- 角色身份、记忆共享和隐私策略。
- 供应商选择和数据保留方式。

重大架构决策写入 `docs/adr/NNNN-short-title.md`，包括背景、决定、替代方案和后果。文档分工、证据标签与维护检查见 [文档导航与维护](README.md)。

## 14. 任务完成定义

完成任务前检查：

1. 实现范围与当前计划一致，没有顺手加入延后功能。
2. 适用于本轮改动的类型检查、相关测试或文档静态检查通过；没有新改动或未解决问题时不重复扩大验证。
3. 受影响流程的错误、取消、空状态和竞态已处理。
4. 没有能力评分污染、越权数据访问或敏感日志。
5. 文档、Schema 和迁移与实现一致。
6. 本轮新增改动仅覆盖授权范围；已有用户或其他代理的修改保持不变，不要求整个工作树干净。
7. 已向协调者提供状态页需要的 Commit、测试和下一步信息。

最终交付说明必须包含：

- 完成的任务。
- 修改的文件。
- 执行的测试及结果。
- 未执行的全量检查及原因。
- 用户可以如何验证。
- 已知限制和下一项建议任务。
