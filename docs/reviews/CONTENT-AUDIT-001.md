## 1. 统计口径

读取当前配置数据库，以 `media_items.current_version` 指向的版本为准，去重到稳定内容键。

与当前 `drizzle-media-repository.ts` 的目录规则对齐：

1. 版本为 `published`，版权状态为 `cleared`。
2. 有 `available` 且未过期的资产。
3. 视频额外要求 `kind=video`、`provider_key=bunny-storage`；播客沿用当前仓库的资产选择规则。
4. 不把旧版本、草稿、候选及已撤下内容加到正式数量。

这里的“可见”表示通过数据库目录门禁。本轮没有下载媒体、逐条探测 CDN 或验证浏览器实际播放，因此不等同于 172 条均已实播验收。

全程使用 `REPEATABLE READ READ ONLY` 事务，并核验 `transaction_read_only=on`。只查询内容、来源、候选和处理记录；没有读取用户画像、私密对话或学习进度。快照不保存密钥、数据库地址、媒体签名 URL 或完整字幕。

建议将 **12 条（6 条视频、6 集播客）** 作为下一实施切片的目标，六种场景各配一条视频和一集播客：

| 场景 | 优先出现的交流动作 |
| --- | --- |
| 购物、餐饮 | 询价、点单、替换要求、确认账单 |
| 租房、居住 | 询问条件、说明问题、约时间、请求维修 |
| 预约、看病 | 预约时间、描述不适、确认用法、请求复述 |
| 出行、办事 | 问路、确认线路、说明目的、确认所需材料 |
| 朋友、日常聊天 | 接话、邀请、婉拒、改约、澄清误会 |
| 工作、学习 | 提问、请求帮助、确认任务、说明进度 |

选材目标：8 条 A2、4 条 B1；视频约 3–8 分钟，播客约 4–10 分钟。以上是编辑目标，不是现有候选的可交付数量承诺。优先检查现有白名单；若找不到合适素材，在后续实施任务中按现有来源与审核流程补候选。

单条应有清晰的交流语境、可迁移的说法、完整双语字幕及可信难度/地区信息。先完成内容复核和发布门禁，再计为新增。现有媒体保持原版本，不为达到短时长目标擅自裁剪、重命名或覆盖已产生学习证据的内容。

另建议将主题映射、泛化日常标签和地区误标作为单独任务处理；不在本盘点中扩大成页面、Schema 或算法改造，不调整全局队列及其他任务状态。
