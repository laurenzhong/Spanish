# Echo-Loop 参考评审

- 参考仓库：[echo-loop/Echo-Loop](https://github.com/echo-loop/Echo-Loop)
- 评审日期：2026-08-20
- 仓库状态：公开、Flutter/Dart、AGPL-3.0
- 宣传网站：[echo-loop.top](https://www.echo-loop.top/zh-CN)，Next.js/Vercel，与 Flutter 客户端分离
- 评审目的：提炼可用于西班牙语沉浸式口语平台的产品与工程模式；源码复用另走授权审查

## 1. 结论

Echo-Loop 是非常有价值的同类参考。它已经验证了一条重要产品判断：语言学习产品不应把练习步骤全部交给用户选择，而应自动组织输入、拆解、模仿、输出和复习，让用户打开产品后直接知道下一步做什么。

双方的核心差异也很明确：

| 维度 | Echo-Loop | 本项目 |
|---|---|---|
| 核心单位 | 一段真实音频 | 一个可迁移的交际目标 |
| 主要闭环 | 盲听 → 精听 → 跟读 → 复述 → 间隔复习 | 情境输入 → 理解 → 独立输出 → 提示 → 迁移 → 对话 → 证据更新 |
| 内容来源 | 用户导入与官方音频材料 | 审核后的核心表达、场景、内容包和角色世界 |
| 评分重点 | 跟读文本覆盖与训练完成 | 语境成功、独立程度、自然度、可理解度和迁移 |
| 陪练关系 | 通用 AI 助手正在建设 | 长期 AI 好友与关系网络是核心体验 |
| 客户端技术 | Flutter 覆盖 iOS、Android、Windows、macOS | Next.js 完整 Web + Flutter 四平台客户端 |
| 网站 | 独立 Next.js/Vercel 宣传与在线服务 | Next.js 完整学习产品、PWA 与公开页面 |
| 数据权威 | Flutter 本地数据库占重要位置 | 服务端 PostgreSQL 是证据、画像和关系记忆权威 |

因此，Echo-Loop 适合作为学习流程、Flutter 多平台边界与工程可靠性的参考，不应成为产品结构或代码实现的模板。

## 2. 直接采用的原则

### 2.1 自动推进与单一继续入口

Echo-Loop 把多个训练阶段串成自动闭环，降低用户判断“现在练什么、练几遍、何时复习”的决策成本。这与本项目首页只保留“继续学习”的原则一致。

本项目采用：

- 推荐器产生唯一的下一学习动作。
- 每个表达和每个 3–5 题微循环都有自然停止点。
- 退出时自动保存；再次进入直接恢复，不要求重新选择时长和模式。

### 2.2 纯流程引擎与外部能力端口

Echo-Loop 的跟读流程把播放、录音、评估和倒计时编排为独立状态机，并通过回调调用外部能力。这个边界非常适合我们的训练引擎。

本项目采用：

- 服务端训练、评分和权限规则保持为无 UI、无数据库实现、无供应商 SDK 的纯 TypeScript 领域逻辑。
- Web 与 Flutter 客户端分别实现即时训练编排，通过共同 JSON fixtures 验证相同状态语义。
- 浏览器录音、Flutter 音频、TTS、服务端评估和持久化通过明确端口接入。
- React 组件和 Flutter Widget 只渲染状态并发送用户动作，不直接写能力事实。

### 2.3 异步 generation token

Echo-Loop 在播放和流式聊天中使用递增 token/sequence，使旧请求完成后不能覆盖新会话状态。

本项目采用：

- 每次训练步骤、转写、评分和聊天生成都有 `generationId` 或 `attemptId`。
- 客户端只接收当前 generation 的回调。
- 服务端写入使用幂等键和状态前置条件，避免重试重复生成证据。

### 2.4 断点续学是领域能力

Echo-Loop 为不同训练阶段保存句子索引和更新时间，而不是只保存一个模糊的课程完成百分比。

本项目采用：

- 保存当前微型目标、任务、变体、提示级别和未完成尝试。
- 每次有效步骤完成后写入断点。
- 断点过旧或内容版本变化时安全迁移到最近的稳定节点，不盲目恢复过期 UI 状态。

### 2.5 快照与事件分离

Echo-Loop 的记忆调度设计将当前调度快照与复习事件分开，并使用版本号与乐观并发控制。这一模式适合用户技能画像。

本项目采用：

- `evidence_events` 只追加，保留可审计的原始学习证据。
- `user_skill_states` 是可重算的当前快照。
- 更新使用事件幂等键和版本字段。
- 算法升级通过版本化重算或显式迁移完成，不静默改写历史证据。

### 2.6 流式协议必须有明确终态

Echo-Loop 的 NDJSON 流区分 `done`、用户取消、服务端异常断流和协议错误，避免把不完整回复伪装成成功。

本项目采用：

- 流式消息协议包含 `meta`、`delta`、`done` 和结构化 `error`。
- 自然断流但没有 `done` 视为失败，可重试并保留用户草稿。
- 用户主动停止可保留已经生成的自然部分，但不能触发完整消息的记忆提取和学习评分。

### 2.7 流程测试优先于页面截图测试

Echo-Loop 的集成测试关注跨页面状态传递、完成后的进度更新和断点恢复。这比只测试按钮存在更有价值。

本项目采用：

- 单元测试覆盖状态机、证据计算和推荐规则。
- 集成测试覆盖数据库事务、RLS、幂等和供应商适配器。
- Playwright 覆盖“继续学习 → 输出 → 反馈 → 画像更新 → 恢复”的完整路径。

## 3. 需要改造后采用的模式

### 3.1 固定训练阶段改为目标驱动计划

Echo-Loop 的音频训练阶段相对固定。本项目不能让每个表达机械走完全部步骤，而应根据熟练度、可信度、环境和历史证据生成任务计划。

改造方式：

- 新内容展开输入、解析、模仿和迁移。
- 已熟练内容直接进入陌生变体或随机追问。
- 静默模式替换口语输出，但标记口语待验证。
- 用户一旦证明能力，后续只做抽样复核，不重复整套训练。

### 3.2 跟读匹配改为多层证据评估

Echo-Loop 当前公开的跟读匹配使用目标文本与转写文本的宽松词级比对。这适合跟读覆盖率展示，但不适合自由表达。

改造方式：

- 跟读任务可以使用文本对齐作为一个低层信号。
- 自由回答先判断交际任务是否完成，再判断自然度、准确性和可理解度。
- 自然替代表达不能因没有命中预设词而失败。
- 低置信度转写不得产生负面能力证据。

### 3.3 本地优先进度改为服务端证据源

Echo-Loop 的 Flutter 应用重视本地数据库和离线能力。本项目的个人 Alpha 首先需要跨设备一致的学习画像和角色记忆。

改造方式：

- 服务端 PostgreSQL 是证据、画像和关系记忆的唯一权威来源。
- 客户端只缓存当前会话、内容和未发送草稿。
- 网络失败时允许继续浏览已加载内容和保存草稿，但不伪造已同步状态。

## 4. Alpha 暂不采用

- 用户本地音频导入、字幕配对和媒体库管理。
- 本地离线 ASR、模型下载和多媒体转码。
- 固定 6 小时到 28 天的七轮复习表。
- 支付、订阅、AI 配额和多渠道购买系统。
- 大量平台特定音频后台能力。
- 将单一总学习时长或词汇量作为主要进步指标。

Flutter 多平台工程已调整为 Alpha 正式技术路线，但不会照搬 Echo-Loop 的 Riverpod/Drift 组织、数据模型或实现代码。状态管理和本地数据库的具体选择在 Flutter 脚手架任务中依据本项目的服务端权威数据模型决定。

其余功能有的属于后续阶段，有的与本项目定位不符。只有在 Alpha 数据证明需要时才重新评估。

## 6. 对实施计划的具体影响

以下工作已经纳入个人 Alpha 实施计划：

1. 训练引擎先建纯状态机，再接 UI 和供应商。
2. 所有异步链路使用 generation token 与幂等键。
3. 学习证据采用追加事件，画像采用可重算快照。
4. 每个训练步骤都支持断点保存和安全恢复。
5. AI 消息流必须显式结束，异常断流不能写入完整记忆。
6. 测试优先覆盖状态流转、恢复、竞态和跨模块闭环。
7. 建立 Flutter 客户端，以少量平台桥接覆盖 iOS 特有能力，并为 Android、Windows、macOS 保留同一代码线。
8. Next.js 网站与 Flutter 客户端共享版本化 API、内容源和跨语言一致性样本；如需复用 Echo-Loop 代码，先完成第 5 节授权记录。
