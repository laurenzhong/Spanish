# 测试与质量策略

- 适用范围：个人 Alpha
- 目标：优先防止能力评分污染、用户数据越权、流程无法恢复和 AI 角色失真

## 1. 测试原则

- 优先测试状态流转和领域规则，而不是只测试页面元素存在。
- 外部 AI、语音和地点服务必须通过内部契约隔离。
- 测试必须覆盖失败、取消、过期回调、重试和重复提交。
- 技术失败不得产生负面能力证据，这是最高优先级不变量。
- 数据隔离、删除和记忆共享属于产品功能，必须自动测试。
- 高成本 E2E 只覆盖关键纵向路径，细节下沉到单元和集成测试。

## 2. 工具基线

计划使用：

- Vitest：领域和 application 单元测试。
- React Testing Library：组件交互和可访问性。
- Playwright：手机视口端到端测试。
- Supabase CLI 或隔离测试数据库：迁移、RLS 和事务测试。
- 固定 fake adapters：默认测试不调用收费供应商。

具体版本在工程脚手架阶段锁定。

## 3. 测试层级

### 3.1 领域单元测试

覆盖纯 TypeScript：

- 训练状态机。
- 训练计划生成。
- 提示依赖和输出方式可靠度。
- 证据强度和重复衰减。
- 技能快照更新。
- 场景状态判定。
- 推荐候选排序。
- 人物事实冲突。
- 记忆分类和共享权限。

要求：

- 不访问网络和真实数据库。
- 时间、随机数和 ID 可注入。
- 同一输入产生确定结果。
- 每个 bug 修复先添加可以复现问题的测试。

### 3.2 Application 集成测试

覆盖：

- 事务边界。
- 幂等提交。
- 乐观并发。
- 证据事件与技能快照一致性。
- 断点保存和恢复。
- 内容版本切换。
- 完整消息后记忆提取。
- 异常断流不提交完整记忆。

### 3.3 数据库与 RLS 测试

必须验证：

- 用户 A 不能读取或修改用户 B 的学习和关系数据。
- 浏览器角色不能直接写证据、画像和关系记忆。
- 未发布内容不会通过公开查询返回。
- 普通证据事件不能更新或删除。
- 删除账号按政策清除或匿名化数据。
- 迁移可以从空库执行，也可以从上一版本升级。

### 3.4 供应商契约测试

为每类供应商维护固定输入集：

- STT：清晰西语、噪声、静音、口音、截断和错误格式。
- 发音：目标句、明显音素错误、语流停顿和无有效语音。
- LLM 评估：标准答案、自然替代、部分成功、无关回答和注入文本。
- LLM 对话：完成、超时、取消、异常断流和结构损坏。
- 地点：有效结果、过期信息、无结果和来源缺失。

契约只断言内部统一格式和错误分类，不把供应商专有字段泄漏到业务测试。

### 3.5 组件测试

重点覆盖：

- 录音权限拒绝后出现打字入口。
- 用户说话期间不出现纠错。
- 提示逐级展开且记录级别。
- 反馈默认只突出关键问题。
- 流式聊天停止、重试和草稿保留。
- 数据不足的八维图不会绘制虚假分数。
- 键盘和屏幕阅读器可以完成主流程。

### 3.6 端到端测试

使用手机视口覆盖少量高价值路径：

1. 登录 → 初次诊断 → 有限画像。
2. 继续学习 → 语音输出 → 反馈 → 画像更新。
3. 麦克风拒绝 → 打字输出 → 口语待验证。
4. 使用三级提示 → 证据强度降低。
5. 刷新页面 → 从稳定断点恢复。
6. 阅读内容包 → 打字回复 → 后续口语复核。
7. Lucía 对话 → 完整流结束 → 关系记忆。
8. 异常断流 → 重试 → 不产生重复记忆或证据。
9. 好友介绍 → 用户同意 → 最小信息共享。
10. 用户查看并删除关系记忆或保存录音。

## 4. 核心不变量测试矩阵

| 不变量 | 必须存在的测试 |
|---|---|
| 自然替代表达不判失败 | evaluator 单元 + 固定 LLM 回放集 |
| 打字不提高发音和语流 | evidence/profile 单元 + E2E |
| 低置信度转写不扣分 | evaluator 单元 + STT 契约 |
| 技术失败不污染画像 | application 集成 + E2E |
| 重复同句不能无限刷分 | evidence 单元 + 数据库幂等 |
| confidence 下降不降低 mastery | profile 单元 |
| 旧异步结果不能覆盖新状态 | training/chat 竞态测试 |
| 没有 done 的流不是完成 | 流协议单元 + application 集成 |
| 私密关系记忆不自动共享 | memory 单元 + RLS/集成 |
| 场景掌握需要口语覆盖 | scene status 单元 |
| 学习时长不参与能力评分 | profile 单元 |
| 用户说话时不被纠错 | 组件测试 |

## 5. 训练状态机测试

每个状态至少测试：

- 合法事件产生正确下一状态和 effect。
- 非法事件不会改变状态。
- 退出和取消会清理活动 effect。
- 过期 `generationId` 被忽略。
- 录音完成、转写失败、评估失败分别可恢复。
- 语音切换打字保留同一学习目标。
- 提示级别只增不减，并写入尝试记录。
- 完成微循环创建稳定断点。

使用表驱动测试覆盖状态 × 事件组合，避免只测试一条 happy path。

## 6. 评分回放集

建立版本化评估样本：

```text
tests/fixtures/evaluation/
  contextual-success.json
  natural-alternatives.json
  common-errors.json
  low-confidence-transcripts.json
  prompt-dependence.json
```

每个样本包含：

- 情境和交际任务。
- 参考表达，但不作为唯一答案。
- 用户输出和输出方式。
- 转写置信度。
- 预期语境结果和允许范围。
- 不应更新的技能。
- 人工解释。

任何 evaluator 或 prompt 变更都运行完整回放集并比较差异。

## 7. AI 角色质量评测

固定对话集至少覆盖：

- 用户开心、焦虑、抱怨和不想学习。
- 用户突然换话题。
- 用户给出兴趣、学校和城市计划。
- 用户抱怨房东等私密信息。
- 用户询问角色年龄、住所、专业和是否为 AI。
- 用户要求真实餐厅、活动、房源或线下约见。
- 角色准备介绍新好友。

评测维度：

- 是否先回应用户真实内容和情绪。
- 是否保持人物语气和已知事实。
- 是否自然继续对话。
- 是否出现教学腔或强行目标句型。
- 是否泄漏其他关系记忆。
- 是否把虚构地点或行动当作现实事实。
- 直接询问是否为 AI 时是否如实回答。

角色 prompt、人物圣经或记忆策略变更后必须运行该评测集。

## 8. 时间、成本与性能

Alpha 性能预算：

- 首页已登录数据尽量在 2 秒内可交互。
- 本地状态切换和提示展开不等待网络。
- 聊天先显示已发送消息和自然处理状态。
- 记录 STT、评估、首 token 和完整响应的 p50/p95。
- 供应商调用测试默认使用 fake；真实回归集限制次数并单独触发。

成本测试：

- 每次训练和聊天保存估算调用成本。
- 防止重试或竞态导致重复收费调用。
- 普通聊天不默认调用严格发音评分。

## 9. 隐私与安全测试

- 上传 URL 短期有效且只能写指定对象。
- 文件类型和大小限制不能只在客户端实现。
- 普通录音处理后按策略删除。
- 日志快照扫描不包含令牌、完整对话或签名 URL。
- prompt injection 不能绕过地点验证、记忆共享和评分 Schema。
- 用户删除数据操作要求重新确认身份并记录结果。

## 10. 测试命令

工程建立后的基线命令：

```powershell
pnpm lint
pnpm typecheck
pnpm test --run
pnpm test:e2e
pnpm build
```

开发过程中优先运行相关测试。跨模块、迁移、发布候选或用户明确要求时运行全套。

## 11. 合并门禁

代码合并前必须：

- 相关测试通过。
- 新规则有单元测试。
- 新失败分支有测试或明确说明无法自动化的原因。
- Schema/迁移同步更新。
- 内容变更通过自动校验和所需人工审核。
- 没有新增敏感日志。
- 受影响文档已更新。

禁止通过删除测试、放宽关键断言或跳过 RLS 来让检查变绿。

## 12. 人工 Alpha 检查

自动测试不能替代以下人工体验：

- 是否愿意继续说或聊。
- 反馈是否显得可信和克制。
- 训练是否像真实沟通而不是题库。
- Lucía 是否像持续存在的朋友。
- 手机端录音、键盘切换和单手操作是否自然。
- 八维图和进步证据是否真的帮助定位问题。

每周将人工发现转化为可复现样本；能自动化的回归必须加入测试集。
