# Spanish 前端视觉与交互设计方案

**日期：** 2026-08-22  
**状态：** Draft，等待产品确认后进入实现计划  
**范围：** Next.js Web/PWA 的产品壳层、学习、训练、探索、对话、我的页面；Flutter 只同步语义令牌和交互原则，不共享 UI 源码。

## 1. 设计目标

Spanish 不是“背单词游戏”，而是帮助已经学过一些西班牙语、却在真实交流中反应慢或不敢开口的成年学习者，把被动知识变成可以迁移的口头能力。

视觉升级需要同时服务三个结果：

1. 打开后立即知道下一步该做什么，不被课程目录、时长选择或分数打断。
2. 让用户感觉自己在一个可信、有温度的西语生活空间中，而不是在填写训练表单。
3. 用证据、状态和可追溯表现表达进步，不用连续打卡、虚假精确分数或游戏化奖励制造压力。

不在本方案中增加支付、实时双向语音、角色商城、完整内容后台或新的服务边界。

## 2. 用户与使用场景

### 核心用户

- A2–B1 成年学习者，已经认识不少词和语法，但开口时需要较长反应时间。
- 有旅行、工作、迁居、兴趣社交或长期语言目标，不希望被当成儿童用户对待。
- 同时使用手机碎片时间和桌面端较完整的练习时间。
- 反感“答错即扣分”，希望知道自己的表达是否被理解，以及下一步最值得验证什么。

### 关键情绪

用户进入产品前常有“我其实懂，但说不出来”的挫败和暴露感。录音时最需要安全感，反馈时最需要可信度，聊天时最需要被当作一个人回应，而不是被教学目标牵着走。

### 高频场景

| 场景 | 时长 | 设计重点 |
| --- | --- | --- |
| 碎片练习 | 3–5 分钟 | 首页一个明确下一动作，快速恢复上次保存点 |
| 完整口语微循环 | 10–15 分钟 | 大型语音入口、渐进提示、说完后再反馈 |
| 不方便发声 | 5–20 分钟 | 听/读/打字可继续，明确“之后需要口语验证” |
| 晚间社交聊天 | 5–30 分钟 | 真实私信结构，教学信息退到按需查看 |
| 周度复盘 | 5 分钟 | 代表性证据、场景状态、需要验证的能力 |

## 3. 竞品与设计知识库观察

本次快速研究使用 `ui-ux-pro-max` 的 product/style/color/typography/ux 数据，并查看了公开产品页面：

- [Speak](https://www.speak.com)：首页反复强调“start speaking”“Real conversation. No pressure.”，说明口语产品需要把开口动作放在第一视觉层，并降低被评判感。
- [Tandem](https://tandem.net)：以“找伙伴、开始聊天”为核心路径，验证了关系网络可以成为学习持续性的入口。
- [Beelinguapp](https://beelinguapp.com)：用“看、听、学”和平行文本承接安静场景，支持本产品的静默模式，但阅读不能直接冒充口语掌握。
- [Duolingo](https://www.duolingo.com)：代表短反馈循环和强反馈产品，但其高饱和奖励、角色化游戏语法不适合作为本产品的成年高级感主视觉。

知识库给语言学习产品的默认建议是 Claymorphism、鲜艳色和进度奖励；这适合低龄或游戏化产品，却会削弱本产品的可信度和关系沉浸。因此方案采用“编辑感的留白与网格 + 温暖的人文色 + AI 原生的语音状态”，只保留轻量微交互，不复制任何竞品品牌、布局或独特资产。

## 4. 视觉方向选型

### 方向 A：Quiet Madrid / 安静的马德里（推荐）

温暖纸面、墨绿色文字、砖红动作色、海绿色证据色，配合少量编辑式衬线字和生活化摄影。卡片不做厚重 3D，使用清晰边界和很轻的阴影；页面像一本现代城市生活杂志，但交互仍然是高效的产品工具。

- 优点：成年、耐看、可信，能同时容纳训练工具和 Lucía 关系。
- 风险：即时奖励感弱，需要用“下一步”和“真实能力”文案保持动机。
- 适用：整个 Alpha Web；可平移到 Flutter 的 Material/Cupertino 主题。

### 方向 B：Cobalt AI / 深蓝 AI 工作台

保留现有蓝色基因，使用深蓝、冷白和半透明表面，强调语音波形、状态脉冲和 AI 处理反馈。

- 优点：迁移成本低，技术感强，训练状态表达清楚。
- 风险：容易像普通 AI SaaS，和真实社交关系的温度不足；半透明层过多会降低可读性。
- 适用：若 Alpha 反馈显示用户更重视数据和工具效率，可作为后续深色模式或训练专用主题。

### 方向 C：Citrus Play / 柑橘学习场

靛蓝、橙色、圆角软块和明显的进度动效，直接借鉴教育产品的“即时奖励”语法。

- 优点：新用户理解成本低，完成动作反馈强。
- 风险：偏儿童化，容易把真实能力简化成分数和打卡，不符合产品不变量。
- 适用：只可用于初次诊断或少量成就状态，不能作为全站主风格。

**决定：** 采用方向 A。方向 B 的语音状态表达和方向 C 的局部鼓励反馈可以作为辅助语法，但不改变整体品牌气质。

## 5. 品牌语法

### 关键词

`有人情味`、`留白`、`口语优先`、`城市生活`、`可信证据`、`轻盈而不幼稚`。

### 明确避免

- 大面积紫色渐变、霓虹光晕、玻璃叠玻璃。
- 连续打卡、经验值、满屏徽章和庆祝 confetti。
- 过大的营销 Hero；登录后第一屏必须是可执行的产品体验。
- 以国旗、斗牛或旅游明信片作为廉价西班牙符号。
- 只靠颜色表达成功、失败、可信度或“待验证”。

### 图像与内容资产

- 内容包使用真实、可授权的生活场景摄影或插画：咖啡桌、街角、超市、地铁站、朋友聚会；必须能看出“正在发生什么”，不用模糊氛围图。
- Lucía 与其他角色使用统一裁切和背景处理的肖像，避免把角色做成卡通头像。
- 图片固定宽高比并声明尺寸，Web 使用 Next `Image` 的响应式 `fill`，移动端保留主体安全区。
- 头像、录音、语音气泡等状态使用 Lucide/Phosphor 线性图标，不使用 Emoji 或手绘不一致的 SVG。

## 6. 设计令牌

令牌先在 Web CSS 中落地，后续由 Flutter 建立等价的 Dart Theme；两端不共享组件源码，但共享语义名称和状态含义。

### 色彩

| 语义 | Token | 值 | 用途 |
| --- | --- | --- | --- |
| 页面纸面 | `--color-canvas` | `#F6F3ED` | 全局背景，避免纯白刺眼 |
| 浮层表面 | `--color-surface` | `#FFFCF8` | 工作台、消息区域、表单 |
| 主文字 | `--color-ink` | `#17211D` | 标题、正文、深色按钮 |
| 次级文字 | `--color-ink-muted` | `#5E6863` | 说明、元数据、辅助标签 |
| 线框 | `--color-line` | `#DDE1DA` | 分隔线、输入框、卡片边界 |
| 信任蓝 | `--color-cobalt` | `#2E5DA8` | 主链接、焦点环、可验证数据 |
| 行动砖红 | `--color-terracotta` | `#B94F3B` | 每页唯一主 CTA、录音完成 |
| 证据海绿 | `--color-teal` | `#2F7A72` | 成功、已验证、口语能力证据 |
| 提醒金 | `--color-amber` | `#B97817` | 待验证、权限和可恢复问题 |
| 错误 | `--color-danger` | `#A9362A` | 真正失败或删除确认，不表示能力下降 |

关键文字配对需达到 WCAG AA：`#17211D` on `#F6F3ED` 约 14.9:1，`#B94F3B` with white 约 4.95:1，`#2F7A72` with white 约 5.06:1，`#2E5DA8` with white 约 6.47:1。所有状态还必须配合文字或图标。

### 字体

- UI 主字体：`Plus Jakarta Sans`，中文回退 `Noto Sans SC`，保证数字、拉丁字母和中文在同一字重系统中稳定。
- 西语短句、角色名或引语可使用 `Newsreader`/`Source Serif 4` 作为局部编辑强调；不用于长篇中文正文、按钮或数据表。
- 规格：正文 16px/26px；辅助 14px/22px；标签 12px/18px；页面标题 32px/40px；桌面重点标题 48px/56px。字号按断点离散调整，不使用随视口连续缩放。
- 不使用大面积全大写；只有英文/西语的 eyebrow 可小写转大写并增加字距。

### 形状、间距、阴影

- 间距基于 4/8 单位：4、8、12、16、24、32、48、64。
- 内容卡片统一 8px 圆角；输入和按钮 8px；状态胶囊使用 999px；头像使用圆形。
- 只保留一组柔和阴影：`0 12px 30px rgb(23 33 29 / 8%)`；默认页面内容优先使用边界和留白，而不是浮夸阴影。
- 桌面内容最大宽度 1180px，12 列网格；手机 16px 页面边距，不产生横向滚动。

## 7. 信息架构与页面方案

### 全局壳层

- 桌面：左侧 232px 固定导航，品牌、四个入口和隐私/连接状态；主区独立滚动。
- 手机：保留现有四栏底部导航（学习、探索、对话、我的），高度至少 64px 并避开安全区；桌面与手机使用同一标签和当前态语义。
- 导航只表达产品空间，不增加“统计”“课程”“设置”等第五层入口；设置和隐私从“我的”进入。
- 页面顶部保留短问候和上下文，避免每页重复大标题。每屏只允许一个主 CTA。

### 学习首页 `/learn`

第一屏结构：

1. 顶部问候和轻量连接状态。
2. “继续这一句”主工作台：沟通目标、为什么是现在、组内 `1 / 4` 进度和唯一的“继续学习”。
3. 最近获得的真实能力，展示一条证据和一个可理解的变化（例如反应时间），不展示总分。
4. 安静学习入口和恢复提示作为次级区域，不抢主动作。

视觉上把当前目标做成“编辑式任务卡”，卡内保留一条细进度线和语境小图；不使用放射状光晕或大面积渐变。完成后以短暂勾选和文案确认保存，不弹奖励弹窗。

### 训练页 `/learn/practice` 与未来 session

- 上方显示人物/场景、当前交际目的和状态，不显示课程题号。
- 中央是一句可播放的西语输入，播放按钮与语速设置为次级图标控件。
- 主要动作是 64px 语音按钮，录音中显示低振幅波形和计时；打字入口始终可见但视觉次级。
- 提示从底部抽屉逐级展开：意图 → 关键词/骨架 → 完整示范和变体；打开提示不改变页面布局。
- 用户说完前不显示纠错。提交后先显示“是否完成交际目的”，再按需展开 1–2 条关键反馈。
- 低置信度、无权限、网络失败都使用可恢复状态：保留草稿、给出再说一次/切换打字，不产生负面能力证据。

### 探索页 `/explore`

- 以沟通动作组织内容：开始交流、表达需要、维持对话、修复沟通、安静阅读。
- 顶部可用一个“今天想说什么？”搜索/筛选入口，但不把首页的唯一下一动作复制成候选列表。
- 内容包采用 2 列桌面、1 列手机的编辑卡：真实图片、场景标签、预计活动形式（听/读/说）和口语验证标记。
- 对“内容整理中”提供明确空状态和回到今天的动作，不使用灰掉的伪按钮。

### 对话页 `/chat`

- 桌面为联系人列 + 当前线程两栏；Alpha 只有 Lucía 时仍保持单线程聚焦，不提前造出空社交网络。
- 顶部头像、姓名、城市和在线状态使用克制的状态色；不把“AI”做成持续水印，但首次进入和直接询问时如实说明。
- 消息气泡以时间、语音时长、播放按钮为主；转写文本默认折叠，点击后展开，减少教学感。
- 底部 composer 以录音为主，键盘为次级；发送、取消、重试和断流状态均有明确反馈。
- “今天聊得怎么样”是用户主动打开的次级入口，只展示 1–3 条代表性反馈，不在聊天中实时显示分数或目标句型。
- 好友介绍以消息中的自然提议出现，用户明确同意后才进入联系人列表；不使用角色商城卡片。

### 我的 `/me`

信息顺序：真实获得的能力 → 代表性证据 → 当前最值得验证的问题 → 场景状态 → 八维能力 → 有效学习热力图 → 隐私与数据控制。

- 八维能力默认使用可读列表 + 轻量雷达/八边形图；数据不足的轴显示“数据积累中”，不可绘制虚假精确面积。
- 图表必须有文字摘要、键盘焦点和可读数据表替代；颜色不是唯一编码。
- 热力图只表示有效学习时长，提供数字图例和点击后的日期详情，明确不参与 mastery/confidence。
- 删除录音、转写、关系记忆和账号数据使用独立设置区，并在不可逆动作前二次确认。

## 8. 动效与装饰

动效强度采用标准偏低档：`fast 160ms`、`standard 240ms`、`slow 420ms`，统一 `ease-out`/轻弹簧曲线。只动 `transform` 和 `opacity`，不动画 width/height/top/left，不引起布局跳动。

- 页面进入：主内容 `opacity + translateY(8px)`，240ms；连续列表 40ms stagger，最多 4 项。
- CTA：箭头最多向右 3px，按钮按下缩放 0.98；不可用状态不抖动。
- 录音：只有录音中显示 1.2s 呼吸环和低振幅波形；停止后立即静止，避免把等待误认为评分。
- 消息流：新气泡从 8px 下方进入；流式生成显示三个静态/短循环状态点，收到 `done` 后才标记完成。
- 进度保存：使用 240ms 的勾选/线段填充，禁止 confetti 和全屏庆祝。
- 加载超过约 300ms 使用保留布局的 skeleton；页面离屏或标签页隐藏时暂停循环。
- `prefers-reduced-motion: reduce` 下移除非必要位移和循环，只保留状态变化、焦点和文字反馈。

装饰使用细线、局部色块、内容摄影和语音波形，不使用漂浮渐变球、持续视差或无因果的粒子背景。

## 9. 状态、可访问性与隐私

- 所有按钮和图标控件最小触控区 44×44px，图标按钮有 `aria-label`，键盘焦点环使用高对比度 cobalt。
- 正文至少 16px，正文行长桌面 60–75 字符、手机 35–60 字符；允许中文和长用户内容自然换行。
- 加载、空、断网、权限拒绝、超时、取消和重试均有局部说明与恢复动作；错误紧邻发生位置，不只在页面顶部显示。
- 语音处理状态使用 `aria-live="polite"`，不会在流式聊天中抢焦点；没有 `done` 的流不显示为已完成。
- 录音完成后的原始文件不在前端长期保留；保存里程碑录音、查看/删除关系记忆均需明确用户动作。
- 任何“待验证”状态同时显示文字和图标，不能只用琥珀色或透明度表达。

## 10. 实现边界与分期

### Phase 0：令牌与壳层

更新全局语义颜色、字体、间距、圆角、阴影、焦点和 reduced-motion；重做桌面左 rail 与手机 bottom bar 的同构布局。不得改变路由、认证和领域接口。

### Phase 1：学习与训练

先改 `/learn`、`/learn/practice` 和训练组件，建立 speak-first 工作台、保存反馈、提示抽屉、录音/打字降级和状态样式。

### Phase 2：探索与对话

将内容包卡和 Lucía 线程迁移到同一套表面、图标、头像和语音状态；接入流式状态时继续遵守 generation/done 语义。

### Phase 3：我的与质量验收

实现证据优先的画像、八维可访问图表、热力图、隐私设置；完成手机与桌面视觉回归。

### Phase 4：Flutter 对齐

把本方案的语义令牌、状态名称、触控尺寸和动效原则映射到 Flutter Theme。Web 与 Flutter 不共享 UI 源码，也不把客户端状态当作能力事实。

## 11. 验收标准

### 视觉

- 375、768、1024、1440px 四个宽度无横向滚动、无文字溢出、无布局跳动。
- 四个产品页面使用同一套表面、按钮、标签、图标、头像和动效节奏。
- 首屏主动作一眼可见；没有页面同时出现两个同等权重的 CTA。
- 对比度达到 WCAG AA，状态不依赖颜色，图表存在文字/表格替代。

### 交互

- 首页打开即“继续学习”，不先选时长或训练模式。
- 语音是训练和聊天默认输入，打字入口始终可用且为次级。
- 用户完整表达前没有纠错或打断；低置信度和技术失败不产生负面能力证据。
- 刷新、断网、录音权限拒绝、超时、取消和旧 generation 回调都有可验证的恢复路径。

### 工程与测试

- 保持现有 Next.js App Router、Route Handler、模块边界和 Web/Flutter 分离原则。
- 受影响页面更新 React/Playwright 测试；训练状态、流式完成和权限/错误状态继续由单元测试覆盖。
- 视觉验收通过后再运行 `pnpm lint`、`pnpm typecheck`、`pnpm test --run`、`pnpm test:e2e` 和 `pnpm build`；涉及 Flutter 时追加 `flutter analyze` 与 `flutter test`。
