# 电脑端 Web 界面密度与操作层级收敛设计

- 日期：2026-09-12
- 上位任务：`ALPHA-033`
- 状态：产品方案与书面规格已由产品本人确认
- 当前平台：Next.js 响应式 Web/PWA；本轮优先电脑端 Web

## 1. 背景与问题

当前实现已经具备训练、阅读、探索、对话和个人数据等多条业务路径，但页面把“功能存在”误当成“功能可用”。说明文字、筛选器、卡片和按钮经常同时占据首屏，多个操作拥有相同视觉权重，用户看到很多功能却无法快速判断下一步。

产品所有者明确要求：减少功能与按钮冗余，提高页面利用率，控制按钮和字体尺寸；其反馈代表一类共性问题，不限于被指出的具体控件。设计与实现需要主动发现同类问题，而不是只逐字修补反馈。

2026-09-12 的 1440×900 浅色/深色只读审计得到以下代表性证据：

- Explore 默认页有 49 个可操作元素，同时出现 3 个 76px 高建议按钮、5 个 58px 高来源筛选按钮、11 个 72px 高沟通目标入口、场景卡和内容包卡。
- 深色 Explore 的“14 项匹配”使用浅色背景和近似浅色文字，内容不可辨认。
- 场景详情为每条表达渲染约 447px 宽的“收藏表达”按钮，并存在悬浮开始条覆盖内容的问题。
- 场景实战的输入框和发送按钮高约 70px，“结束并查看复盘”横跨约 834px；用户截图还显示输入区左侧裁切、消息字号偏大和中部空间利用失衡。
- 阅读页默认有 61 个可操作元素，两项新增内容操作、排序、筛选、逐卡入口和九页分页同时出现。
- “我的”空数据页仍渲染八个近整栏宽的能力按钮和完整空热力图；自动审计记录 115 个可操作元素，其中包含大量不产生当前决策价值的空状态控件。

自动化测试通过和页面可以打开只能说明路径具备测试条件，不能作为视觉完成、功能完整或发布候选结论。

## 2. 目标

本设计需要达到：

1. 一屏只服务一个明确决策，默认界面安静，复杂功能在用户需要时再出现。
2. 每个页面具有唯一的最高权重动作，次要动作不与其竞争。
3. 删除无决策价值的说明、重复入口和伪按钮，同时重新组织布局，不能只隐藏后留下空洞。
4. 建立适用于所有电脑端页面的字号、按钮、列表增长、状态和深浅色规则。
5. 保留现有业务路由、服务端权限、训练状态机、内容版本、评分和隐私边界。
6. 将全站改造拆成可以独立测试和验收的页面切片。

## 3. 非目标

本轮不做：

- 新增支付、实时双向语音、开放角色创建或完整内容后台。
- 改写 mastery/confidence、证据、推荐或记忆语义。
- 删除仍有真实用途的服务端接口、数据或深链接路由。
- 恢复 Flutter 功能同步或宣称完成 iPhone Safari 真机验收。
- 以全站一次性重写替代渐进式收敛。

## 4. 全站设计规则

### 4.1 操作预算

- 一个页面或单一决策区域最多有一个填充色主操作。
- 同一区域默认最多直接展示两个次要操作；其余进入详情、上下文菜单或对应状态。
- 数量、状态、标签和不可操作的信息不能使用按钮语义或按钮样式。
- 相同结果只保留一个入口。返回、关闭、暂停、结束、历史和设置需要按上下文去重。
- 列表项以整行/整卡进入详情时，不再重复放置“打开”按钮；收藏等低频动作使用图标并在悬停、聚焦或详情中出现。

### 4.2 字号与密度

电脑端使用以下目标范围：

| 层级 | 字号 |
|---|---:|
| 页面标题 | 28–32px |
| 分区标题 | 18–20px |
| 卡片标题 | 16–18px |
| 正文 | 14–16px |
| 实战消息 | 17–18px |
| 标签和辅助信息 | 12–13px，不能低于 12px |

控件目标范围：

| 类型 | 可见高度 | 文字 |
|---|---:|---:|
| 主操作 | 40–44px | 14px 左右 |
| 普通按钮 | 36–40px | 13–14px |
| 紧凑筛选/标签 | 32–36px | 12–13px |
| 图标按钮 | 图形 18–20px、可见容器 32–36px | 使用可访问名称 |

图标控件的实际点击区域仍需接近 44px；不能通过放大图标或按钮外观来满足命中区。

### 4.3 说明文字

- 删除“选择辅助”“暂时不知道练什么？”等解释页面本身的标题和段落。
- 只在安全风险、错误恢复、真实空状态和首次无法从控件理解的操作处保留说明。
- 安全提示需要保留事实，但使用紧凑的一行提示；高风险场景仍明确说明虚构资源不代表现实安排。
- 技术错误只显示用户可以采取的恢复动作，不把内部配置说明作为普通界面正文。

### 4.4 列表增长

- 首页和聚合页不同时展开所有内容类型。
- 使用内容类型切换、搜索和筛选缩小候选池。
- 默认列表分批显示；表达初始最多 12 条，后续使用单一“显示更多”，不堆叠页码按钮。
- 搜索或筛选变化后回到首批结果。
- 数据量增长到需要服务端分页时，保持相同 UI，底层改用游标；不能因数据源变化重新增加大批分页控件。

### 4.5 状态与主题

- 空、加载、失败和恢复状态均只提供一个明确结论和一个恢复动作。
- 禁用状态必须保持可读，不能只降低整个控件透明度。
- 浅色和深色分别验证文字、背景、边框、选中、悬停、聚焦和禁用状态。
- 普通正文达到 4.5:1 对比度，重要控件边界和图标达到 3:1。

## 5. 公共壳层与侧边栏

- 展开侧栏宽度约 200–208px，显示 Logo、图标和导航名称。
- 收缩侧栏宽度约 68–72px，只显示导航图标；悬停或键盘聚焦时显示名称提示。
- 删除“开始 / 发现 / 账户”等不产生导航价值的分组说明。
- 收缩按钮位于顶部 Logo 旁，使用统一的侧栏收起/展开图标；可见容器 32–36px，点击区域接近 44px。
- 展开和收缩时按钮保持在稳定位置，主内容区同步重排，不能只隐藏文字。
- 收缩状态在本设备保存，不写入学习证据、画像或账户数据。
- 1280px 及以上首次默认展开，1024–1279px 首次默认收缩；用户手动选择优先于默认值。
- 小于桌面断点时继续使用移动底部导航，不同时保留侧栏。
- 收缩态顶部使用与现有字标字体一致的 `S` 紧凑标记，不新增另一套 Logo；当前页面继续通过图标、颜色和侧边标记表达，并提供 `aria-label`、工具提示和键盘操作。

## 6. Explore 页面

### 6.1 页面结构

- 移除可见的“探索真实表达”和“练习历史”页头；保留仅供辅助技术使用的页面标题。
- 练习历史路由继续保留，入口统一转移到学习首页的练习记录区域，不占用 Explore 首屏。
- 第一行只放全宽搜索框。
- 第二行放“适合我的 / 探索新场景 / 随机来一个”三个紧凑、等宽选项；桌面保持一行三项，窄屏允许换行。
- 不显示选择辅助标题、问题句和三项说明段落；名称和图标本身承担识别作用。
- 工具区下方只保留“场景 / 表达 / 内容包”三个内容视图，默认显示场景。

### 6.2 建议与筛选

- 点击建议模式后，以单个建议结果替换普通结果区的优先位置。
- 建议结果只保留“开始练习”和低权重“换一个”；选择理由使用紧凑文本，不重新形成说明卡墙。
- 当前五个大型来源筛选移入“筛选”弹层，只在相关内容视图出现。
- 已选筛选条件显示为可移除的小标签。
- “14 项匹配”改成与阅读页数量胶囊同源的非交互统计样式，并为深浅色提供独立的高对比配色。

### 6.3 内容呈现

- 场景改成紧凑横向卡片，仅展示名称、难度、角色和一个沟通目标；完整目标、条件变化和安全细节进入详情。
- 表达改成单行或双行列表，展示西语、中文和必要标签；收藏使用右侧书签图标。
- 沟通目标不再作为 11 个大型入口单独铺开，而作为场景/表达的筛选维度和标签。
- 内容包只在“内容包”视图显示。

Explore 打开后只要求用户作出一个决定：搜索、让系统选择，或者浏览一种内容。

## 7. 场景详情、实战与复盘

### 7.1 场景详情

- 页头由返回、28–32px 标题、难度和紧凑临时人物信息组成。
- 沟通目标使用紧凑编号列表，完整说明按需展开。
- 表达使用单/双行列表，收藏改为右侧书签图标，删除逐项整行收藏按钮。
- 桌面端使用约 280px 的紧凑右侧栏展示临时人物、预计轮次和唯一的“开始实战”主操作；1024px 时侧栏并入页头下方。
- 删除当前覆盖表达内容的悬浮开始条，不重复开始入口。
- 虚构场景说明保留为紧凑一行，高风险场景继续明确现实边界。

### 7.2 实战工作台

- 页头压缩为返回、场景名、角色和进度；删除独立暂停按钮，返回时先保存稳定断点并将会话置为暂停，再离开页面。
- 当前目标使用单行状态栏：`目标 1/3 · 礼貌点一份主菜`；提示位于右侧，使用低权重操作。
- 对话区占主要空间并独立滚动，消息限制为可读行宽，字号 17–18px。
- 输入区固定在工作区底部，但不覆盖对话、不伸入侧栏，修复左侧内容裁切。
- 默认直接显示文字输入，麦克风作为输入框内的模式按钮。
- 常用表达使用轻量工具入口，打开后才显示表达。
- 切换到语音后才显示按住说话控件，不再常驻“表达 / 按住说话 / 键盘”三个同权按钮。
- 未达到结束条件时只显示进度；达到后才显示紧凑“完成练习”主操作，不再渲染整栏禁用按钮。
- 发送按钮为紧凑动作，并为深浅色分别定义启用和禁用配色。

### 7.3 复盘

- 复盘以完整对话和关键反馈为主。
- 筛选、复现时间、表达收藏和详细教学说明按需展开，不在首屏同时出现。
- 保留“用户完整表达后再反馈”和“技术失败不产生负面证据”的产品不变量。

## 8. 学习首页与训练工作台

- 学习首页继续根据真实断点提供唯一主动作。
- 当前约一整屏高的主任务卡压缩到首屏上半区。
- 当前目标和三步流程使用紧凑进度呈现；详细步骤按需展开。
- 次级的阅读、关系和探索入口降低视觉权重，不与开始/继续练习竞争。
- 没有证据时只显示紧凑空状态，不重复展示“完成后会出现”等说明卡和信息条。
- 训练工作台复用场景实战的输入模式、提示、按钮和字号规则，但继续使用既有训练状态机与 generation 保护。

## 9. 阅读书架与文章阅读器

### 9.1 阅读书架

- 第一行左侧为“公共文章 / 我的文章”标签，右侧保留非交互的“105 篇”数量胶囊。
- 未完成的 Web Sites 能力和路由不删除，但在闭环完成前不占据主标签。
- 第二行由搜索框和紧凑的排序、筛选、“添加内容”组成。
- “Generate Story”和“Upload Text or Audio”合并到“添加内容”菜单；菜单项只有在对应路径真实可用时出现。
- 删除元素后重新计算对齐、宽度和留白，不保留空栏。
- 文章卡整体进入文章，不重复“打开文章”链接；收藏保留为图标动作。
- 每页固定呈现 12 篇，底部使用紧凑分页：保留上一页、下一页、首尾页和当前页邻近页，页数较多时以省略号收敛，不平铺全部页码；搜索、筛选、排序或来源变化时回到第 1 页。
- 中文产品控件使用一致语言，西语保留用于文章内容和教学需要。

### 9.2 文章阅读器

- 正文是唯一主表面。
- 顶栏保留唯一文章标题，正文区不重复渲染大标题；正文紧接顶栏后的舒适留白开始。
- 朗读、词语辅助、保存和口语迁移进入紧凑工具栏，只有当前启用的工具展开。
- 桌面浮动解释器可通过标题栏拖动并限制在视口内；固定入口从 `1200px` 起可用，固定到右侧时阅读区移除外层横向留白，尽量保持固定前的正文行宽和断行。`1200–1279px` 使用最小 `300px` 解释栏，低于 `1200px` 继续使用覆盖面板且不显示固定入口。
- 当前被解释的单词或句子使用不持久化的临时高亮；切换选区或关闭解释器时立即更新或清除，与用户主动保存的永久高亮分离。
- 首次访问且没有已保存主题偏好时默认浅色；深色阅读器使用低眩光暖炭灰背景和柔和米灰文字，避免纯黑纯白的强反差。
- 版权、来源和阅读状态继续真实显示，但不与正文争夺主视觉。
- 阅读和打字仍不直接构成口语证据。

## 10. 对话页

- 页面只保留联系人列表、当前对话和输入区三层结构。
- 联系人搜索只在联系人数量足以产生搜索需求时显示。
- 好友申请和角色介绍合并为一个低权重入口，只有待处理事项时显示数量。
- 当前角色页头只展示头像、姓名和关系状态；资料、清理和排序等低频操作进入上下文。
- 空会话只显示一句自然开场，不建立宣传式说明卡。
- 数据或会话不可用时合并为一个紧凑错误状态和一个重试动作；输入区同步禁用，不能伪装成可发送。
- 翻译、引用、撤回等操作只在选中具体消息后出现。
- 对话正文使用 15–17px，时间和辅助状态使用 12–13px。

## 11. “我的”、设置与隐私

- “能力与活动 / 关系隐私 / 数据与隐私 / 偏好设置”使用紧凑标签导航。
- 账户资料编辑继续位于头像菜单或资料页，不在首页重复入口。
- 多个数据请求失败时合并为一个页面级错误状态和一个重试动作。
- 无证据时顶部只显示 `0/8 已验证维度`和唯一的第一次练习入口。
- 没有证据时不渲染八条同质“数据不足”按钮；有证据时使用紧凑能力行。
- 能力行只有存在可展开内容时才使用按钮语义。
- 无活动时不渲染完整空热力图；产生数据后再展示 12 周视图。
- 证据详情、代表性尝试和算法解释默认折叠。
- 数据删除、导出、关系记忆和语音数据保留独立分区及明确确认，不弱化隐私安全。

## 12. 其他页面与一致性

- 登录、帮助、偏好和隐私页应用相同字号与按钮分级。
- 登录确认、权限和不可逆删除仍提供足够明确的说明与确认步骤。
- 所有可见操作必须具有真实动作、明确禁用状态或诚实的不可用说明。
- 不使用纯视觉快照代替按钮结果、焦点、状态机和权限断言。

## 13. 响应式与可访问性

- 本轮主要验收 1280px 和 1440px 电脑端，额外保证 1024px 不出现横向溢出。
- 既有移动样式不能因电脑端改动明显退化，但 iPhone Safari 真机继续作为延期项。
- 键盘顺序与视觉顺序一致；隐藏工具和弹层打开后正确移动焦点，关闭后恢复触发点。
- 图标按钮提供可访问名称；选中、展开、禁用和当前导航状态使用原生语义。
- `prefers-reduced-motion` 下移除非必要位移和缩放。
- 数量胶囊、标签和状态不进入 Tab 顺序。

## 14. 实施切片

按照一次一个任务 ID 推进：

1. `UI-012`：Explore、场景详情、场景实战与复盘。
2. `UI-013`：学习首页与训练工作台。
3. `UI-014`：阅读书架与文章阅读器。
4. `UI-015`：对话页面。
5. `UI-016`：“我的”、设置与隐私。
6. `UI-017`：公共壳层、可收缩侧边栏与全站一致性复核。

每个切片完成后更新状态页、提交并推送，再领取下一项。若某个页面需要改变服务端接口或业务语义，停止扩大当前切片，单独补充设计或 ADR。

## 15. 测试与验收

每个切片至少覆盖：

- 相关组件和领域行为测试。
- Playwright 的真实点击结果、焦点、筛选、展开/收起、错误恢复和刷新恢复。
- 1280×900、1440×900 的浅色与深色视觉人工复核。
- 无横向溢出、无固定区域遮挡、无输入文字裁切。
- 主操作唯一，状态与统计不可点击，重复入口清零。
- 深浅色文字和控件对比度检查。
- `pnpm lint`、`pnpm typecheck` 和相关 Vitest/Playwright。

完成 `UI-017` 后再执行全量：
