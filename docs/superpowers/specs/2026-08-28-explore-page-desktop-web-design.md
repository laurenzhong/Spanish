# 探索页桌面 Web 视觉与交互方案

- 日期：2026-08-28
- 状态：视觉评审稿（非生产实现）
- 方向：Warm Editorial Discovery Workspace
- 优先级：桌面 Web；移动端作为同语义单列适配

## 1. 设计决策

采用“路径型目录”为骨架，吸收编辑杂志的排版和少量对话画布的意图输入：

- 顶部给用户一个低压力的“我现在想说……”入口。
- 中部保留五个沟通目标索引，帮助用户按真实动作浏览。
- 下方用内容网格承载已发布、继续中、保存和整理中状态。
- 选中内容后在右侧显示详情 rail，不让用户在浏览与决定之间来回跳页。

这套方案能保持现有五项导航和产品不变量，同时为后续真实内容增长留出结构。

## 4. 组件状态

### 4.1 意图输入

- 默认是低对比度纸面输入，不抢夺唯一主 CTA。
- 聚焦时显示 2px 蓝色焦点环和辅助文字“只会匹配已发布目标”。
- 成功匹配后显示目标 chip，可移除；无匹配时保留输入并给出最近目标。
- 不直接发起 LLM 对话，不写入学习证据。

### 4.2 目标索引

- 五个目标按横向 5 卡（≤1199px 时 3+2 网格）展示。
- 每卡最多显示一行说明、真实内容数量和最近练习时间；没有数据时显示“数据积累中”。
- hover 只改变边框和箭头位置 2px；不旋转图标、不弹跳。

### 4.3 内容卡

- 卡片上方是主题色块或真实缩略图；无图片时使用几何纸面纹理，不伪造照片。
- 元数据顺序：等级 → 技能 → 时长 → 状态。
- `published` 显示“打开内容包”；`in_progress` 显示“继续”；`draft/unavailable` 只显示状态说明。
- 保存是独立的 icon button，必须有 aria-label 和 tooltip，不与整卡点击冲突。

### 4.4 详情 rail

- 只有选中卡片后出现，进入/退出采用 8px 横向位移和透明度。
- 顶部显示状态和版本；中部显示“你会练到什么”；底部只保留一个主动作。
- rail 内的来源、审核和数据不足说明使用小号文本，不隐藏关键限制。

## 5. 动效剧本

1. 页面加载：H1 与目标卡淡入上移 8px，250–350ms。
2. 目标切换：内容网格交叉淡出/淡入 160–200ms，保留滚动位置。
3. 卡片 hover：`translateY(-2px)`、边框转为赤陶，160ms。
4. rail 打开：`opacity 0→1` + `translateX(8px→0)`，200ms。
5. reduced motion：跳过位移和交叉淡入，立即呈现最终状态；不影响内容顺序和焦点。

## 6. 移动端适配原则（非本轮主实现）

- 320–767px 单列；意图输入和目标索引全宽。
- 内容卡横向滚动只用于“继续”小队列，全部内容仍为纵向列表，避免双向滚动。
- rail 改为底部 sheet 或卡片内展开，不能遮挡底部五项导航和键盘焦点。
- 命中区至少 44px；固定底栏预留安全区和内容底部 padding。
