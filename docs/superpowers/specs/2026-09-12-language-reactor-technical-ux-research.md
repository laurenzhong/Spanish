# Language Reactor 全站技术与 UX 调研

> 调研日期：2026-09-12
> 调研对象：[Language Reactor](https://www.languagereactor.com/) 公开 Web/PWA 站点
> 调研目的：为 Sueño 后续的内容学习、阅读器、逐词辅助、复习与媒体学习设计提供可验证的参考，不构成复制第三方源码、资源或受保护内容的授权。
> 当前登录状态：未登录。登录后个人数据闭环另列为待补测项。

## 1. 结论摘要

Language Reactor 不是一套按章节推进的传统课程，而是一个“把任意原生内容转化为语言学习材料”的工具工作台。它最成熟的设计不是某一个页面，而是一组跨媒体保持一致的操作语法：逐句播放、双语对照、点击查词、词形归一、词汇标记、跨内容高亮、上下文保存和句子级复习。

它最值得 Sueño 借鉴的部分是：

1. 视频、图书、播客和网页复用同一套“内容—句子—单词”层级模型。
2. 在不中断内容消费的前提下，用右侧栏完成查词、看词形、看频率、听发音和看语料例句。
3. 使用 `A / S / D` 完成上一句、重播、下一句，用 `Q` 控制字幕后的自动暂停；高频操作不需要离开键盘。
4. 保存词语时同时保存原句、来源、时间位置、音频或截图引用，为之后复习和导出保留语境。
5. PhrasePump 把复杂的词汇判断压缩为 `KNOWN / LEARN / DON'T LEARN` 三态，并在旧词复习与新词引入之间切换。

它不适合直接照搬的部分是：

1. 功能入口并列过多，缺少一个贯穿“现在该做什么”的主动作。
2. 桌面学习器同时呈现播放器、字幕、翻译、词典、词频和词汇状态，效率很高，但初学者认知负担大。
3. 词频和标词状态是全站主要组织轴，但“看过、查过、标记过”不能自动等价为真正会说。
4. 移动端视频页在 390px 宽度下主要保留播放器和底部图标，桌面的字幕与词典工作区没有自然降级。
5. 图标型导航和部分小型按钮的可发现性、可访问名称与触控尺寸存在风险。

Sueño 应吸收它的工具效率，但必须继续坚持自身产品不变量：沟通成功优先、完整表达后再反馈、打字不增加口语证据、技术失败不形成负面证据、`mastery` 与 `confidence` 分离，以及唯一且真实的首页主动作。

核心闭环可概括为：

```text
选择原生内容
    ↓
按句播放或阅读
    ↓
点击词语即时理解 ──→ 标记词语状态
    ↓                         ↓
继续当前内容           跨内容持续高亮
                              ↓
                    PhrasePump / 导出复习
```

这套架构的关键不是“页面很多”，而是同一个词语对象能跨页面继续存在。目录负责选择材料，工作台负责理解，标记负责记忆状态，PhrasePump 和导出负责后续复现。

## 4. 全局壳层、视觉语言与导航

### 4.1 桌面布局

**已实测。** 应用页统一使用深色工作台：左侧约一列图标宽度的固定导航栏，顶部为当前内容或工具的上下文操作区，中间是主内容，右侧按需出现文本、词语或词典面板。紫色是主强调色，绿色主要表示已知、播放或积极状态，灰色表示次要、未激活或不可用。

视觉策略偏“专业工具”而不是“课程卡片”：边框和背景层级代替大面积阴影，信息密度高，圆角较轻，正文和控件尺寸偏紧凑。公开 HTML 加载 `Varela Round` 与 `Noto Sans`；页面实际观感中，品牌和部分短标签更圆润，长文本保持中性易读。

### 4.2 左侧导航按钮

| 控件 | 作用 | 设计逻辑 | 状态 |
|---|---|---|---|
| 顶部 `>` / 折叠箭头 | 展开或收起侧栏 | 释放学习工作台横向空间；图标栏在深页面仍持续可达 | 已实测 |
| `西` 语言徽标 | 显示/切换当前学习语言 | 把全站内容、词典和词汇状态绑定到同一目标语言 | 已实测 |
| 播放三角形 | 进入媒体发现/学习入口 | 用内容消费符号表示视频与媒体 | 已实测 |
| 对话气泡 | 进入 Aria Chatbot | 把自由对话与内容学习并列为独立工具 | 已实测 |
| 棕榈/树形图标 | 进入 PhrasePump | 图形有品牌记忆，但仅靠图标不容易首次理解 | 已实测 |
| 列表/方格 | 进入已保存项目或词语列表 | 统一承接跨内容保存对象 | 已实测；数据登录受限 |
| `?` | 打开帮助与说明 | 在复杂工具中持续提供逃生口 | 已实测 |
| 齿轮 | 打开通用设置 | 全局语言、词典、显示和账户设置 | 已实测 |
| 人形/辅助图标 | 进入额外工具或辅助入口 | 无文字时语义较弱，应依赖 tooltip | 已实测外观；具体账号后行为未验证 |
| 门/箭头图标 | 登录或退出入口 | 放在导航底部，与学习工具分开 | 未登录状态已实测 |

设计优点是主工作区从不失去全局工具入口；缺点是大量图标没有常驻标签，新用户必须悬停或试点才能建立含义。

### 4.3 学习器顶部通用按钮

| 控件 | 作用 | 设计逻辑 |
|---|---|---|
| 返回箭头 | 返回目录或上一个上下文 | 保留从“挑内容”进入“沉浸学习”的层级关系 |
| 上一句/下一句 | 移动到相邻字幕句 | 将视频时间轴转换成离散、可练习的句子序列 |
| 标题与信息 `i` | 显示当前内容身份或附加信息 | 让来源在深层工作区仍可确认 |
| 键盘图标 | 查看快捷键说明 | 高密度学习动作适合从鼠标迁移到键盘 |
| 分享图标 | 分享当前材料或位置 | 把内容深链作为协作/稍后使用入口；真实分享结果未提交验证 |
| 布局图标与下拉箭头 | 改变播放器、字幕或侧栏布局 | 允许不同屏幕和学习偏好调整信息密度 |
| `AP` | 切换字幕后自动暂停 | 把自然视频切成“听一句—理解—再继续”的训练节奏 |
| `1x` | 调整播放或朗读速度 | 在不换内容的情况下控制输入难度 |
| 翻译/语言图标 | 切换字幕、翻译或界面语言相关显示 | 把语言显示设置放在内容附近，而不是藏进全局设置 |
| 全屏图标 | 进入/退出全屏 | 为视频沉浸和小屏补充空间 |
| `文本` | 显示逐句原文与翻译 | 默认学习主视图 |
| `词语` | 显示学习词、词频或出现次数 | 从线性内容切换到词汇层分析 |
| 搜索 | 搜索当前文本或词语 | 在长字幕/长书中快速定位 |

这些按钮的设计逻辑是把设置分成两层：只影响当前内容的高频动作放在顶部；跨内容的语言、词典和账户偏好放到通用设置。

## 5. 页面逐项调研

### 5.1 营销首页

**状态：已实测。**

#### 布局

首页是一条很长的纵向功能故事线。首屏左侧使用霓虹风插画，右侧是 Language Reactor 标志、简短价值主张、Chrome 扩展主按钮和用户量社会证明。后续先讲“从喜爱的内容中学习”，再讲“语言学习神器”“掌握每个单词和短语”“熟能生巧”，最后展示媒体评价。

主要功能模块依次包括：Netflix、YouTube 与播客、书籍与网站、双语字幕、精确播放控制、词典与 Lexa AI、多语言支持、学习重点、智能高亮、PhrasePump、导出到 Anki、Aria、FSI/DLI、手机和平板、Pro 模式和媒体背书。

#### 按钮与作用

| 控件 | 作用 | 设计逻辑 |
|---|---|---|
| `安装 Chrome 扩展` | 进入 Chrome Web Store 安装扩展 | 首页唯一最强 CTA，直接承接 Netflix/YouTube 的核心价值 |
| 顶部应用/语言/账户类图标 | 进入 Web 工具、切换界面语言或账户状态 | 让熟悉产品的用户跳过营销内容 |
| 各功能卡片的小箭头/链接 | 进入相应功能或说明 | 先通过截图说明价值，再给进一步入口 |

#### 设计评价

优点是通过真实工作台截图解释复杂功能，用户能看到“装完以后会发生什么”；缺点是页面极长，几乎所有能力都以相同视觉权重出现。对想马上开始学习的人，除安装扩展外缺少基于当前状态的唯一下一动作。

### 5.2 媒体总目录 / YouTube 目录

**状态：已实测。**

#### 布局

顶部横向来源导航包含 `YouTube`、`Netflix`、`图书`、`课程`、`媒体文件`、`播客`、`我的文本`、`学习资源`。左侧筛选列用于词汇水平、时长、排序和频道；右侧是搜索结果或空状态。首次进入会显示居中的语言选择对话框。

#### 按钮与作用

| 控件 | 作用 | 设计逻辑 |
|---|---|---|
| `学习语言` 下拉框 | 选择内容目标语言 | 决定目录、字幕与词典的主语言 |
| `您的母语` 下拉框 | 选择翻译语言 | 决定双语字幕和词典解释语言 |
| `OK` | 确认语言组合 | 先建立语言上下文，再加载目录，减少错误内容 |
| 顶部来源标签 | 切换 YouTube、Netflix、图书等内容类型 | 同一个学习器接入多种来源，来源只负责摄取 |
| `安装` | 安装扩展 | 在 Netflix/YouTube 能力受限时就地提供解决路径 |
| `词汇水平` 双端滑块 | 设置可接受的词汇量区间 | 用内容难度筛选替代固定 CEFR 课程顺序 |
| `Duration` 双端滑块 | 设置 30 秒到约 4 小时的时长范围 | 同时支持碎片学习与完整内容 |
| `日期` | 按发布时间排序 | 偏向发现新内容 |
| `播放量` | 按流行度排序 | 用社会信号提高选材成功率 |
| 放大镜 | 搜索目录 | 允许目标明确的用户直接找内容 |
| `Reactor Mix` | 选择混合推荐频道 | 降低不知道看什么时的选择成本 |
| `所有频道` | 清除频道限制 | 恢复更广的发现范围 |
| 内容卡片 | 打开具体视频/材料 | 把目录筛选结果直接交给统一学习器 |

#### 设计评价

目录筛选围绕“我能不能理解”和“我有多少时间”，比按主题堆分类更符合沉浸学习。词汇量区间虽高效，但会诱导用户把词汇覆盖当成总体水平；Sueño 若采用，应作为选材信号而不是能力结论。

### 5.3 Netflix 页

**状态：公开入口已实测；真实 Netflix 播放增强未安装扩展，因此受限。**

页面与 YouTube 同处内容来源层，主要 CTA 是安装浏览器扩展。其设计逻辑是 Web 站负责目录、账号和设置，扩展在第三方播放器上叠加双语字幕、逐词词典、自动暂停与保存能力。未验证 DRM 播放、字幕抓取、账号区域差异或 Netflix 页面内按钮。

### 5.4 视频学习器

**状态：已实测公开 YouTube 内容。**

#### 布局

桌面端是典型三栏工作台：

1. 左栏：视频播放器、时间轴、音量、全屏和当前句范围指示。
2. 中栏：原文与翻译逐句列表，当前句有强调条；每句可定位播放。
3. 右栏：默认词典，也可切换到 Lexa AI 对话。

顶部保留内容标题、上一句/下一句、快捷键、分享、布局、自动暂停、速度、语言显示和全屏。中栏上方有 `文本 / 词语 / 搜索`。

#### 播放器按钮

| 控件 | 作用 | 设计逻辑 |
|---|---|---|
| 播放/暂停 | 控制视频 | 保留用户熟悉的媒体模型 |
| 时间轴 | 跳转时间 | 与字幕句定位并存：一个连续，一个离散 |
| 音量 | 静音或调节音量 | 标准媒体控制 |
| 视频全屏 | 只放大视频或进入媒体全屏 | 适合纯观看，但可能暂时离开字幕工具 |
| 字幕句 | 跳到该句对应时间并设为当前句 | 文本即导航，减少拖动时间轴的精度要求 |
| 当前句左侧紫色标记 | 表示播放/学习焦点 | 让长列表中的位置一眼可见 |
| 句内单词左键 | 打开该词的词典详情 | 把理解成本压缩到一次点击 |
| 句内单词右键 | 标记或改变词语学习状态 | 阅读与词汇管理共用同一个文本表面 |
| 星标/更多菜单 | 保存句子或展开上下文动作 | 低频动作不占据主阅读路径；未登录保存结果未验证 |

#### 键盘逻辑

| 快捷键 | 作用 | 为什么有效 |
|---|---|---|
| `A` | 上一句 | 左手连续操作，适合回看 |
| `S` | 重播当前句 | 最高频听辨动作放在中间键 |
| `D` | 下一句 | 与 A/S 构成位置记忆 |
| `Q` | 切换自动暂停 | 不移动鼠标即可改变练习节奏 |
| 按住字幕相关键 | 临时显示或隐藏字幕，松开恢复 | 允许“先听后看”而不永久改变设置 |

#### 设计评价

最优秀的地方是时间轴、句子和单词三种粒度在一个屏幕互相联动。最主要的问题是桌面信息密度非常高，而且播放器控制、学习器控制和全站控制同时存在；初学者很难立刻知道哪些按钮最重要。

### 5.5 逐词词典侧栏

**状态：已实测。**

#### 布局与内容

右侧栏顶部是 `词典` 与 `Lexa AI 对话 BETA` 两个标签。词典页包含搜索框、清空、历史、词头、发音、简明释义、词频条、学习状态、标签、Lexa 笔记入口、词元/词性/变体、多来源解释、当前文本例句与 Tatoeba 例句。

#### 按钮与作用

| 控件 | 作用 | 设计逻辑 |
|---|---|---|
| 搜索框 | 手动查询或显示当前点击的词 | 支持从内容驱动和主动查词两种入口 |
| `×` | 清空当前词 | 快速回到空词典或准备新搜索 |
| 历史时钟 | 查看最近查询 | 减少重复输入 |
| 扬声器 | 朗读词头 | 即时连接词形与声音 |
| 词频条与排名 | 展示相对常见程度 | 辅助判断是否值得投入；不应直接作为掌握度 |
| 信息 `i` | 解释频率或指标含义 | 为压缩指标提供渐进说明 |
| `✓` | 标为已知 | 表示不需要重点复习 |
| 书本/学习图标 | 标为要学 | 把词加入学习队列 |
| 禁止符号 | 标为不学 | 排除专名、噪声或当前不想投入的词 |
| `tags >>` | 查看或编辑标签 | 在三态之外提供自定义组织 |
| `Lexa 笔记 / 登录` | 生成或保存 AI 辅助笔记 | 高成本/个性化能力与登录状态绑定 |
| `Re / Gl / Wi / GPT` | 切换不同词典或 AI 解释来源 | 同一词允许对照简释、外部词典与生成式解释 |
| `Tatoeba` | 展示外部语料例句 | 用真实或共享语料补充当前上下文 |

#### 数据设计启示

一个可复用的词语对象至少需要区分：表面词形、规范化词元、词性、目标语言、释义来源、词频、用户状态、标签、当前句、来源内容、出现位置和音频位置。Language Reactor 的跨内容高亮之所以成立，是因为它不只保存页面上的字符串，而是尝试把不同词形归到同一词元。

### 5.6 `词语` 分析页

**状态：页签和公开结构已实测；用户真实词表登录受限。**

中栏从逐句文本切换为词语分析，顶部提供 `学习`、`词频排名`、`视频中出现次数` 三种观察方式，并有 `设置词汇水平` 按钮。

| 控件 | 作用 | 设计逻辑 |
|---|---|---|
| `学习` | 按用户学习状态组织当前内容中的词 | 连接个人词库与当前材料 |
| `词频排名` | 按通用频率排序 | 优先暴露高价值词 |
| `视频中出现次数` | 按本材料局部频次排序 | 找出当前内容的关键词 |
| `设置词汇水平` | 估算或调整已知词边界 | 用批量阈值降低逐个标记成本 |

这个页面把同一批词分别从“个人状态、全局频率、局部频率”观察，信息设计非常清楚。未登录时中心列表可能为空，不能据此判断真实账户的筛选和批量修改行为。

### 5.7 图书目录与图书阅读器

| `文本 / 词语 / 搜索` | 在阅读、词汇分析和检索之间切换 | 复用学习器顶层模型 |

图书页证明其核心抽象不是“视频字幕”，而是“有顺序、可定位、可播放的双语句子”。这非常适合 Sueño 的文章阅读器。但逐行双栏翻译会打断长文阅读节奏，应允许按需隐藏译文、只在当前句显示或采用侧栏解释。

| 控件 | 作用 | 设计逻辑 | 证据 |
|---|---|---|---|
| 左箭头 / `A` | 上一句 | 与视频学习器保持相同肌肉记忆 | 公开说明/截图 |

#### 状态逻辑

```text
建议词出现
├─ KNOWN → 作为已知词，降低学习优先级

└─ DON'T LEARN → 从建议中排除

句子轮次
旧词复习 ↔ 新词引入
     ↓
听句子 / 看句子 / 理解语法与词汇
```

它的优点是决策极简，缺点是三态很容易被误用为能力评分。Sueño 若借鉴，应把三态限定为“复习意图”，真正掌握度仍只能来自语境任务中的口头证据，低置信度转写和技术失败不得产生负面证据。

## 6. 关键交互状态机

### 6.1 视频/音频逐句学习

```text
加载内容
├─ 成功 → 建立句子时间轴 → 当前句就绪
└─ 失败 → 应显示来源失效/字幕缺失/网络错误（播客页发现失效样本）

当前句就绪
├─ 播放 → 时间推进 → 当前句随时间更新
├─ 自动暂停开启 → 句尾暂停
├─ A / 上一句 → 定位前一句
├─ S / 重播 → 回到本句起点
├─ D / 下一句 → 定位后一句
└─ 点击词 → 词典侧栏更新，但不离开当前内容
```

设计要点：句子是控制媒体、显示翻译和保存上下文的共同主键；异步翻译或词典加载不应阻塞播放器基本控制。

### 6.2 图书逐句阅读

```text
打开书 → 恢复页码或从第 1 页开始
    ↓
当前页分句 + 双语对齐
    ├─ 点击行播放 → TTS 当前句
    ├─ 连续播放 → 顺序 TTS
    ├─ 点击词 → 词典
    ├─ 翻页 → 新页分句
    └─ 搜索 → 定位匹配处
```

设计要点：媒体时间戳在书中变为页码和句序号；两者应抽象为统一的 `sourcePosition`，而不是把视频和文章做成互不兼容的数据模型。

### 6.3 词语状态

```text
内容中的表面词形
    ↓ 词形分析
规范化词元 + 词性 + 语言
    ↓ 用户选择
KNOWN / LEARN / DON'T LEARN
    ↓
当前内容高亮 + 其他内容高亮 + PhrasePump 候选 + 导出
```

需要特别区分：

- `status` 是用户的学习意图或自我标记。
- `encounterCount` 是遇见次数。
- `contentFrequency` 是当前材料出现次数。
- `corpusFrequency` 是通用词频。
- `mastery` 是通过真实任务证据计算的能力状态。
- `confidence` 是对 `mastery` 估计的可信程度。

前四项都不能直接覆盖后两项。

### 6.4 对话

```text
选择对话起点或自由输入
    ↓
文本/语音输入 → 生成中 → 完整回复
                  ├─ ESC / 停止
                  └─ 失败 / 重试
    ↓
可选反馈、记忆或下一轮
```

Language Reactor 的公开界面展示了输入、停止提示、场景模板和 Pro 记忆，但未登录实测没有覆盖完整消息、取消、异常断流、记忆写入和纠错时机。Sueño 必须继续使用 `generationId`，旧回调不能写入当前轮，只有显式 `done` 的完整轮次才允许进入长期记忆候选。

## 7. 响应式与移动端审查

### 7.1 已实测的 390 × 844 视频页

移动页保留：左上返回、右上速度、中心播放器加载区和底部图标导航。桌面的中间双语字幕列、右侧词典、顶部多数工具和清晰的文本/词语切换没有在首屏自然呈现。

这说明它虽然有 PWA Manifest、iPhone/iPad 启动画面和移动外壳，但核心视频学习体验仍明显以桌面/扩展程序为中心。Manifest 声明 `display: standalone`、`orientation: portrait`，启动页是 `/phrasepump`；产品策略上更像“移动端优先进入句子复习”，而不是把完整三栏视频工作台压进手机。

### 7.2 风险

1. 底部存在 6 个左右图标入口，超过移动主导航通常建议的 5 个，并且没有常驻文字标签。
2. 字幕、查词和播放控制如果藏在多层抽屉，会增加听一句、查一个词的交互成本。
3. 部分桌面按钮视觉尺寸明显小于 44px；作为 iPhone PWA 触控目标不够稳妥。
4. 固定底栏需持续预留安全区和内容底部空间，避免遮挡字幕或输入框。
5. 竖屏锁定有利于 PhrasePump，但可能限制平板视频/阅读器的横屏生产力。

### 7.3 对 Sueño 的启示

移动端不应机械缩小三栏布局。更合适的层级是：主内容全宽，当前句固定在播放器下方，查词使用可拉起且可保留选择状态的底部抽屉；次要分析页进入独立页面。底部一级导航最多五项且图标带标签，所有触控目标至少 44px，iPhone Safari 使用安全区和动态视口。

## 8. 可访问性与可用性审查

### 8.1 做得好的地方

- 深色画布和高亮当前句形成强焦点。
- 重要学习动作有键盘替代，连续听辨效率很高。
- 播放、速度、全屏等遵循常见媒体符号。
- 设置页用分组标题和就地信息按钮降低说明密度。
- 登录受限页面有明确原因和登录动作，不显示无法解释的空白。

### 8.2 发现的问题

- Playwright 粗略检查中，首页、目录和视频页没有可靠的语义标题层级；视觉标题不等于屏幕阅读器可导航标题。
- 部分图标按钮没有稳定的可访问名称，尤其左侧栏与顶部工具区。
- 图标型一级导航缺少常驻标签，首次使用依赖 tooltip、图形猜测或试错。
- 多个桌面交互目标不足 44px；虽然 WCAG Web 最低目标存在例外，但 PWA/触屏应按更稳妥的 44px 设计。
- 字幕、翻译和词汇状态大量依靠颜色、背景或细线区分，需要同时暴露文本/状态语义。
- 高密度三栏可能造成键盘焦点被固定顶部、滚动字幕或词典区域遮挡；应验证焦点可见和滚动区域顺序。
- 当前只验证普通视觉环境，未完成屏幕阅读器、200% 缩放、强制颜色、`prefers-reduced-motion` 和纯键盘全流程测试。

### 8.3 复刻时的最低门槛

1. 每页一个明确 `h1`，子区按顺序使用标题层级。
2. 每个仅图标按钮具有可访问名称，并暴露 `pressed`、`selected`、`expanded` 或 `disabled` 状态。
3. 可见焦点环不被播放器、粘性栏或抽屉遮挡。
4. 不只用紫/绿/灰表达词语状态，始终保留文字或图标说明。
5. A/S/D/Q 只是加速器，所有功能仍有可见按钮且不覆盖浏览器/辅助技术快捷键。
6. 动态“当前句、已标记、数量变化”使用克制且完整的状态播报，不抢夺焦点。

## 9. 公开技术架构指纹

以下均为 **技术推断**，只描述浏览器可见证据。

| 观察 | 证据 | 推断与限制 |
|---|---|---|
| 单页应用 | 根 HTML 只有挂载外壳和一个 hash 命名的模块 bundle | 前端为 SPA；不能据此确定所有路由策略 |
| React | 发布 bundle 中存在 `react`、`react-dom`、`createRoot` 指纹 | 可确认 React 客户端运行时；版本未在本报告固化 |
| Vite/Rollup 风格构建 | bundle 中存在 `__vite__` 指纹，资产名如 `index-DosS3XlF.js` | 很可能使用 Vite 构建；不代表开发仓库结构 |
| Material UI 倾向 | bundle 中存在 MUI 相关引用，控件和布局也呈现 Material 风格 | 可作为组件体系线索，不断言所有控件都来自 MUI |
| Firebase | HTML 加载 Firebase UI Auth CSS，bundle 包含 Firebase、Firestore、`authDomain` 和 Realtime Database 域名指纹 | 很可能使用 Firebase Auth，并在部分数据能力使用 Firestore/Realtime Database；真实表结构与权限规则不可见 |
| 独立 API | bundle 暴露 `api.dioco.io`、`api-cdn.dioco.io` 等主机字面量 | 存在自有 API/CDN 层；不探测私有接口或鉴权协议 |
| BunnyCDN | HTML、Manifest 和 bundle 响应头为 `BunnyCDN-*` | 静态站点和资产通过 BunnyCDN 分发 |
| Paddle | 根页加载 `cdn.paddle.com/paddle/paddle.js` | Pro 付费很可能使用 Paddle；未进入结账或验证订阅生命周期 |
| PWA | `manifest.json`、standalone、主题色、maskable 图标、大量 iPhone/iPad 启动画面和 service worker 指纹 | 支持安装型 Web 外壳；离线内容范围和更新策略未验证 |
| 本地状态 | bundle 含 `localStorage` 与 `indexedDB` 指纹 | 用于偏好、缓存或离线状态的可能性高；具体字段和敏感性未检查 |
| 网络层 | bundle 含 Axios 指纹 | 部分 HTTP 请求可能通过 Axios；不能证明所有调用一致 |
| 外部内容/语料 | YouTube、Netflix、Tatoeba、Chrome Web Store 等公开入口 | 产品通过第三方内容与语料增强学习，必须处理来源授权和失效 |

### 9.1 可能的数据边界

从 UI 行为可推断出以下概念模型，但字段名不是其真实数据库 Schema：

```text
User
├─ languagePreferences
├─ subscription / entitlements
├─ vocabularyStatus[]
├─ savedItems[]
├─ phrasePumpProgress
└─ chatbotPreferences / memory

ContentSource
├─ type: youtube | netflix | book | podcast | media | text
├─ title / language / sourceUrl / version
└─ Segment[]
   ├─ order
   ├─ sourcePosition: timestamp | page+sentence
   ├─ sourceText
   ├─ translation
   └─ Token[]
      ├─ surface
      ├─ lemma
      └─ partOfSpeech

SavedItem
├─ token/phrase
├─ segmentContext
├─ sourcePosition
├─ sourceIdentity
├─ media/screenshot reference
└─ user status / tags
```

### 9.2 对复刻架构的直接建议

- 把 `ContentSource`、`Segment`、`Token` 和 `SourcePosition` 做成明确 DTO，使视频时间戳与文章句序都能进入相同侧栏。
- 保存时冻结内容版本、原句和位置；第三方字幕变化后不能静默让旧证据指向不同文本。
- 词形归一和查词由内部 provider 接口承接，供应商结果必须转内部类型并校验。
- 词语标记只写个人偏好域，不直接写 `evidence_events` 或提高 `mastery`。
- 外部语料只保存许可允许的字段、来源与链接，不能未经授权复制完整内容。
- 媒体、词典、翻译和 AI 各自失败时允许主内容继续使用，并提供重试或降级。

## 11. 三类复刻决策

### 11.1 可以直接借鉴的交互原则

1. **逐句导航**：上一句、重播、下一句具有可见按钮与 A/S/D 快捷键。
2. **字幕后自动暂停**：作为用户可切换的输入节奏，不改变证据规则。
3. **文本即时间轴**：点击字幕句或文章句直接定位播放/朗读。
4. **词语侧栏不离开内容**：查词不发生页面跳转，选择状态可保留。
5. **上下文保存**：冻结内容版本、原句、来源、位置和可合法使用的音频引用。
6. **同一词元跨内容高亮**：不同表面词形归一后共享个人学习意图。
7. **导出透明**：允许导出结构化数据并清楚说明字段和媒体授权。
8. **公开空状态诚实**：没有数据、未登录或来源失效时解释原因和下一步。

### 11.2 必须改造后才能采用

1. PhrasePump 三态改为“已熟悉 / 想复现 / 暂不学习”的复习意图，不作为能力评分。
2. 词频改为选材和解释信号，不能主导首页，也不能覆盖语境成功。
3. 双语逐句默认应支持按需隐藏翻译、只显示当前句翻译或先听后看。
4. Chatbot 话题模板可用，但自然回应必须先于教学反馈，完整表达前不得打断。
5. 保存的第三方内容必须带来源、许可、内容版本和删除策略。
6. 桌面三栏在移动端重排为单主内容加底部抽屉，而不是只隐藏核心工具。
7. 快捷键要可配置、可发现，并为屏幕阅读器和所有动作保留可见替代。

### 11.3 禁止照搬

1. 把“标为已知、看过、查过、读过”直接计入发音、语流或真实口头反应。
2. 用词频或唯一参考句替代语境任务成功。
3. 首页罗列全部功能并要求用户先选择时长、模式或内容类型。
4. 仅图标一级导航、过小触控目标和没有可访问名称的按钮。
5. 对话中即时纠错覆盖角色的自然回应。
6. 未经授权抓取、复制或长期保存第三方全文、字幕、截图或音频。
7. 把 AI 生成内容直接发布，或让聊天模型直接写入画像、人物圣经和长期关系记忆。
8. 把媒体解析失败、低置信度转写或供应商错误当作负面学习证据。

## 12. 对 Sueño 的建议优先级

### P0：直接服务当前 UI 收敛，不新增产品范围

- 为现有阅读器词语侧栏补齐 `surface → lemma → POS → definition → current sentence` 的信息层级。
- 为现有逐句训练补充可见的上一句、重播、下一句与 A/S/D 快捷键，并保证焦点和取消安全。
- 在训练和阅读页面明确唯一主动作，其他工具进入次级区或侧栏。
- 审核图标按钮可访问名称、44px 触控目标、标题层级和固定区域遮挡。

### P1：单独设计后实现

- 内容来源统一 DTO 与 `sourcePosition`，让文章句序和未来媒体时间戳共享上下文保存模型。
- 词形归一、词元级跨内容高亮和语料例句 provider。
- 句子循环、字幕后自动暂停、临时显示翻译。
- 结构化个人词语导出，明确许可和音频引用边界。

### P2：完成个人 Alpha 验证后再评估

- 播客、外部视频和用户媒体导入。
- 类 PhrasePump 的跨内容句子复习器。
- 更大范围的课程目录与内容推荐。
- 浏览器扩展或第三方播放器叠加层。

P2 不是当前 Alpha 承诺。若进入实现，必须先更新设计、版权/隐私规则和实施计划，不能以竞品已有为理由扩张范围。

## 13. 登录后补测清单

未登录不会推翻本报告对公开页面的布局和设计结论，但以下事项必须登录后才能达到完整产品验证：

1. 词语 `KNOWN / LEARN / DON'T LEARN` 是否立即保存、是否可撤销、是否跨设备同步。
2. 同一词元不同变形的高亮与状态合并规则，以及同形异义词如何区分。
3. 保存项目是否包含原句、时间戳、截图、音频和来源版本，删除后如何级联。
4. PhrasePump 的选句算法、旧词/新词比例、完成条件、间隔策略和进度恢复。
5. Anki、CSV、JSON 真实导出的字段、编码、重复项、媒体文件和隐私边界。
6. Aria 的生成、停止、断流、重试、语音输入、纠错时机与 Pro 记忆权限。
7. Chatbot Settings 各设置是否自动保存、失败如何提示、是否影响既有会话。
8. 登录、退出、订阅、取消订阅和账户删除流程。
9. 本地媒体与我的文本的格式限制、上传位置、保留时间和删除能力。
10. PWA 离线范围、service worker 更新、IndexedDB 清理和多标签页一致性。

如果后续要补测，建议使用专门的测试账号和无版权风险的自有短文本/音频；不要在个人主账号中注入不可清理的测试词语、记忆和订阅状态。

## 14. 最终判断

Language Reactor 的核心竞争力可以用一句话概括：**它让用户在原生内容中遇到的每一句、每一个词，都能立即变成可理解、可定位、可保存和可复习的对象。**

Sueño 不应把自己改造成另一个功能密集的 Language Reactor。更合适的方向是：保留 Sueño 清晰的学习主线、口语证据规则、场景成功标准和角色/隐私边界，再选择性吸收 Language Reactor 的逐句控制、逐词侧栏、上下文保存与跨内容复习效率。这样得到的是“更容易持续完成真实口语任务的沉浸式平台”，而不是一个把词频和工具数量当作学习成果的内容播放器。
