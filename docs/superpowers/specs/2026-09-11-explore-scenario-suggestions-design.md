# Explore 场景建议与随机选择设计

- 日期：2026-09-11
- 状态：产品本人已逐节确认
- 任务归属：`SCN-003` 场景与表达库
- 上位设计：[Web 优先的个人学习产品与场景实战设计](2026-09-11-web-first-personal-learning-and-scenario-practice-design.md)
- 实施计划：[Web/PWA 场景学习闭环实施计划](../../plans/2026-09-11-web-first-scenario-practice-implementation-plan.md)

## 1. 问题与目标

用户进入 `/explore` 时不一定已经知道要搜索什么。Explore 需要在保留搜索、分类和浏览能力的同时，提供低负担的场景选择帮助，使用户无需先组织关键词，也能在一次选择后得到可解释、可开始且有权访问的场景。

本设计增加三个明确入口：

1. **适合我的**：结合可信学习状态和用户主动保存的资料，选择当前较有帮助的场景。
2. **探索新场景**：优先展示尚未练过的分类或沟通目的。
3. **随机来一个**：在已经过资格过滤、难度合理的候选中随机选择。

这三个入口是 Explore 内的发现辅助，不是首页的第二套学习调度器。首页仍根据稳定断点提供唯一且真实的“开始第一次练习”或“继续学习”主动作；到期复现和跨任务排序仍归 `SCN-004` 的 `recommendation` 模块。

## 2. 已确认方案与替代方案

采用“三个明确入口，共用一个合格候选池”的方案。每个入口直接说明选择依据，结果先展示预览卡，由用户决定开始或更换。

未采用的方案：

- 单一“帮我选”按钮再二次询问：页面更紧凑，但增加一步操作，也隐藏了系统能力。
- 默认使用对话式 AI 询问兴趣：表达能力强，但延迟、成本和不确定性更高，且难以形成稳定、可审计的默认路径。

LLM 只在现有内容不足、用户明确确认“生成私人场景”后参与，不用于默认选择或推荐理由生成。

## 3. 页面与交互

### 3.1 入口位置

在 `/explore` 搜索框下方增加“暂时不知道练什么？”区域：

- **适合我的**——“根据你的水平、收藏表达和近期练习推荐。”
- **探索新场景**——“发现还没练过的生活、学习和社交场景。”
- **随机来一个**——“从适合当前水平的可用场景中随机选择。”

知道目标的用户继续直接搜索；三个入口不替代搜索，也不在进入 Explore 前要求选择时长、训练模式或内容类型。

### 3.2 结果卡

点击入口后原位显示一张结果卡，不自动进入练习。结果卡包含：

- 场景名称、分类、CEFR 难度和沟通目标；
- 一至两个简短、可理解的选择理由；
- 主动作“开始练习”；
- 次动作“换一个”；
- 可选动作“收藏”；
- 公共场景或本人私人场景的来源标识。

理由示例：

- “适合你当前的 A2 难度。”
- “可以复用你收藏的问路表达。”
- “你还没有练过医疗沟通类场景。”

不展示内部权重、能力小数或“匹配度 93%”一类虚假精确度。

### 3.3 换一个与候选用尽

“换一个”在当前建议会话中排除已经展示的场景。单次建议会话默认最多展示五个不同结果；达到上限后提示调整分类或难度、重新开始一轮选择，或者确认生成私人场景。该限制用于避免无限刷新形成老虎机式交互，不限制用户正常搜索和浏览场景库。

### 3.4 响应式与可访问性

桌面端可横向排列三个入口；iPhone 端按单列排列。结果卡原位更新，避免无必要跳页。按钮触控区域不小于 44px，加载、成功、失败和不可用状态均有文字说明，不只依赖颜色。结果更新后以可感知但不抢夺正在输入焦点的方式播报；关闭或结束结果卡后将焦点还给触发入口。

## 4. 候选资格

三个模式先经过相同的服务端资格过滤。候选必须满足以下条件之一：

- 已完成要求审核并处于 `published` 状态的公共场景；
- 当前用户拥有、未归档且 Schema 完整的私人场景。

候选同时必须：

- 支持当前可用的练习模态；
- 包含可开始所需的沟通目标、表达、提示和临时人物数据；
- 没有被删除、失效或因来源不可用而阻断；
- 通过服务端所有权、内容版本和发布状态检查。

必须排除：

- 未审核或未发布的公共内容；
- 其他用户的私人场景或私人来源；
- 当前无法开始的场景；
- 当前建议会话中已经展示的场景；
- 具有稳定学习断点、应由首页“继续学习”承接的当前任务。

现有 Explore 列表仍可按其原有状态展示进行中内容，但场景建议不会借此建立第二个“继续学习”入口。

## 5. 三种选择策略

### 5.1 适合我的

在合格池中按确定性规则排序：

1. 难度与可信 CEFR 状态是否匹配；
2. 是否能复用用户主动收藏的表达；
3. 是否覆盖由可靠口语证据确认、且适合当前场景练习的近期困难；
4. 是否避免刚刚完成或连续多次出现的场景；
5. 在前述条件相同时优先更具新鲜度的场景。

画像证据不足时不伪造个性化，退化为“难度安全、可立即开始、近期未展示”的基础选择，并在理由中使用“适合作为基础练习”，而不是声称了解用户能力。

### 5.2 探索新场景

优先级为：未练过的分类、未覆盖的沟通目的、近期较少出现的场景，再以难度安全和内容完整度打破平局。新鲜度不能绕过 CEFR 安全区，也不能让未审核内容获得资格。

### 5.3 随机来一个

随机不是对数据库全量盲抽。服务端先完成资格过滤和难度安全筛选，再从前一组合格候选中加权抽取。近期刚完成或连续出现的场景降低权重；尚未练过但难度合理的场景提高权重。

随机数生成器作为策略依赖注入，使默认实现可使用安全随机源，测试可使用固定 seed。客户端不能提交任意候选 ID 或自行决定可访问范围。

## 6. 推荐依据与隐私

允许使用的服务端数据：

- 当前 CEFR 与 `mastery`、`confidence` 分离后的可信学习画像；
- 已完成或开始过的场景记录；
- 用户主动收藏的表达；
- 由合格证据确认的近期困难；
- 当前用户自己的私人场景及来源引用。

明确禁止：

- 使用原始录音、完整私密对话或长期角色关系记忆；
- 用低置信度转写、技术失败或取消产生负面偏好；
- 用打字表现提高或降低发音、语流和真实口头反应判断；
- 用学习时长参与能力判断或场景排序；
- 把推荐行为本身写成学习证据；
- 把未审核公共内容通过推荐路径暴露到生产环境。

理由只暴露必要的学习解释，不回显完整错误原句或私人来源正文。本功能不新增用户行为分析埋点；普通诊断日志只记录内部请求 ID、模式、结构化结果状态和延迟，不记录搜索原文、来源正文、私密对话或能力明细。

## 7. 私人场景生成回退

优先从已有公共场景和本人私人场景选择。只有没有合适结果或候选已经用尽时，才展示生成入口。

生成入口先说明可用依据，例如“使用你收藏的两条表达生成私人场景”。用户确认后，调用 SCN-003 已规划的独立生成用例。该用例必须再次执行鉴权、来源所有权、最小化读取、Schema 校验和幂等检查。

生成结果：

- 默认仅当前用户可见；
- 保存为私人 draft，可立即学习；
- 不进入公共内容 API 或公共建议候选；
- 失败时不保存半成品，重试不重复生成；
- 可由用户取消和删除。

如果没有可用来源或生成 Provider 不可用，展示三个轻量主题选项，例如“日常生活”“学习办事”“社交沟通”，继续从现有合格内容中过滤；不得伪造 AI 已生成成功。

## 8. 模块与 API 边界

发现与选择归 `explore` 模块，场景实战仍归 `scenario-practice`：

```text
Explore 页面
  -> POST /api/v1/explore/scenario-suggestions
  -> ExploreSuggestionUseCase
  -> 场景目录、收藏表达、可信画像的只读端口
  -> 纯资格过滤与选择策略
```

建议新增：

```text
src/modules/explore/domain/scenario-suggestion.ts
src/modules/explore/application/suggest-scenario.ts
app/api/v1/explore/scenario-suggestions/route.ts
```

请求 DTO：

- `mode`: `best_fit | discover | random`
- `suggestionSessionId`
- `requestId`
- `excludedScenarioIds`
- 用户主动选择的可选分类、CEFR 或模态筛选

响应 DTO：

- 统一场景卡 DTO 与可开始链接；
- `sourceKind`: `public | personal`
- 一至两个结构化 `reasonCodes` 及本地化展示文本；
- `canSwap`、当前会话已展示数量和候选用尽状态；
- 无结果时的结构化生成建议，但不直接触发生成。

Route Handler 只做鉴权、Zod 校验、调用 application 用例和协议转换。资格过滤、排序与随机策略保持纯 TypeScript，并通过 repository/provider 端口读取数据。用户专属响应使用 `private, no-store`；服务端不返回完整候选池、内部排序权重、原始错误记录或其他用户数据。

私人场景生成继续使用独立写接口与 `Idempotency-Key`，不能由建议接口产生隐式写入或 Provider 费用。

## 9. 并发、空状态与恢复

- 首次加载时三个入口立即可用；画像尚未加载或没有画像时使用安全基础候选。
- 选择请求只锁定当前入口，搜索框和已有结果保持可用。
- 每次请求携带 `suggestionSessionId` 与 `requestId`；客户端取消旧请求，旧响应不得覆盖当前结果。
- 请求失败时保留已有结果，并提供“重试”与“直接搜索”。技术失败不进入学习证据。
- 候选为空时返回明确的 `no_eligible_scenario`，页面展示主题筛选和经确认的私人生成入口。
- 私人来源失效或越权时跳过该候选，不泄露其存在。
- 生成失败时保留用户已选择的主题和来源引用，允许使用同一幂等键安全重试。
- 离线缓存只可用于展示最近场景卡；进入练习前仍须由服务端确认权限、版本与可用性。

## 10. 测试与验收

### 10.1 单元测试

- 三种模式对同一候选池产生符合各自规则的结果；
- 未发布、越权、失效、不完整和模态不兼容的候选始终被排除；
- `random` 只从合格池抽取，固定 seed 可复现；
- `excludedScenarioIds` 和五次会话上限阻止重复展示；
- 学习时长、低置信度转写、技术失败和纯打字表现不影响排序；
- 理由代码与实际命中的规则一致；
- 没有可信画像时正确退化，不伪造个性化理由。

### 10.2 应用、契约与数据库测试

- 未登录请求返回稳定鉴权错误；
- 公共发布状态、私人场景和私人来源所有权由服务端验证；
- 空候选池返回结构化状态，而不是 500；
- 用户专属响应不可公共缓存；
- 生成入口不隐式调用 Provider，确认后的生成写入继续满足幂等和事务规则；
- 旧 `requestId` 的结果不能更新最新页面状态。

### 10.3 Playwright

- 无需输入搜索词即可进入三个选择模式；
- 结果卡可以开始、收藏和换一个；
- 无学习画像的新用户仍能获得基础建议；
- 覆盖候选用尽、网络失败、生成失败和焦点恢复；
- 搜索与 Explore 原有筛选仍可独立使用；
- 桌面 Chromium 和 390px 移动视口无横向溢出，关键路径再由真实 iPhone Safari 验证。

### 10.4 验收条件

用户不知道练什么时，最多一次选择即可得到一个可解释、可开始且有权访问的场景；结果不合适时可以换一个；现有内容不足时才引导用户确认生成私人场景。选择过程不产生学习证据、不泄露私人来源、不调用默认高成本 AI，也不改变首页唯一下一动作。

## 11. 非目标与后续

本设计不包含：

- SCN-004 的到期复现、历史排序或首页唯一下一动作；
- 基于完整对话的开放式 AI 选课顾问；
- 公共内容自动发布或 AI 自动审核；
- 跨用户协同过滤、社交热榜或商业推荐；
- Flutter、原生 iOS/Android 或桌面客户端同步。

后续只有在 SCN-003 的确定性策略缺少实际选择质量时，才基于匿名、最小化的人工验收结果讨论新排序信号；任何新增数据用途需先补充隐私说明和测试。
