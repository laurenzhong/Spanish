# 自动内容供应与词句学习重构设计

- 日期：2026-09-12
- 状态：产品本人已完成逐项确认和书面规格复核
- 当前任务：`IA-001`
- 适用范围：个人 Alpha、响应式 Web/PWA；当前以电脑端 Web 为主要验收环境
- 关联决策：[ADR-0008：内容驱动学习入口与自动采集审核链路](../../adr/0008-content-led-learning-and-automated-ingestion.md)
- 调研依据：`2026-09-12-language-reactor-technical-ux-research.md`（当前位于原工作区且尚未纳入本分支；本任务只读使用，不复制或覆盖该文件）

## 1. 背景与结论

现有“学习”页围绕“开始第一次练习”“继续学习”和独立表达训练组织，任务感过强，且与已经成熟的探索场景练习重复。产品本人确认不再保留该页现有内容与功能入口；用户打开产品后本来就有学习意图，不需要额外的 Hero、欢迎说明或强制任务 CTA。

新的产品结构仍保留“学习、阅读、探索、对话、我的”五项一级导航，但重新定义职责：

- **学习**：直接展示视频和播客资料库，用户点击任何内容即可开始，不再先经过任务入口。
- **阅读**：承载文章、词汇、短语、文字考察和跨来源语料查询。
- **探索**：继续承载公共场景、私人场景、表达发现和临时人物多轮实战。
- **对话**：承载 Lucía 等长期 AI 角色、文字与语音消息及关系记忆。
- **我的**：承载四板块能力、有效活动、数据与隐私、Provider 设置，以及仅所有者可见的内容工作流。

内容供应从手工少量导入改为“每日自动发现与处理、所有者审核、显式发布”。第一版接入白名单 YouTube 频道、播客 RSS、文章 RSS 和少量专用适配器。自动化只能创建候选草稿，不能绕过来源、许可、内容质量和审核门禁直接发布。

## 2. 取代关系与不变量变化

本规格在书面复核后取代以下旧决定：

- [2026-08-20 产品设计](./2026-08-20-spanish-speaking-learning-platform-design.md)中“学习首页必须提供唯一下一动作”的页面要求。
- [2026-09-11 Web 优先设计](./2026-09-11-web-first-personal-learning-and-scenario-practice-design.md)中“学习负责今日新任务、继续学习和到期复现”的导航定义。
- [2026-09-11 授权视频设计](./2026-09-11-licensed-video-immersion-content-design.md)中“视频继续作为 `content_packs` 且不改变学习导航”的建模与入口决定；该文档的来源、许可、字幕和播放器调研仍可作为实现参考。
- 现有 `AGENTS.md`、`README.md`、`PROJECT_STATUS.md`、实施计划、架构和测试文档中相同的旧表述；这些文件在详细实施计划的文档同步切片中统一更新，在此之前不得把两种产品结构混合实现。

新的入口不变量是：

> 登录后打开“学习”即看到真实可用的视频和播客内容；页面不设置 Hero、“开始学习”“继续学习”或唯一任务 CTA，也不要求先选时长、模式或内容类型。每张内容卡本身就是等权、真实的开始入口。

以下不变量继续有效：

- 听说仍是能力验证核心，阅读和文字考察只更新其适用的词句或交流证据。
- 用户完整表达前不得纠错或打断。
- 评分以语境成功为先，接受自然替代表达。
- 打字不能提高发音、语流、真实口头反应或跟读表现。
- 低置信度转写和技术失败不能产生负面能力证据。
- `mastery` 与 `confidence` 分离，学习时长只进入热力图。
- 长期角色记忆、私人场景和内容工作流继续执行现有所有权、RLS、隐私和角色安全规则。

## 3. 目标与非目标

### 3.1 目标

1. 让用户打开学习页后像使用桌面 YouTube/B站一样直接选择真实西语视频或播客。
2. 让视频、播客和文章共享“来源—版本—片段—词句出现位置”语义，而不是共享一个臃肿的业务表。
3. 每日自动发现和处理可用素材，减少手工寻找、转写、切句、分类和建索引的成本。
4. 让词汇、短语和语料始终保留原始上下文，并可从文章、视频或播客跳回准确位置。
5. 用不要求口头作答的文字考察建立词汇与短语证据。
6. 用 AI 角色对话、语音消息和跟读分别建立交流、语音和跟读证据。
7. 让所有者在一个轻量工作流中完成候选复核、修订、批准和发布，不建设完整 CMS。

### 3.2 非目标

- 公开内容社区、创作者后台、商业订阅、广告或推荐竞价。
- 任意网站抓取、绕过登录/付费墙/DRM、规避平台限制或下载许可不明媒体。
- 自动发布未经所有者复核的 AI 文本、字幕、翻译或第三方内容。
- 实时双向语音、用户音频媒体库或本地离线 ASR。
- 在 `content_packs` 中继续堆叠文章、视频、播客和词库的新语义。
- 恢复 Flutter 同步或为本阶段新增原生客户端。
- 用词频、遇见次数、收藏或看完内容直接证明掌握。

## 4. 五项导航的新定义

| 导航 | 用户问题 | 主要内容与动作 | 明确不承担 |
| --- | --- | --- | --- |
| 学习 | “我现在想看或听点西语” | 视频、播客、筛选、搜索、继续播放、媒体学习器 | 独立表达课、任务 Hero、到期复现队列 |
| 阅读 | “我想读、查、记或考察词句” | 文章、词汇、短语、语料查询、文字考察 | 视频/播客目录、临时人物实战 |
| 探索 | “我想练一个现实场景” | 场景库、表达发现、私人生成、多轮实战、复盘 | 长期角色关系、媒体资料库 |
| 对话 | “我想和熟悉的角色交流” | 长期角色、文字/语音消息、自然关系 | 临时训练人物、媒体目录 |
| 我的 | “我想看能力或管理数据” | 四板块能力、活动、隐私、Provider、所有者工作流 | 手机顶部重复头像入口 |

### 4.1 桌面与移动壳层

- 桌面继续使用可收缩侧边导航；账户菜单可以位于侧栏底部或“我的”页内。
- 手机继续使用带文字标签的五项底部导航。“我的”已经是稳定账户入口，因此产品首页和普通一级页顶部不再常驻头像。
- 深层页面顶部只保留与当前内容有关的返回、标题和必要动作；账户入口不与底部“我的”重复。
- 所有触控目标至少 44px，固定区域预留安全区与内容底部空间。

## 5. 学习页：视频与播客资料库

### 5.1 首屏结构

`/learn` 打开后直接显示内容，不出现欢迎 Hero、进度宣言、“开始学习”“继续学习”或模式选择器。桌面布局由以下区域组成：

1. 紧凑页头：页面标题、搜索和必要的视图设置。
2. 内容类型切换：`全部 / 视频 / 播客`，默认“全部”。
3. 横向主题或频道筛选：地区、难度、主题、时长、来源；高级筛选可收起。
4. 内容网格或高密度列表：缩略图/封面、标题、来源、内容类型、时长、地区、发布时间、字幕/转写状态和上次播放位置。
5. 分页或稳定的“加载更多”；第一版不做不可控无限滚动。

每张卡都可直接打开，且只有真实可播放/可收听的已发布内容才显示。恢复位置只是卡片上的次级状态，不改变所有卡片等权可选的结构。

### 5.2 排序与筛选

第一版支持：

- 搜索标题、频道/节目、摘要、主题和已索引词句。
- 按全部、视频、播客切换。
- 按 `es-ES`、拉美地区或未知地区过滤。
- 按 A1、A2、B1、B2 或未分级过滤；难度是选材信号，不是能力结论。（2026-10-10 修订：媒体难度从 A2/B1 扩展为四档，与文章、场景和生成故事的 A1–B2 口径对齐；迁移 `0041_media_cefr_four_levels`，已发布内容的历史难度值不变。）
- 按短、中、长时长过滤。
- 按最新发布、最近收录和最近继续排序。

推荐和个性化排序延后。没有足够数据时按稳定的“最近收录＋来源质量”排序，不能用伪造的“适合你”解释。

### 5.3 空、错和下架状态

- 没有匹配内容：保留筛选条件并提供清除筛选。
- 素材暂不可用：从公开目录移除；历史状态保留，并显示来源已失效或已撤下。
- 播放地址、嵌入或音频失败：保留标题、字幕和重试，不跳到其他内容冒充成功。
- 字幕缺失：仍可播放，但明确说明当前无逐句辅助；若处于 ASR 候选则不提前公开未审核草稿。

## 6. 统一媒体学习器

视频与播客使用同一内容、片段和词句侧栏语义，但保留不同的主播放器：视频使用受控官方嵌入或已获许可的媒体资产，播客使用音频播放器和节目封面。

### 6.1 桌面布局

- 主区：播放器、标题、来源、基础控制和当前片段。
- 字幕区：按时间排序的西语片段，可选中文翻译；当前片段高亮。
- 辅助区：词典/短语、语料例句、已保存状态和当前来源信息。
- 高级工具默认折叠，避免把 Language Reactor 的所有控制同时暴露给第一次使用者。

### 6.2 核心操作

- 上一句、重播、下一句有可见按钮，并提供 `A / S / D` 快捷键。
- 自动暂停是用户可选设置；`Q` 只是快捷方式，不是唯一入口。
- 点击字幕行定位到句子起点；点击词语或审核短语只更新辅助区，不离开媒体。
- 可切换仅西语、双语、隐藏字幕；翻译默认不覆盖主内容。
- 保存词或短语时冻结内容版本、片段、原句和时间位置。
- 视频和播客分别保存最后播放毫秒、最后片段和内容版本。

### 6.3 手机重排

手机不缩小桌面三栏。播放器全宽，当前片段紧随其后，完整字幕在主滚动区，词句解释使用可拉起的底部抽屉。抽屉关闭后焦点回到触发词，不能遮挡底部导航或播放器控制。

### 6.4 跟读

每个已审核片段可显式进入“跟读这句”。跟读是独立尝试：

- 使用新的 `attemptId` 和 `generationId`。
- 原音播放和录音生命周期可取消、可释放。
- 完成后才评估完整度、发音、节奏/韵律和可理解度。
- 静音、过短、低置信度和 Provider 失败只返回待验证或可重试。
- 跟读证据只进入“跟读表现”，不自动证明自由交流。

## 7. 阅读页：文章、词汇、短语与语料

`/read` 保留一个一级导航，在页面内提供 `文章 / 词汇 / 短语 / 语料` 四个稳定子入口。文章继续使用现有 article 模型和阅读器；词汇、短语与语料由新的 `lexicon-corpus` 模块提供。

### 7.1 词汇页

词汇对象以规范化词元为主，至少显示：

- 词元、词性、常见表面词形和发音。
- `zh-CN` 核心释义、语域、地区和常见搭配。
- 当前语料频次、遇见次数、来源类型和最近上下文。
- 用户意图：`已熟悉 / 想复现 / 暂不学习`。
- 可追溯的文章段落、视频/播客片段和跳转位置。

用户意图只是个人组织状态，不直接更新 `mastery` 或 `confidence`。

### 7.2 短语页

短语不是简单字符串收藏。正式条目至少保存规范化表达、自然变体、可替换槽位、语用目的、正式程度、地区、中文说明和多个真实上下文。用户从内容中保存的短语先进入私人条目，不自动晋升为正式公共内容。

### 7.3 语料查询

语料页支持词元、表面词形、完整短语和短语模式查询，第一版返回 KWIC（关键词在上下文中）结果：

- 左右上下文、来源标题、内容类型、地区、日期和说话者（可用时）。
- 文章定位到段落，视频/播客定位到毫秒和片段。
- 按内容类型、地区、来源、日期和词性过滤。
- 查询结果只来自已发布内容或当前用户拥有的私人内容。
- 服务端重新校验可见性，不能因索引命中泄漏撤下内容或其他用户文本。

### 7.4 文字考察

词汇和短语考察不要求口头回答。题型优先级为：

1. 语境选择。
2. 含义或用法判断。
3. 语境填空。
4. 少量完整输入，用于确认拼写和主动提取。

题目必须来自已发布内容的冻结上下文，接受语义等价答案。一次题目提交使用稳定 `assessmentAttemptId`，重复提交不得重复生成证据。单次选择、收藏、点击释义或浏览词条不构成能力证据。

## 8. 自动内容供应工作流

### 8.1 来源白名单

第一版只从所有者明确配置的来源运行：

- YouTube 白名单频道：使用官方 API/RSS 发现视频和读取允许取得的元数据/字幕；不做通用搜索爬虫或规避下载限制。
- 播客 RSS：读取 feed、episode 元数据和 enclosure；是否临时处理音频由来源规则和权利状态决定。
- 文章 RSS：读取摘要或正文；只有来源许可/授权允许时才进入全文处理。
- 专用文章适配器：仅用于结构稳定且已记录许可与抓取约束的来源。

每个来源保存：适配器类型、来源 ID、语言/地区、抓取频率、允许内容类型、权利策略、速率限制、启用状态和最后成功游标。密钥只存在服务端或调度运行环境。

### 8.2 每日链路

```text
每日调度
  → 拉取白名单来源增量
  → 用来源 ID、规范化 URL 和内容哈希去重
  → 相关性、语言、时长、质量与权利策略初筛
  → 获取允许使用的元数据、正文、字幕或临时音频
  → 无可用字幕时按预算与资格决定是否 ASR
  → 清洗、切片、语言识别、翻译草稿和词句抽取
  → 结构/安全/重复/来源校验
  → 进入所有者候选审核库
  → 所有者修订并分别批准内容与发布
  → 生成不可变版本、发布目录和语料索引
```

每日自动化到“候选审核库”为止。发布必须由所有者显式操作。

### 8.3 调度实现边界

业务逻辑位于仓库内 `content-acquisition` 模块和 TypeScript CLI，不绑定特定平台。个人 Alpha 首版由定时 CI runner 每日触发；长任务按来源和候选拆成有界批次，使用 PostgreSQL 工作记录恢复，不新增消息队列或独立微服务。Vercel Route Handler 只负责所有者操作和短请求，不承担长时间抓取、下载或 ASR。

### 8.4 自动初筛

候选必须同时满足：

- 西语为主体，语言置信度达到配置门槛。
- 来源处于启用白名单，且没有命中撤下/拒绝记录。
- 标题、摘要和抽样文本与学习主题相关。
- 时长或文章长度位于来源配置范围。
- 音频清晰度、字幕覆盖或正文质量达到最低门槛。
- 权利策略允许读取和处理当前字段；证据不足时进入 `rights_pending`，不获取大型资产。

评分只用于候选排序，不能成为发布决定或用户能力证据。

### 8.5 字幕与 ASR

处理优先级为：来源提供的人工字幕 → 来源提供的自动字幕 → 允许处理时进行 ASR。没有字幕的媒体只有在以下条件全部满足时才自动 ASR：

- 已通过来源、相关性、语言、时长和权利初筛。
- 当日/当月 ASR 预算尚有余额。
- 没有相同音频哈希或同一来源版本的已完成转写。
- 音频可以在允许的处理链路中临时取得。

ASR 结果永远是草稿，保存 Provider、模型、请求 ID、置信度、语言、时间轴和成本。临时音频在成功、失败、取消或超时后立即删除；低置信度片段在审核界面醒目标记，不能自动发布。

### 8.6 候选、审核与发布状态

为避免把抓取进度、教学审核和公开状态混为一个枚举，分别保存：

- `acquisitionStatus`：`discovered / screened / acquiring / processing / review_ready / failed / rejected`。
- `rightsStatus`：`unknown / pending / verified / restricted / revoked`。
- `reviewStatus`：`pending / changes_requested / approved`，并分别记录 `es-ES` 内容审核和 `zh-CN` 教学审核。
- `publicationStatus`：`draft / published / archived`。

只有 `acquisitionStatus=review_ready`、`rightsStatus=verified`、两个审核维度均为 `approved` 且结构校验通过的版本才能发布。发布创建不可变内容版本；后续正文、字幕、翻译、时间轴或语用含义变化必须新建版本。

### 8.7 所有者工作流

入口位于“我的 → 内容工作流”，仅项目所有者可见。列表展示：

- 来源、类型、发现时间、质量/相关性信号和去重结论。
- 权利字段及其证据，不把平台自报许可当作自动批准。
- 正文或字幕与来源并排预览、低置信度片段、翻译和词句抽取。
- 处理阶段、失败原因、Provider/模型、耗时和估算成本。

操作包括接受进入审核、请求修改、拒绝、重新处理、批准两个审核维度、发布和撤下。批准与发布是两个显式动作；任何失败都保留可重试状态，不产生半发布版本。

## 9. 模块边界

新增三个业务模块，并复用现有 article：

### 9.1 `content-acquisition`

负责来源注册、增量游标、发现、去重、初筛、采集状态、处理编排、预算门禁和候选审核投影。不拥有正式文章、媒体版本、词汇或学习证据。

### 9.2 `media`

负责已接受视频/播客的稳定身份、不可变版本、播放资产、字幕/转写片段、来源位置、用户播放进度和公开投影。它不负责来源爬取、词元归一或能力评分。

### 9.3 `lexicon-corpus`

负责词元、词形、短语、出现位置、语料查询、个人词句意图和文字考察。它读取 article/media 的只读版本投影，不修改其内容，也不直接更新 profile；可信考察结果通过 evidence application 写入。

### 9.4 现有模块调整

- `content`/article：继续拥有文章版本、正文、来源、审核和发布；自动采集只提交文章草稿 DTO。
- `training`：保留可复用的尝试、录音和证据编排能力，但不再提供独立任务式学习首页或核心表达课入口。
- `explore`/`scenario-practice`：继续负责场景与临时人物，不承载媒体目录。
- `conversation`：继续负责长期角色文字和语音消息；只把完整、服务端验证的结果交给 evidence。
- `evidence`/`profile`：继续是能力事实与快照权威，不信任客户端或采集 Provider 的评分。
- 旧 `content_packs`：冻结为兼容和历史证据载体，不为新视频、播客或文章扩展新语义；迁移和退役另设任务，不物理删除已有记录。

依赖方向：

```text
scheduled runner / owner UI → content-acquisition application
                                   ├→ source adapters
                                   ├→ article draft port → content/article
                                   └→ media draft port   → media

article read model ─┐
media read model  ──┼→ lexicon-corpus → evidence → profile
private sources   ──┘
```

所有 domain 保持纯 TypeScript。Route Handler 只做鉴权、Zod 校验、调用 application 和协议转换。模块不能直接写其他模块拥有的表。

## 10. 统一内容位置模型

文章和媒体不强行共用同一实体表，但通过明确 DTO 共享定位语义：

```ts
type ContentDocumentRef =
  | { kind: "article"; stableKey: string; version: number }
  | { kind: "media"; stableKey: string; version: number };

type SourcePosition =
  | { kind: "text"; paragraphId: string; segmentIndex: number }
  | { kind: "media"; startMs: number; endMs: number; segmentIndex: number };
```

词句出现记录同时引用文档、不可变版本、片段、表面文本、规范化词元/短语和 `SourcePosition`。删除或撤下来源时，索引不可继续通过公开查询返回，但内部审计引用可以保留。

## 11. 数据模型

以下是逻辑表族；具体列、索引和迁移顺序在实施计划中按单一任务细化。

### 11.1 自动采集

- `acquisition_sources`：白名单、适配器、游标、频率、权利策略、速率和启用状态。
- `acquisition_runs`：`runId`、触发来源、开始/结束、状态、游标和汇总计数。
- `content_candidates`：来源身份、规范化 URL、类型、状态、质量信号、权利状态和去重键。
- `candidate_artifacts`：允许保留的元数据、正文/字幕草稿、临时资产引用、哈希、处理版本和保留期限。
- `candidate_processing_attempts`：`jobId`、步骤、generation、Provider、状态、重试、延迟和成本。
- `candidate_reviews`：审核维度、结论、审核者引用、时间、备注和候选版本。

### 11.2 媒体

- `media_items`：稳定身份、类型、来源和当前发布版本。
- `media_versions`：不可变标题、摘要、语言、地区、难度、主题、发布日期和内容哈希。
- `media_assets`：官方嵌入/受控音频或视频资产、时长、媒体类型、可用性、许可和短时播放策略。
- `media_segments`：稳定片段、时间范围、说话者、西语文本、翻译和审核状态。
- `user_media_progress`：用户、版本、最后毫秒、最后片段、完成状态和 revision。

### 11.3 词句与语料

- `lexemes`、`lexeme_forms`：规范化词元、词性、语言和表面形态。
- `phrase_entries`、`phrase_variants`：正式短语、变体、槽位、语用、地区和审核版本。
- `corpus_occurrences`：文档版本、片段、位置、左右上下文和词元/短语引用。
- `user_lexical_intents`：`familiar / revisit / ignore`，只表示个人复习意图。
- `lexical_assessment_items`：题目版本、来源上下文、答案规则和适用技能。
- `lexical_assessment_attempts`：幂等提交、答题结果、输入方式、算法版本和证据引用。

所有用户私有表包含 `user_id`、RLS、服务端所有权检查和账号删除级联。正式内容表只能由服务端导入/发布角色写入。

## 13. 四板块能力与证据

旧八维雷达图不再作为产品主画像。新的“我的 → 能力”使用四个板块，每个板块内部仍保存可解释子技能、`mastery`、`confidence`、证据数量和最近验证时间，不生成缺乏依据的单一总分。

| 板块 | 可信来源 | 可以更新 | 不可更新 |
| --- | --- | --- | --- |
| 词汇与短语 | 文字选择、判断、语境填空、少量完整输入 | 识别、语境含义、搭配/语用、文字主动提取 | 发音、语流、口头反应 |
| 交流运用 | AI 角色或临时人物中的完整文字/语音轮次 | 语境成功、交际策略、准确性、自然替代、提示依赖 | 仅浏览/收藏不能更新；文字轮不能更新语音子技能 |
| 语音表达 | 完整语音消息、自主口语任务 | 可理解度、发音、语流、口头反应（有可靠时间证据时） | 低置信度、技术失败、打字 |
| 跟读表现 | 用户显式开始并完成的跟读尝试 | 完整度、模仿清晰度、节奏/韵律、稳定性 | 自由交流能力、词句主动调用 |

同一次语音角色轮可以分别形成“交流运用”和“语音表达”的证据事件，但必须使用同一 `attemptId`、不同 `skillKey`，并由服务端去重。跟读证据永远不能替代自主表达。词句文字考察不要求录音，也不因未开口降低口语可信度。

现有历史八维证据不删除。`PROFILE-001` 提供版本化映射和迁移投影；无法可靠映射的历史维度保留在审计层，不伪造成新的四板块分数。

## 14. 可靠性、幂等与恢复

- 每次调度使用 `runId`，每个处理步骤使用 `jobId` 和 `generationId`。
- 来源平台 ID＋来源版本/发布日期＋规范化 URL形成发现幂等键；正文/字幕/媒体使用 SHA-256 去重。
- 同一幂等键和同一输入复用终态；同键不同输入返回冲突。
- 增量游标只在当前批次所有已承诺写入完成后推进，失败不丢失候选。
- 处理步骤以 revision/CAS 更新；旧 generation 只能记录诊断，不能覆盖新草稿。
- 下载、临时文件、网络流、播放器监听器、录音、定时器和对象 URL 由创建者释放。
- 无显式完成标记的 ASR/翻译/生成流视为失败，不发布部分结果。
- 来源限流、超时和 5xx 按有界退避重试；鉴权、权利限制和 Schema 错误不盲目重试。
- 发布事务同时创建不可变版本、更新当前发布指针和建立语料索引声明；任一步失败全部回滚。
- 大型索引构建可在发布后以 `indexing` 内部状态完成，但索引完成前内容不进入语料查询。

## 15. 安全、版权、隐私与保留

非盈利和未发布状态不取消来源与平台义务。系统仍必须保存来源、许可/授权、署名、抓取时间、内容哈希和撤下能力；不得绕过付费墙、访问控制、DRM 或平台下载限制。

保留策略：

- 未发布候选草稿：最后活动后 30 天删除或压缩为最小审计元数据。
- 被拒绝候选的大型正文、字幕草稿和媒体：7 天后删除；保留来源 ID、拒绝原因和哈希，避免重复采集。
- ASR 临时音频：成功、失败、取消或超时后立即删除。
- 已发布内容：按来源权利和版本政策保留；撤下后停止公开投影和索引，保留必要审计记录。
- 用户媒体进度、词句意图和考察记录：随账号删除流程级联或按证据政策处理。

日志只记录内部 ID、来源 ID、步骤、状态、延迟、稳定错误码、Provider/模型和估算成本，不记录完整受保护正文、完整字幕、临时音频、访问令牌、API 密钥或长期有效播放 URL。

## 16. 成本与运行控制

- 来源级速率、日抓取量、最大正文/音频大小、最长媒体时长和并发数可配置。
- ASR 设每日与每月硬预算；预算耗尽时候选保持 `review_ready` 或 `processing` 的明确等待状态，不悄悄跳过。
- 先去重和初筛，再下载/ASR/翻译；已有字幕不重复转写。
- 词形分析和语料索引批量预计算，不在每次页面查询时调用 LLM。
- 翻译或词句说明优先复用已审核内容和缓存；AI 草稿按内容版本缓存，但不能自动晋升为正式内容。
- 每次运行生成可核对的 discovered/duplicate/rejected/processed/review-ready/cost 汇总。

## 17. 测试策略

### 17.1 领域与 application

- 来源状态转换、非法转换、revision 冲突和过期 generation。
- 增量游标、来源 ID/URL/哈希去重和重复运行幂等。
- 语言、相关性、时长、质量、权利和预算门禁。
- 无字幕媒体的 ASR 资格；低置信度片段不能进入可发布版本。
- 两个审核维度和显式发布门禁；失败事务不产生半发布内容。
- 词元/词形归一、短语重叠、KWIC 边界和撤下内容不可见。
- 文字题自然等价答案、重复提交和题目版本冻结。
- 四板块证据路由；打字、观看、收藏、低置信度和技术失败隔离。

### 17.2 适配器契约

- YouTube API/RSS、播客 RSS、文章 RSS 和专用适配器使用固定 fake 响应。
- 覆盖分页、ETag/Last-Modified、游标、限流、鉴权、失效来源、字段缺失、恶意 HTML 和异常编码。
- ASR、翻译、语言识别和词形分析只断言内部 DTO、错误分类、取消与成本字段。
- 默认测试不访问公网、不下载真实媒体、不调用收费 Provider。

### 17.3 数据库与权限

- 所有者工作流接口拒绝非所有者，即使用户已登录。
- 普通客户端不能写正式内容、审核、发布和采集运行。
- 用户 A 不能读写用户 B 的媒体进度、词句意图或考察记录。
- 证据仍为 append-only；重复题目或语音提交不增加事件数量。
- 迁移从空库和上一版本均可执行，账号删除和候选清理顺序可验证。

### 17.4 组件与 E2E

- `/learn` 首屏直接显示媒体卡，不出现旧 Hero 或任务 CTA。
- 视频/播客筛选、搜索、分页、空状态、失效来源和恢复位置。
- 播放器逐句定位、A/S/D/Q、自动暂停、字幕模式、词句抽屉、取消和失效播放地址重试。
- `/read` 四个子入口、词句状态、语料查询、文字考察和来源跳转。
- “我的 → 内容工作流”的审核、请求修改、拒绝、批准、发布、撤下和失败重试。
- 320/375/414/768/1024/1440px 无横向溢出；手机顶部无常驻头像，底部“我的”可达。

## 18. 首版验收

1. 五项导航使用新职责；学习页打开即为已发布视频/播客资料库，无旧任务 Hero、开始/继续入口或独立表达训练卡。
2. 每日调度能从至少一个 YouTube 白名单频道、一个播客 RSS 和一个文章 RSS 增量发现内容；重复运行不产生重复候选。
3. 至少一篇文章、一个视频和一个播客走通“发现→处理→所有者双维度审核→显式发布→网站可见”。
4. 没有字幕的合格媒体可在预算内生成带置信度的 ASR 草稿；临时音频处理后删除，低置信度内容不能自动发布。
5. 视频和播客使用同一字幕/转写、逐句控制、词句解释和位置恢复语义，失败时保留可恢复路径。
6. 阅读页可浏览文章、词汇、短语并进行跨来源语料查询；结果能跳回文章段落或媒体时间点。
7. 词句考察完全可以文字完成，且只有提交后的可信结果进入“词汇与短语”证据。
8. 四板块能力清楚区分词句、交流、语音与跟读；历史数据不足时显示待积累，不绘制虚假值。
9. 所有者以外的用户无法看到内容工作流或调用内部操作；正式发布、用户私有状态和撤下内容均通过权限测试。
10. 相关 lint、typecheck、单元、契约、数据库、Playwright 和 build 门禁通过；真实收费调用与公网采集只在显式运行中执行并记录成本。
