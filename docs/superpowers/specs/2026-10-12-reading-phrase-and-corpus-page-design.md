# 阅读页短语与语料页面设计

- 状态：accepted（产品本人于 2026-10-12 确认首屏例句与短语匹配语义）
- 日期：2026-10-12
- 关联规格：`docs/superpowers/specs/2026-09-12-automated-content-supply-and-lexical-learning-redesign.md`
- 关联 ADR：`docs/adr/0012-reading-phrase-and-corpus-workspace.md`
- 关联任务：`LEX-001`、`LEX-002`

## 1. 目标

把阅读区的两个入口分成两个清晰的工作模式：

- `/read/phrases` 是表达库。用户在这里理解一个表达、查看语用和变体，并决定是否复习。
- `/read/corpus` 是语料浏览器。用户在这里搜索多个真实用例、比较上下文，再跳回原始文章段落或媒体时间点。

两页共用 `/read` 的单行子导航和视觉语言，但不合并成一个复杂工作台。短语页强调条目理解和个人组织，语料页强调查询、比较和来源定位。

浏览、收藏、展开例句、设置 `familiar/revisit/ignore` 和跳转来源都不写入 `evidence_events`、`mastery` 或 `confidence`。只有显式提交的文字考察进入词汇与短语能力证据。

## 2. 调研依据

调研日期：2026-10-12。

- [Readlang](https://www.readlang.com/) 将文本中的即时词句解释、保存和后续卡片复习连在一起。短语信息应从当前阅读上下文进入表达库，用户不需要离开原文寻找入口。
- [Linguee](https://www.linguee.com/) 以短语检索和带来源的双语例句为核心。语料结果必须携带来源标题和内容类型，不能只展示孤立句子。
- [Tatoeba](https://tatoeba.org/en/) 同时提供句子搜索、语言/标签浏览、可靠性提示和音频入口。语料页需要明确空状态、来源状态和可用位置。
- 本地 UI/UX 规则要求搜索无结果时给出恢复动作、输入和筛选可通过键盘操作、触摸目标至少 44px、加载期间避免把已有结果清空，并支持可恢复的深链接。

## 3. 信息架构

| 页面 | 首要问题 | 默认内容 | 主要动作 | 次要动作 |
| --- | --- | --- | --- | --- |
| 短语 | 这个表达是什么意思、什么语气、我要不要复习？ | 表达卡片列表 | 设置复习意图 | 查看例句、进入语料、打开来源 |
| 语料 | 真实内容里的人怎么使用它？ | KWIC 结果列表 | 搜索并比较用例 | 筛选来源、查看短语条目、跳转位置 |

两页之间使用可恢复 URL 互相跳转：

```text
阅读器中的短语
  → 短语详情/加入“想复现”
  → /read/corpus?entryKind=phrase&entryId=...
  → KWIC 结果
  → 文章段落锚点或媒体毫秒位置
  → 可选文字考察
```

## 4. 共享页面规则

1. 保留现有单行阅读导航：`文章 / 词汇 / 短语 / 语料 / 已保存`。不增加第二条平行导航。
2. 页面标题下只保留一句说明和结果数量；产品不变量说明放在辅助文字或可展开帮助中，不与主要内容竞争。
3. 桌面使用统一内容最大宽度；长上下文控制在可读行长内。手机 320/375/414px 不产生横向滚动。
4. 所有搜索、筛选、分页和展开控件提供可见标签、键盘焦点和至少 44px 的触摸命中区。信息不能只靠颜色表达。
5. 加载时保留查询和已有结果；错误状态靠近触发控件，并提供重试；无结果状态提供清除筛选、改变匹配方式或返回完整列表的动作。
6. 公开条目与用户私有条目在短语页显示范围标签。服务端继续按用户所有权和发布/版权状态过滤，客户端不自行推断可见性。

## 5. 短语页 `/read/phrases`

### 5.1 页面结构

```text
标题：短语
说明：表达的意思、语气和真实用法放在一起。

[搜索短语                                      ] [搜索]
[全部] [想复现] [已熟悉] [暂不学习] [未分类] [更多筛选]
共 N 个短语

┌ 表达卡 ┐  ┌ 表达卡 ┐  ┌ 表达卡 ┐
```

桌面使用三列卡片；中等宽度两列；手机单列。筛选项为表达、语用目的、语域、地区和 CEFR。意图筛选保持在首屏，其他筛选通过“更多筛选”渐进展开。

### 5.2 表达卡

卡片按以下顺序展示：

1. 西语表达、CEFR 和范围标签（公共 / 我的）。
2. 中文核心说明。
3. 语用目的，例如礼貌缓和、开启话题或表达不确定。
4. 自然变体和可替换槽位；没有变体时不显示空占位。
5. **默认显示 1 条代表例句**，高亮表达并显示来源标题和内容类型。代表例句没有可见来源时，卡片显示“暂无可见例句”，不能编造例句。
6. “查看更多真实例句（N）”按需展开最多 6 条 KWIC；每条可以跳回来源。
7. 复习意图控件：`已熟悉 / 想复现 / 暂不学习`，使用 `aria-pressed` 表示当前状态；旁边提供“在语料中查看全部用例”。

代表例句是阅读理解辅助，不是口语评分提示。意图更新失败时保留旧状态并显示可重试错误，不能假装成功。

### 5.3 空状态和加载

- 无筛选结果：显示“没有匹配的短语”、清除筛选动作和一条改变筛选的建议。
- 完全为空：说明短语来自已发布文章/媒体中的正式条目或用户自己的私有条目，并提供回到文章库的入口。
- 数据不可用：保留当前 URL 筛选条件，显示重试；不把服务故障写成“没有短语”。
- 首屏加载：使用与表达卡结构一致的 skeleton，避免整页只显示一个无语义 spinner。

## 6. 语料页 `/read/corpus`

### 6.1 查询区

默认查询参数写入 URL：

```text
/read/corpus?q=dar%20cuenta&match=phrase&documentKind=media&page=1
```

查询区包含：

- 带可见标签的搜索框“搜索词或短语”。
- 匹配方式：`连续短语`（多词默认）或 `包含全部词`。
- 来源筛选：`全部 / 文章 / 视频·播客`。
- “更多筛选”预留来源、地区、日期和词性；后端没有对应可靠字段时不展示空筛选。

多词默认使用连续短语匹配。当前实现把多词拆成 token 后做独立包含查询，不能直接满足这个承诺；必须先增加明确的 `match` 语义和测试，再把该选项作为默认 UI。

### 6.2 结果卡

每条结果使用单列阅读流，最大宽度约 760px：

1. 左右上下文和高亮关键词；上下文不足时保留原始边界，不补写句子。
2. 来源标题、文章/视频/播客类型和可用的来源、地区、日期、说话者信息。
3. 位置标签：文章显示段落，媒体显示 `mm:ss`，并提供“打开来源”动作。
4. 已知 `entryKind/entryId` 时提供“查看短语条目”或“查看词条”；原始查询没有对应正式条目时不显示伪链接。

分页继续使用有界分页和上一页/下一页控件，不使用无限滚动作为唯一访问方式。结果排序只使用服务端声明的稳定顺序，不把出现次数未经定义地标成“最常用”。

### 6.3 状态

- 未提交查询：给出示例查询和查询说明。
- 查询中：保留上一组结果，搜索按钮进入忙碌状态，旧请求不能覆盖新查询。
- 无结果：显示命中的词数/短语、清除筛选、切换匹配方式和返回短语页的动作。
- 查询失败：保留输入和筛选，显示局部错误和重试按钮。
- 文字考察：放在结果之后，以“用一道题检验理解”作为次级入口；提交失败或未完成不产生证据。

## 7. API、DTO 与实现边界

### LEX-001

- `PhraseItem` 增加可选 `representativeOccurrence` 投影，或提供等价的首条可见 KWIC；其余例句继续懒加载。
- 词句卡必须保留 `ContentDocumentRef` 和 `SourcePosition`，确保文章段落与媒体毫秒位置可恢复。
- 个人意图仍通过 `PUT /api/v1/lexicon/intents/:entryId` 幂等更新，不创建能力证据。

### LEX-002

- `corpusQuerySchema` 增加 `match: "phrase" | "all"`，默认 `phrase`；查询和分页状态由 URL 驱动。
- `CorpusItem` 对客户端公开 `sourceKind`、`entryKind`、`entryId` 和位置 DTO；客户端不得据此绕过服务端可见性检查。
- 连续短语匹配必须使用 token 边界、重音归一和顺序判断，不能使用会产生子串误命中的简单 `%token%` 组合。
- 文章和媒体来源跳转复用 `contentSourceHref`，不复制全文或隐藏字幕正文。

## 8. 验收条件

1. 375px 和 1440px 视口均能进入两个页面，导航只有一条，页面无横向溢出。
2. 短语卡首屏有 1 条真实代表例句；无例句时显示诚实空状态。
3. 多词短语默认连续匹配；词序分散的句子不会误命中 `match=phrase`。
4. 刷新、浏览器返回和复制 URL 后，搜索词、匹配方式、来源筛选和页码可恢复。
5. 文章结果跳到稳定段落，媒体结果跳到正确毫秒和片段；撤下或无权内容不可见。
6. 意图更新、展开例句、来源跳转和语料浏览均不写能力证据；文字考察只在服务端确认提交后写入适用词句能力。
7. 搜索加载、取消、错误、空结果、过期响应和重复点击均有明确行为。
8. 所有交互控件满足触摸尺寸、键盘焦点、读屏标签、深色模式和减少动效要求。

## 9. 暂不进入本轮

- 语料结果内嵌完整视频/音频播放器；第一版跳转到媒体学习器的准确片段。
- 未经审核的自动释义、自动翻译或自动生成例句。
- 以语料出现次数推导“最常用”排序或能力分数。
- 把用户选中的 surface text 自动晋升为公共短语。
