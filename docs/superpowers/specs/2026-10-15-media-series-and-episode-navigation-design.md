# 媒体系列、选集与播后同系列推荐设计

- 日期：2026-10-15
- 文档任务：`MEDIA-SERIES-000`；本轮仅交付设计与任务切片。
- 状态：2026-10-16 所有者以“实现整个需求”确认详细规格；按001–006逐项实施，完成情况以状态页为准。
- 用户补充：视频播放结束后，在下方展示当前系列的其他视频。
- 关联：[ADR-0018](../../adr/0018-media-series-directory.md)、[实施计划](../../plans/2026-10-15-media-series-implementation-plan.md)。
- 关系：补充 [2026-09-12 内容设计](2026-09-12-automated-content-supply-and-lexical-learning-redesign.md)，保持其学习入口、发布、隐私和证据不变量。

## 1. 问题与范围

当前 `MediaCard` 只有单集和 `sourceName`，没有正式系列关系；`media_versions` 的频道/feed 标识用于溯源。“换一批”目前按内容类型和来源名称轮换，不能区分同一频道的不同系列。以上是代码现状，不代表已逐条确认真实库存的系列归属。

本设计解决同系列内容的发现、排序、选集与播后继续选择。保留单集直接进入学习的路径，不改为强制选系列或课程任务。只做当前响应式 Web/PWA，复用 `media` 与所有者轻量内容工作流。

首批价值闭环为 `MEDIA-SERIES-001` 至 `004`；浏览多样性与采集建议分别作为 `005`、`006` 后续切片。暂不做自动连播、订阅、系列收藏、用户自建合集、跨媒体课程或个性化推荐。

## 2. 概念与归属

| 对象 | 定义 | 边界 |
| --- | --- | --- |
| 来源 | 发布频道、节目 feed 或已登记平台来源 | 继续保存原始来源与许可；不以展示名称作为唯一身份 |
| 系列 | 有明确共同节目/作品身份的一组单集 | 一个来源可发布多个系列；系列可有多个可核验来源 |
| 单集 | 当前稳定媒体 ID 对应的独立播放内容 | 字幕、内容版本、进度和证据仍绑定原单集 |
| 主题 | 旅行、生活等内容特征 | 标题或主题相似不能直接证明同系列 |

第一版每个单集最多归属一个已确认系列，也允许无归属。一个系列只含一种 `kind`（video 或 podcast），不混合视频/播客。未来的专题合集与多重归属另行设计。

播客 feed 可以提供节目归属证据，但迁移、转载、混合 feed 需要核实；频道 ID 不能直接当系列 ID。官方播放列表也可能只是精选合集，不能无条件转为系列。证据不足保持未归类。

## 3. 页面与交互

### 3.1 学习页卡片

- 默认仍展示真实可播放的单集卡片；封面和标题直接打开该集。
- 已确认归属显示系列名、可用时的真实季/集标签，以及独立的“查看系列”链接。链接不能嵌套在整卡链接内。
- 原来源信息继续保留，不能用系列名覆盖版权溯源。
- 无归属不展示占位系列、猜测集号或失效入口。

### 3.2 系列页与随时可用的选集

- 系列页建议路径 `/learn/series/[seriesKey]`，显示名称、简短介绍、类型、本站当前可见集数与单集列表。
- 只写“本站已收录 N 集”，不推断官方总集数、缺集或已完结。集数只统计当前已发布、清权且可播放条目。
- `ordered` 系列按确认的 `position` 升序；`episodic` 独立节目按发布日期降序，缺日期排后，再以稳定键打破平局。
- 每集展示标题、时长、难度和当前用户原有播放状态；不生成系列能力分数或额外完成记录。
- 播放页提供“选集”；桌面折叠面板、手机抽屉，当前集高亮。前后集语义按系列实际显示顺序，按钮标“上一集 / 下一集”，缺少方向时禁用。
- 选集有界分页，默认 20、最大 50；当前集即使不在首屏也能定位。列表排序不要求加载全部字幕或全部单集。
- 选集是用户主动入口，随时可用；播后推荐另见 3.3。

### 3.3 视频结束后的同系列推荐（明确需求）

- 仅当前视频播放器的有效 `ended` 事件触发；暂停、逐句自动暂停、seek/时间接近末尾、技术失败以及历史进度为 completed 都不触发。
- 在播放器所在主列的下方、字幕区域之外增加“当前系列的其他视频”，不盖住视频、不移除字幕、不强制滚动、不抢焦点。窄屏按自然阅读顺序出现在播放器下方，预留底部导航空间。
- 最多展示 6 条同系列、同为 video 且当前可见的卡片；排除当前稳定媒体 ID、其他系列、草稿、撤下、版权受限和失效资产。
- 有明确顺序时，先按 position 展示当前集之后的可见单集，再用之前的可见单集补足；无明确顺序时按发布日期降序。均用稳定键打破平局，不把未知集号描述成“下一集”。
- 第一版不依据用户观看记录重新排序或排除全部已看单集；卡片可复用原有播放位置。此处“推荐”仅指系列关系与固定排序。
- 点击才进入目标单集，沿用已有该集进度恢复逻辑；不自动播放、不倒计时、不循环回首集。
- 有结果时附“查看全部”系列入口。无系列或成功返回零条时不展示推荐区；读取失败显示局部重试，不冒充没有其他集，也不影响当前集重播与字幕。
- 请求期间显示紧凑加载态；20 秒截止，可取消。重复 ended 不发重复在途请求；成功结果在本次结束展示期间复用。失败允许重试。
- 当前视频开始重播或 seek 回内容区后隐藏推荐区并取消在途请求；下一次有效 ended 重新读取。切集、换版本、播放器实例重建和卸载清除旧状态，旧 generation 回调不得重新展示旧推荐。
- 展示推荐不依赖进度写入成功，也不新增 completed 写入。已有播放器结束进度语义不变；看完不产生能力证据。
- 播客第一版保留选集，不把视频播后区直接放进文本主体；播客结束推荐另行评估。

### 3.4 浏览多样性（后续切片）

仅改变“随便看看 / 换一批”的排序。先按稳定来源身份轮换，各来源内部优先轮换系列，同系列剩余项在后续轮次补回；无系列条目各自作为独立组。不能为满足系列上限丢弃合法内容或提前报告耗尽。

普通最近收录、最新发布、最近继续排序保持原语义。明确进入系列页/系列筛选时按其顺序展示，不应用分散。保留 seed、筛选、排除集合、稳定分页与历史恢复；系列关系 revision 变化也使旧浏览游标失效。

## 4. 数据与模块边界（拟实施）

`media` 拥有系列目录，不新增独立业务服务，不扩展旧 `content_packs`。

- `media_series`：稳定 seriesKey、名称、简介、kind、orderMode（ordered/episodic）、active/archived、正整数 revision、审计时间。
- `media_series_memberships`：mediaItemId、seriesId、可空 seasonNumber/episodeNumber/episodeLabel、排序 position、确认来源与证据引用、确认者和时间。mediaItemId 唯一；ordered 的 position 必须为正且在系列内唯一，允许空档，不代表缺集事实。episodic 不要求 position，季/集号未知时留空。
- `media_series_changes`：追加式变更审计，记录关联前后值、expectedRevision、操作者、原因和证据。首次导入、修正、解绑、调整顺序与撤下系列均可追溯；不存完整字幕、私密对话、密钥或签名播放 URL。
- 系列的名称/归属是可修订目录元数据，以独立 revision 与审计维护；不修改已发布 media version、内容哈希、字幕、历史审核、用户进度或 evidence。
- 内容版本变更后继续按稳定媒体 ID 找到系列；公开读取仍解析 currentVersion 并重验发布/清权/资产。系列 active 不授予单集播放权，系列 archived 隐藏系列入口而不自动撤下仍可用的单集。
- 创建/归属/排序由 application 定义事务与 CAS；串行化同一系列修改并处理媒体跨系列移动的竞争，不允许半导入或相同媒体同时占用两个系列。跨系列移动同时校验双方 revision。
- 普通用户只读当前可见系列投影，写入仅所有者服务端工作流；RLS 与服务端所有权检查同时执行。用户进度仍按账号隔离，不放入全局系列缓存。

`content-acquisition` 只能通过 `media` application 提交待确认归属建议，不直接写上述表。自动发现到建议为止，不因映射命中跳过现有内容审核与发布门禁。

## 5. 拟定协议

实施从内部领域接口与 fake 开始，随后同步 Zod、DTO、OpenAPI、JSON Schema 与稳定错误码；本轮没有新增实际 API。

- 现有 MediaCard 增加可空系列摘要：seriesKey/title、真实季集标签和 orderMode。新字段对旧客户端可忽略，客户端兼容旧响应缺字段；播放资产、字幕和数据库行类型不进入摘要。
- `GET /api/v1/media-series/:seriesKey`：已鉴权的系列简介、当前可见集数和 revision；不存在或不可见统一 404。
- `GET /api/v1/media-series/:seriesKey/episodes`：cursor、pageSize、可选 anchorMediaKey，返回有界 MediaCard 列表及当前集邻接位置；计数、顺序和权限一致。
- `GET /api/v1/media/:stableKey/series-recommendations`：最多 6 条、当前系列摘要及读取 revision；无系列返回成功空结果，当前媒体不可见为 404，读取失败为 503。
- 所有者 `PUT /api/v1/internal/content-workflow/media-series/:seriesKey`：显式创建/更新命令、幂等键、expectedRevision（创建为 0）、完整校验的有界成员变更；跨系列移动显式提供原系列与 revision。相同键不同输入拒绝，不隐式挪走其他系列成员。
- 上述端点均需鉴权；所有者写额外校验 allowlist。个人化响应 private/no-store。列表 cursor 绑定 series revision、排序及可见成员当前版本集合；变化返回稳定的 cursor-invalid 错误并支持重新读取，不静默跳页。
- 推荐、选集和系列简介采用窄查询，不读取字幕，也不阻塞原播放接口或首次播放器准备。点击推荐后播放端再次执行现有可见性与资产门禁。

错误码至少区分：查询无效、系列不可见、媒体不可见、revision 冲突、幂等冲突、归属冲突、游标失效与服务不可用；实施时沿用现有媒体错误映射而非重复创建同义码。

## 6. 已有内容与采集

先产出只读归属清单：稳定媒体 ID、来源标识、拟归属、顺序证据、未知项和冲突。优先库存最多的可核验节目/系列，不把历史盘点的来源分组直接当确认后的系列数量。

批量导入先完整校验，再事务写入；默认 dry-run，显式 apply 限定映射文件哈希与 expectedRevision。重复运行幂等，任一冲突不得部分生效。本轮不运行导入、数据库迁移、公开采集或收费供应商。

未来只从已有白名单允许获取的结构化元数据提出归属建议。新增展示文案必须注明来源；新增 AI 教学文案继续遵守独立双维审核，不因系列确认自动获得语言/教学审核资格。历史审核身份保持原值，新审核遵守当前 review-identity 定义。

## 7. 验收与恢复

1. 学习页仍直接展示单集；无系列媒体完全可用；来源信息和旧链接保持。
2. 卡片、系列页与选集能定位同一已确认系列，显示真实可见集数与顺序；未知集号诚实缺省。
3. 当前视频真实结束才出现下方同系列其他视频；最多 6 条、排除自己、不跨系列、不自动连播。
4. 暂停/逐句暂停/接近末尾不触发；失败可重试；切集、重播、换版本与旧回调不会串集或抢焦点。
5. 所有读取重验权限和 currentVersion；撤下内容不从选集、计数、邻接或推荐泄漏；用户 A 不看到用户 B 的进度。
6. 系列修改可审计、幂等、事务且 CAS；不变更内容版本、证据、画像、字幕或历史审核。
7. 桌面与 320/375/768/1440px 路径可用；选集抽屉有焦点恢复、Escape 和 44px 操作目标，不覆盖底部导航。
8. 按切片完成单元、契约、数据库/RLS、Playwright；跨模块/迁移与发布候选完成仓库全量门禁，既有失败单列。真实数据库与 iPhone Safari 未验时如实标注。

回退采用隐藏系列/推荐入口或撤销目录归属的追加审计变更，保留单集原播放路径。迁移只向前，不能删除证据、重写历史版本或手工改生产库恢复。
