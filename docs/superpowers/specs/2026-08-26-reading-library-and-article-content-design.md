# Sueño 阅读库与西语文章内容体系设计

- 日期：2026-08-26
- 状态：已获产品方向批准，待实施前审阅
- 关联设计：[Web UI 设计研究与页面方案](D:/workspace/docs/superpowers/specs/2026-08-26-web-ui-design-research-and-scheme.md)
- 关联产品规范：[西班牙语沉浸式口语学习平台设计](D:/workspace/docs/superpowers/specs/2026-08-20-spanish-speaking-learning-platform-design.md)
- 设计目标：为西语刊物、生活文章和工作文章提供可扩展的阅读库，并把阅读自然连接到可选的口语迁移，同时保护版权、学习评分和用户隐私。

## 1. 决策摘要

Sueño 增加一个名为“阅读”的一级产品表面，形成五项主导航：

```text
学习 · 阅读 · 探索 · 对话 · 我的
```

阅读不是探索页中的一个卡片，也不是把现有沉浸式内容包简单改名。它是一个独立的内容与阅读工作流：

1. 用户按主题、难度、来源和阅读时长发现文章。
2. 用户在专注阅读器中阅读西语原文，按需获得词语、段落和语音辅助。
3. 用户可以保存文章、短语、高亮和个人笔记。
4. 阅读行为只产生阅读活动，不直接更新 `mastery`、`confidence` 或口语证据。
5. 用户愿意开口时，可以从文章生成一个可选的自主口语迁移任务。

内容采用“编辑部 + 个人保存”的混合模式：

- Alpha 先以原创、授权、公共领域和合规开放许可内容为主，建立稳定的西语文章库。
- 数据模型从第一天支持大量文章、版本、段落、来源、审核和阅读状态。
- 用户保存 URL 作为次级能力，先保存来源和个人阅读状态；只有版权和技术条件允许时才保存规范化全文。
- RSS、Newsletter、浏览器扩展和任意网页导入属于后续增量，不在第一版伪装成已完成能力。

本设计不引入新微服务，不改变服务端评分、证据、画像、记忆权限和角色安全边界。

## 2. 研究范围与主要发现

### 2.1 语言学习产品

| 来源 | 观察 | 对 Sueño 的启发 |
| --- | --- | --- |
| [LingQ](https://www.lingq.com/en/learn-spanish-online/) | 大型内容库按 Books、Podcasts、News、Business、Technology、Science、Travel、Culture 分类；支持导入自己的内容、转写、音频、上下文词汇和 SRS | 文章库需要主题、难度、格式、音频和阅读状态，不应只是时间排序列表 |
| [Readlang](https://readlang.com/) | 阅读中点击词语或短语即可翻译；查询过的词自动进入复习列表；支持文章、书、视频和用户文本 | 辅助必须贴着正文发生；“保存短语”比单独做生词本更自然 |
| [Language Reactor](https://www.languagereactor.com/) | 代表双语字幕、词典、短语保存和逐句控制的沉浸辅助模式 | 译文、音频和词语解释应是局部工具，不应把用户带离文章 |
| [BBC Learning English](https://www.bbc.co.uk/learningenglish) | 以等级、主题、最新内容、播客、工作英语、新闻英语和技能组织内容 | Sueño 可以把生活、工作、新闻、文化等主题做成稳定分类，并保留“最新”和“适合今天”入口 |

### 2.2 英语阅读与内容管理产品

| 来源 | 观察 | 对 Sueño 的启发 |
| --- | --- | --- |
| [Readwise Reader](https://readwise.io/read) | 将 RSS、网页、Newsletter、PDF、EPUB、YouTube 转写和社交长文放入统一阅读库；高亮、搜索、标签、键盘阅读、朗读和 Daily Review 是核心能力 | “阅读库”应是持续工作流，而不是一次性文章详情页；阅读后要能回到高亮和短语 |
| [Omnivore](https://github.com/omnivore-app/omnivore) | 开源 read-it-later；正文抽取、保存位置、高亮、笔记、标签、搜索、离线、RSS、Newsletter 和 PWA 形成闭环 | 原网页和规范化阅读正文必须分离；文章抓取必须经过服务端解析、清洗和版权判断 |
| [wallabag](https://github.com/wallabag/wallabag) | 保存网页后抽取干净正文，去掉弹窗和干扰内容；支持自托管和多端生态 | 文章阅读体验不能依赖原站布局；需保存来源链接并提供回到原文的路径 |
| [Readest](https://github.com/readest/readest) | 全文搜索、标注、词典、翻译、TTS、阅读进度、主题和跨平台同步 | 阅读器应支持搜索、标注、TTS、主题、键盘和屏幕阅读器；不复制其 AGPL 代码 |
| [The Guardian](https://www.theguardian.com/international) | 精选、频道、主题、作者、时间和文章类型有明显层级 | 首页应有编辑精选和主题入口，避免无限信息流淹没学习目标 |
| [Medium](https://medium.com/) | 先以主题和故事吸引阅读，再逐步进入具体文章 | 文章卡片应先表达“为什么值得读”，再展示语言学习元数据 |

### 2.3 研究限制

- 上述观察来自公开页面、公开宣传材料和开源仓库文档；未假设登录后的付费功能一定存在于 Alpha。
- Readwise、LingQ 和 Readlang 的高级导入、订阅和 AI 能力不自动视为 Sueño 的授权或实施承诺。
- Omnivore、Readest、wallabag 的代码和资源仅用于原则研究；实际复用必须单独做许可证和授权审查。

## 3. 产品边界与不变量

### 3.1 文章阅读不等于口语能力证据

以下行为只产生阅读相关记录：

- 打开、阅读、完成文章。
- 点击词语、查看翻译、展开段落解释。
- 播放 TTS、改变速度、查看原文和译文。
- 保存短语、高亮、写个人笔记。

这些记录可以用于推荐和复习，但不能直接更新发音、语流、真实口头反应、`mastery` 或 `confidence`。

只有用户自主开口完成文章相关迁移任务时，才进入现有训练评估链路。打字回答可以证明理解、组织和语境准确性，但不能提高发音或语流能力。

### 3.2 文章与角色关系边界

- 文章可以成为 Lucía 对话的话题来源，但不能把用户读过文章中的个人信息自动写入关系记忆。
- 文章涉及现实地点、人物、活动或工作信息时，必须显示来源和时间；不确定的信息只能作为文章内容或一般建议呈现。
- AI 文章解释不能绕过来源校验、版权限制、记忆权限或角色事实检查。
- “和 Lucía 聊聊这篇文章”是一个可选对话入口，不应让 AI 伪装成文章作者或现实见证者。

### 3.3 Alpha 范围

本设计批准进入后续实施计划：

- 五项导航中的“阅读”。
- 平台策划的文章库。
- 文章列表、筛选、搜索、阅读进度和继续阅读。
- 词语解释、段落辅助、TTS、保存短语和个人高亮。
- 文章结束后的可选口语迁移。

本设计不提前实现：

- 任意网站全文抓取并保证成功。
- 浏览器扩展、RSS/Newsletter 自动订阅和大规模外部 feed 管理。
- 付费墙绕过、第三方文章全文再发布或未经许可的批量抓取。
- 独立搜索服务、独立内容微服务或离线音频媒体库。

## 4. 导航与信息架构

### 4.1 五项一级导航

| 导航 | 路由 | 核心职责 | 不负责 |
| --- | --- | --- | --- |
| 学习 | `/learn` | 唯一下一步、训练断点、口语闭环 | 大量文章浏览 |
| 阅读 | `/read` | 文章发现、阅读器、保存、标注、口语迁移 | 核心表达课程目录 |
| 探索 | `/explore` | 沟通目标、表达资料库、沉浸内容包 | 个人文章库 |
| 对话 | `/chat` | Lucía、角色联系人、私信和好友介绍 | 文章全文阅读 |
| 我的 | `/me` | 能力证据、活动、记忆、语音和数据控制 | 文章内容管理 |

移动端底部导航最多五项，桌面端侧栏按语义分组：

```text
开始：学习、阅读
发现：探索、对话
账户：我的
```

主题、语言和账号设置仍然属于“我的 → 偏好”，不在导航中增加孤立的工具按钮。

### 4.2 词语与复习的层级

词语和短语是跨页面的辅助对象，不设置为第六个一级导航。用户在文章中点击词语后可以查看解释并保存短语；探索页可按表达和语块浏览；学习首页只在存在真实复习队列时显示短语复习次级入口。若后续数据证明复习已形成稳定高频任务，再增加 `/review` 子路由，不直接挤占移动端底部导航。

### 4.3 阅读库路由

建议使用以下可深链路由：

| 路由 | 作用 |
| --- | --- |
| `/read` | 阅读首页和文章书架 |
| `/read/article/[articleId]` | 规范化文章阅读器 |
| `/read/saved` | 用户保存的文章和短语 |
| `/read/topic/[topicId]` | 主题文章列表 |
| `/read/search?q=` | 文章标题、摘要、段落和标签搜索 |
| `/read/article/[articleId]/speak` | 文章相关的可选口语迁移入口 |

路由只在后端存在真实数据和状态时开放。未实现的 RSS、导入或浏览器扩展不能通过空按钮占位。

## 5. 阅读首页设计

### 5.1 首屏层级

阅读首页不是内容后台，也不是无限瀑布流。首屏按以下顺序组织：

1. **继续阅读**：上次阅读的文章、段落位置和剩余预计时间。
2. **今日精选**：少量编辑精选，显示“为什么值得读”。
3. **按主题浏览**：生活、工作、文化、科技、旅行、新闻、观点等。
4. **按难度和时长筛选**：A2/B1、短文/中篇、5/10/20 分钟。
5. **我的保存**：收藏、阅读中、已读和个人短语。

主 CTA 根据状态变化：

- 有断点：继续阅读。
- 无断点：打开今日精选中的第一篇推荐。
- 无已发布内容：显示可解释空状态和管理员/内容阶段提示，不显示失效按钮。

### 5.2 文章卡片

文章卡片至少包含：

- 标题和一行摘要。
- 来源、作者、发布时间或更新时间。
- 主题标签。
- CEFR 难度或“难度待评估”状态。
- 预计阅读时间。
- 是否有音频、中文摘要、词语辅助。
- 阅读状态：未开始、阅读中、已读。
- 版权/来源标记，不把未审核内容混入正式精选。

文章卡片的“保存”“打开”“继续”必须是实际动作；“内容整理中”“等待审核”等状态使用非交互标签。

### 5.3 筛选与搜索

首版支持：

- 主题。
- CEFR 难度。
- 阅读时长。
- 内容形式：文章、访谈、短讯、工作场景、带音频。
- 阅读状态：未开始、阅读中、已读、已保存。

搜索支持标题、摘要、来源、作者、主题和已发布正文。搜索结果使用分页或游标分页，不能一次加载整个文章库。无结果状态应提供修改筛选或返回精选的实际入口。

## 6. 阅读器设计

### 6.1 阅读模式

默认打开纯西语阅读，不要求用户预先选择学习模式。辅助能力按需展开：

- **词语辅助**：点击词语或短语显示简短释义、词性、发音和保存入口。
- **段落辅助**：显示中文摘要或更简单的西语解释，明确这是辅助而非原文。
- **音频辅助**：全文、段落和句子级 TTS；支持速度调整和暂停。
- **阅读设置**：字号、行距、主题、窄栏/标准栏和高对比模式。

任何辅助都不应把用户强制跳转到另一个页面；词语弹层应支持键盘关闭、屏幕阅读器朗读和移动端底部抽屉。

### 6.2 正文版式

- 正文宽度控制在每行 65–75 个字符。
- 标题、来源、作者、时间和阅读时长在正文前清晰显示。
- 段落之间有稳定垂直节奏，不使用过度卡片化的“每段一个盒子”。
- 长文章显示阅读进度，但不把阅读进度伪装成能力进度。
- 文章图片必须有尺寸、替代文字、版权来源和懒加载策略。
- 外部原文链接始终可见，打开前说明会离开 Sueño。

### 6.3 高亮、保存和笔记

- 用户可选词语、短语或一段文字进行高亮。
- 高亮存储基于文章版本和稳定段落/字符范围，文章版本变化后不能错误定位。
- 保存短语属于用户私有阅读数据，默认不共享给任何角色。
- 笔记可以是中文或西语，不自动写入教学画像或关系记忆。
- 删除高亮、笔记和保存动作需要明确反馈；失败可以重试且不丢失当前阅读位置。

### 6.4 内容问答

后续可增加“解释这段”或“问问文章”能力，但必须满足：

- 只基于当前文章版本和明确引用的段落。
- 显示回答来源范围和生成状态。
- 无完整 `done` 的流不显示为成功。
- 不自动保存为长期记忆，不自动更新能力评分。
- 供应商失败只显示可恢复错误，不影响文章阅读和已保存内容。

## 7. 阅读到口语的桥接

### 7.1 触发时机

完成文章或阅读到足够段落后，可显示一张次级卡片：

> 读完了。要不要用西语说说你的看法？

用户可以跳过，不影响文章完成、阅读进度或收藏。

### 7.2 迁移任务类型

文章根据主题生成一个口语任务：

1. **摘要**：用 20–40 秒说明文章讲了什么。
2. **观点**：选择一个观点并说出是否同意。
3. **个人迁移**：联系自己的生活或工作经历。
4. **角色对话**：带着文章主题进入 Lucía 对话。

任务只提供语境和意图，不要求复述唯一参考句。用户自然替代表达可以完成交际任务。

### 7.3 证据边界

| 行为 | 可更新 | 不可更新 |
| --- | --- | --- |
| 阅读完成 | 阅读活动、推荐上下文 | 发音、语流、口头反应 |
| 词语查询 | 词汇复习候选 | 掌握度、可信度 |
| 打字摘要 | 语境理解、组织能力（若明确作为写作任务） | 发音、语流、真实口头反应 |
| 自主语音摘要 | 语境成功、自然度、可理解度等适用口语证据 | 低置信度或技术失败造成的负面证据 |

阅读模块不能直接写 `evidence_events`。口语迁移必须通过现有训练 application 和评估 provider 接口提交。

## 8. 内容来源、版权与审核

### 8.1 来源层级

优先级从高到低：

1. Sueño 原创文章、原创访谈和原创工作场景。
2. 明确授权、合作、公共领域或满足许可条件的开放内容。
3. 基于可靠来源自行撰写的西语事实摘要，附原文链接和来源说明。
4. 用户保存的外部 URL，仅保存必要元数据和个人阅读状态；是否保存正文取决于许可和解析结果。

禁止：

- 复制付费墙或受版权保护的完整文章。
- 仅做轻微改写后当作原创。
- 删除作者、来源、许可或署名信息。
- 把自动抓取或 AI 改写直接视为已审核内容。

### 8.2 审核状态

文章发布沿用版本化流程，并增加版权检查：

```text
draft
  → source-checked
  → language-reviewed
  → pedagogy-reviewed
  → rights-approved
  → published
  → retired
```

没有完整来源、许可、署名和审核信息的文章不能进入 `published`。已发布文章修改必须产生新版本，旧版本继续支持已有阅读记录。

### 8.3 文章内容字段

文章版本至少包含：

- 稳定文章 ID、版本号和内容哈希。
- 标题、摘要、正文段落和语言。
- 作者、来源、原文 URL、发布时间和抓取/整理时间。
- `sourceType`、`license`、`attribution`、`copyrightStatus`。
- CEFR 难度、主题、地区、语域和内容形式。
- 预计阅读时间、音频可用性、中文摘要可用性。
- 段落级词汇、短语、语法和相关沟通目标。
- 审核状态、审核人、审核时间和审核备注。

## 9. 数据与模块边界

### 9.1 模块职责

```text
content
  文章来源、文章版本、正文段落、版权、审核和发布

reading
  阅读进度、保存、收藏、高亮、笔记、词语查询和阅读活动

recommendation
  基于主题偏好、阅读状态、难度和最近活动提供文章建议

training / evidence
  只处理用户主动口语迁移产生的评估、证据和画像更新

conversation / memory
  只在完整对话轮完成且通过权限检查后处理角色对话和候选记忆
```

模块之间使用明确 DTO，不让数据库行类型扩散到 UI。阅读模块不能直接写其他模块拥有的表，也不能把阅读事件伪装成证据事件。

### 9.2 逻辑数据实体

第一版可在现有 PostgreSQL 和模块化单体中增加以下逻辑实体，具体迁移在实施计划阶段确定：

- `article_sources`：来源、作者、原文 URL、许可和版权状态。
- `article_items`：稳定文章身份、当前发布版本和主题索引。
- `article_versions`：正文、版本、哈希、审核和内容元数据。
- `article_segments`：段落、意群、词汇和句子级定位。
- `article_assets`：封面、正文图片、音频和来源信息。
- `user_reading_progress`：用户、文章版本、当前位置、状态和最后活动。
- `user_article_saves`：保存、收藏和用户私有状态。
- `user_article_highlights`：版本、段落范围、用户笔记和创建时间。
- `user_reading_events`：打开、阅读、查询、播放和完成等可重放活动。

文章库查询使用 PostgreSQL 过滤、排序和全文搜索作为 Alpha 起点；只有真实数据量和查询延迟证明需要时，才评估外部搜索服务。

### 9.3 存储和安全

- PostgreSQL 保存文章元数据、规范化正文、段落和用户阅读状态。
- Supabase Storage 保存获得许可的封面、图片和音频；对象 URL 使用短期签名。
- 用户私有高亮、笔记和保存记录受 RLS 与服务端所有权检查保护。
- 文章正文 HTML 必须服务端清洗，禁止脚本、内嵌追踪和未经允许的外部资源。
- 日志不能写入完整私密笔记、文章正文、访问令牌或长期签名 URL。
- 删除账号时按现有账号数据删除顺序处理用户阅读进度、保存、高亮和笔记；公共文章内容不因单个用户删除而删除。

## 10. 推荐与阅读状态

### 10.1 推荐输入

推荐器可以使用：

- 用户明确选择的主题和难度。
- 文章已读/未读/阅读中状态。
- 最近保存的主题和短语。
- 文章阅读完成时间和最近活动。
- 已验证的口语能力缺口，作为机会而非硬性考试要求。

阅读时长只能参与活动和排序解释，不能参与能力评分。推荐理由必须可解释，例如：

> 这篇文章和你最近保存的“工作沟通”短语有关，预计 6 分钟读完。

### 10.2 状态机

```text
unread → in-progress → completed
   │          │             │
   └────── saved ────────────┘
```

- `saved` 是独立的用户私有标记，可以与其他状态并存。
- 刷新、断网和多设备同步不能把 `completed` 回退为 `unread`。
- 文章版本升级后，旧版本阅读位置必须可解释地迁移或标记为“需要重新定位”。
- 阅读事件写入需要幂等键，重试不能重复计数或重复生成供应商成本。

## 11. Web 与 Flutter 体验边界

- Web 提供完整文章书架、搜索、阅读器、快捷键和深链。
- Flutter 提供同一内容语义、阅读进度、词语辅助和 TTS 入口，但使用 Dart/Flutter 自己的 UI。
- 两端共享文章 DTO、内容版本、错误码和 `contracts/fixtures`，不共享 React 组件或 Flutter Widget。
- Web/Flutter 客户端不能把本地阅读状态当作服务端能力事实。
- 内容加载、空状态、离线状态、文章版本过期和同步失败必须在两端分别有明确设计。

## 13. 测试与验收

### 13.1 内容与数据

- 未发布、未审核或版权字段不完整的文章不能通过公开查询返回。
- 文章版本重复导入幂等；同版本不同哈希被拒绝。
- 文章正文清洗会移除脚本、追踪和不允许的外部资源。
- 用户 A 不能读取或修改用户 B 的进度、高亮、笔记和保存。
- 文章版本升级不会破坏或静默覆盖历史阅读记录。
- 删除用户数据不删除公共文章，也不保留用户私有高亮和笔记。

### 13.2 阅读器组件

- 阅读、刷新、断网、恢复和多设备同步状态可恢复。
- 词语弹层支持关闭、键盘焦点和移动端底部抽屉。
- TTS 失败不产生负面能力证据，也不阻塞正文阅读。
- 高亮、保存和笔记失败显示明确错误并支持重试。
- 空文章库、无搜索结果、已退休文章和旧版本都有明确状态。

### 13.3 口语桥接

- 阅读完成只写阅读活动，不写 `evidence_events`。
- 打字迁移不更新发音、语流和真实口头反应。
- 自主语音迁移走现有 `attemptId`/`generationId` 和评估链路。
- 低置信度、静音、截断和技术失败不产生负面能力证据。
- 文章问答或角色对话异常断流不能写入完整关系记忆。

### 13.4 关键 Web/Flutter 路径

1. 阅读首页 → 打开精选 → 阅读到断点 → 刷新 → 恢复位置。
2. 文章 → 点击词语 → 保存短语 → 在保存页查看。
3. 文章 → 播放 TTS → 切换段落 → 继续阅读。
4. 文章 → 跳过口语桥接，不产生口语证据。
5. 文章 → 自主口语迁移 → 反馈 → 画像按适用技能更新。
6. 旧文章版本 → 显示重新定位或迁移提示，不静默丢失高亮。
7. 用户 A/B → 阅读数据隔离和删除确认。

## 14. 性能、隐私和版权风险

- 阅读首页使用分页/游标和懒加载，不能一次返回整库正文。
- 文章正文和图片声明尺寸，避免 CLS；非首屏资源懒加载。
- 文章正文使用服务端解析和清洗，客户端不直接执行外部 HTML。
- 普通阅读不默认调用高成本 LLM；词语解释和文章问答必须使用内部 provider 接口并记录模型版本、延迟和估算成本。
- 供应商调用失败不能改变阅读进度、文章发布状态或能力画像。
- 文章来源、许可、署名和审核状态在后台与公开阅读器中保持可追溯。
- 不抓取付费墙全文，不绕过登录或访问控制，不保存未经授权的长期副本。

## 15. 未在本设计中提前决定的事项

- 第一批具体文章来源和作者名单。
- RSS/Newsletter provider、浏览器扩展协议和外部 URL 抽取 provider。

- 是否允许用户上传本地文本或 EPUB；该能力需单独评估与隐私说明。
- 文章库达到何种规模后引入外部搜索服务。

这些事项不会阻塞 Alpha 文章库的 DTO、发布审核、阅读器和口语桥接设计。
