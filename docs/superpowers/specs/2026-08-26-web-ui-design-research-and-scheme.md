# Sueño Web UI 设计研究与页面方案

- 日期：2026-08-26
- 状态：已获产品方向批准，待实施前审阅
- 适用范围：Next.js Web/PWA 个人 Alpha
- 关联产品规范：`docs/superpowers/specs/2026-08-20-spanish-speaking-learning-platform-design.md`
- 关联架构规范：`docs/superpowers/specs/2026-08-20-multiplatform-client-architecture-design.md`
- 设计目标：重建 Web 信息层级、视觉语言和交互真实性，消除“看起来可以操作、实际没有结果”的控件。

## 1. 决策摘要

Sueño Web 采用“温暖编辑式对话工作台”（Warm Editorial Conversation Workspace）作为 Alpha 的统一视觉方向：

- 用暖米白、纸面表面、深墨色文字和低饱和赤陶色建立长期陪伴感。
- 用一张明确的“当前任务”主卡片承载首页默认主路径“继续学习”；必要的时长、模式或内容调整以低干扰、可跳过的方式提供。
- 用联系人、最近话题和语音/文字输入建立对话页，而不是把对话做成第二个课程仪表盘。
- 用“当前能做什么”和“证据是否足够可靠”展示进步，不用经验值、连胜或学习时长制造能力感。
- 所有可点击元素都必须有真实目的、可观察结果和失败恢复路径；未发布内容使用状态标签，不伪装成按钮。
- 桌面端使用侧栏，移动端使用五项底部导航；两端共享导航语义，不共享 UI 源码。

本决策不改变服务端评分、证据、画像、记忆权限和角色安全规则，也不提前实现支付、实时双向语音、开放角色商城或其他 Alpha 延后能力。

## 2. 研究范围与方法

### 2.1 研究对象

公开网站与仓库在 2026-08-25 进行只读检查：

1. [Duolingo](https://www.duolingo.com/)：公开中文首页、入口层级和课程导航。
2. [Babbel](https://www.babbel.com/)：公开首页、语言入口和真实交流叙事。
3. [Busuu](https://www.busuu.com/)：公开首页、短课、口语练习和社区定位。
4. [Tandem](https://tandem.net/)：公开中文首页、联系人和消息/语音交换叙事。
5. [Echo-Loop](https://github.com/echo-loop/Echo-Loop)：公开仓库首页与本仓库既有参考评审。
6. 当前本地 Web：`http://localhost:3000/`、`/learn`、`/explore`、`/chat`、`/me`、`/learn/practice` 的 DOM、可见按钮、链接和截图。
7. [LingQ](https://www.lingq.com/en/learn-spanish-online/)、[Readlang](https://readlang.com/)、[BBC Learning English](https://www.bbc.co.uk/learningenglish)、[Readwise Reader](https://readwise.io/read)、[Omnivore](https://github.com/omnivore-app/omnivore)、[wallabag](https://github.com/wallabag/wallabag)、[Readest](https://github.com/readest/readest)、[The Guardian](https://www.theguardian.com/international) 和 [Medium](https://medium.com/)：文章发现、阅读器、标注、搜索、来源与版权边界。

GitHub 的通用仓库搜索在调研时触发了 secondary rate limit，因此没有把搜索结果数量或排序作为证据；Echo-Loop 使用直接公开仓库页面和本仓库既有评审作为可靠来源。

### 2.2 研究原则

- 只提炼公开可观察的产品模式，不复制品牌、文案、独特插画或源码。
- 将“值得借鉴的体验原则”和“本产品明确不采用的模式”分开记录。
- 优先选择能服务产品不变量的模式，而不是视觉上最醒目的模式。
- 任何设计建议都必须能够映射到真实路由、真实状态或已批准的 Alpha 范围。

## 3. 研究结论

| 来源 | 可观察模式 | Sueño 采用 | Sueño 不采用 |
| --- | --- | --- | --- |
| Duolingo | 首页有单一开始入口，减少用户决策；进度反馈强 | 首页默认突出“继续学习”；继续入口始终指向稳定断点，可根据用户需要渐进式提供调整 | 连胜、宝石、经验值作为核心反馈 |
| Babbel | 用真实生活对话和“说得更有信心”组织产品叙事；工具分层 | 使用沟通目标、场景和可迁移表达组织探索页 | 首页先要求选择语言、时长或课程模式 |
| Busuu | 短课、真实场景、口语反馈和社区内容并列 | 将听说训练、静默内容和关系对话分成清晰入口 | 将 AI 角色描述成真人社区或真实线下资源 |
| Tandem | 联系人、头像、最近话题、文字/语音入口很明确 | 对话页以好友和话题为第一层级；输入区保持稳定 | 真实用户匹配、视频通话和开放社交网络 |
| Echo-Loop | 自动编排训练步骤、断点恢复、状态机、显式完成终态 | 单一下一动作、自然停止点、生成代际保护和流程优先测试 | 固定音频训练阶段、源码组织或评分语义 |

### 3.1 当前 Web 基线

本地页面检查得到以下结论：

- 现有四项主导航 `/learn`、`/explore`、`/chat`、`/me` 都能解析到页面；阅读库作为新增产品表面，需要独立路由和状态设计。
- 当前可见主页面的导航链接没有发现明显的无目标链接；问题主要是视觉层级、空状态与可操作状态的区分不足。
- `/learn` 的主卡片方向正确，但桌面端内容区偏窄，右侧留白过大。
- `/explore` 的集合结构清楚，但“内容整理中”需要更明确地表现为非交互状态。
- `/chat` 已经有 Lucía 入口，但学习入口和关系入口的权重还没有完全拉开。
- `/me` 的能力图、维度详情和表格重复感强，更接近诊断后台而非个人能力中心。
- 主题切换以孤立的 icon-only 控件出现在主导航；账号数据删除按钮位于进步页，容易被误认为普通设置操作。
- `/me` 在数据不足时能显示重试或空状态，但状态卡、按钮样式和数据可信度提示需要统一。

## 4. 产品不变量对 UI 的约束

以下规则约束 UI 设计。第 1 条是可通过可用性验证调整的首页策略；第 2–10 条是不可因为视觉改版而弱化的产品不变量：

1. 首页默认优先展示“继续学习”，不把时长、模式或内容类型选择作为进入前置条件；若可用性验证证明有价值，可提供不阻塞主路径的渐进式调整入口。
2. 听说是核心；读写和打字是静默环境下的延续，不能伪装成口语证据。
3. 用户完整表达前不得纠错或打断。
4. 评分以语境成功为先，不能要求匹配唯一参考句。
5. 低置信度转写和技术失败不能产生负面能力证据。
6. `mastery` 与 `confidence` 分开呈现；学习时长只用于活动热力图。
7. AI 好友首先自然回应；教学目标不能控制对话内容。
8. 私密关系记忆默认不向其他角色共享。
9. 角色不得把虚构房源、地点、线下约见或现实行动描述成真实存在。
10. 用户直接询问角色是否为 AI 时必须如实回答。

## 5. 视觉方向

### 5.1 风格定义

“温暖编辑式对话工作台”由四个关键词组成：

- **温暖**：暖米白底色、低饱和赤陶色、柔和表面，不使用高饱和儿童游戏配色。
- **编辑式**：标题、眉题、分隔线和留白建立阅读节奏；内容按沟通目标分组。
- **对话式**：角色头像、最近话题和语音/文字输入有明确连续性。
- **工作台**：训练状态、错误恢复和下一动作可观察，不用装饰性卡片遮盖状态。

设计不采用纯玻璃拟态、霓虹渐变、极端拟物、过度圆润的儿童化插画或大面积数据仪表盘。

### 5.2 颜色令牌

实现时使用语义变量，不在组件内散落原始颜色值。以下为第一版建议值，落地时必须通过实际字体、字号和主题组合进行对比度检查。

#### 浅色主题

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--ui-bg` | `#F6F1E8` | 页面背景 |
| `--ui-surface` | `#FFFDF8` | 卡片和表面 |
| `--ui-surface-raised` | `#FFFFFF` | 对话、弹层和高层级表面 |
| `--ui-ink` | `#1D2521` | 主文字 |
| `--ui-muted` | `#68736B` | 次要文字、解释和时间 |
| `--ui-border` | `#DED7CA` | 分隔线和边框 |
| `--ui-accent` | `#B85B45` | 主 CTA、关键状态 |
| `--ui-accent-strong` | `#984634` | hover、pressed 和高对比主 CTA |
| `--ui-accent-soft` | `#F3DED5` | 主色浅底、选中态 |
| `--ui-secondary` | `#56706B` | 辅助强调、语音和关系提示 |
| `--ui-success` | `#5E806D` | 成功、有效证据 |
| `--ui-warning` | `#B9843C` | 数据不足、需要注意 |
| `--ui-danger` | `#B74A42` | 删除、不可恢复操作 |
| `--ui-focus` | `#365CC8` | 键盘焦点环，不能只依赖主色 |

| `--ui-muted` | `#B8C0B8` |

错误、警告和删除操作还必须配合文字或图标，不得只用颜色传达含义。普通正文与表面组合需达到 WCAG AA 4.5:1，对大字和非文字控件分别检查对应阈值。

### 5.3 字体和文字层级

- 拉丁文字和品牌字：`Plus Jakarta Sans`。
- 中文界面：`Noto Sans SC`。
- 回退：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。
- 优先使用 `next/font` 或自托管字体，避免运行时请求字体造成不可见文字或布局跳动。

| 层级 | 桌面端 | 移动端 | 用途 |
| --- | --- | --- | --- |
| Display | 48/56px，700 | 32/38px，700 | 首页主任务标题 |
| H1 | 36/44px，700 | 28/36px，700 | 页面标题 |
| H2 | 24/32px，700 | 22/30px，700 | 区块标题 |
| Body | 16/26px，400 | 16/25px，400 | 正文和解释 |
| Label | 13/18px，600 | 13/18px，600 | 眉题、状态、按钮辅助文字 |
| Meta | 12/18px，500 | 12/18px，500 | 时间、来源、次要状态 |

正文宽度控制在每行约 60–75 个字符；长说明不得使用过窄的固定卡片，也不得让桌面端文本铺满全屏。

### 5.4 间距、圆角和层次

- 基础间距使用 4px/8px 节奏。
- 页面水平内边距：移动端 20px，平板 32px，桌面 40–56px。
- 主内容最大宽度：1120px。
- 侧栏宽度：224–240px。
- 卡片圆角：14px；控件圆角：10px；头像可使用圆形。
- 阴影只用于浮起的工作面和弹层，主页面卡片优先用边框与表面差异建立层次。
- 不通过阴影、颜色或圆角同时强调同一层级；每个层级选择一种主信号。

### 5.5 图标、动效和可访问性

- 图标统一使用 Lucide 或 Phosphor 的单一线性风格，默认 1.75–2px stroke。
- 装饰性图标使用 `aria-hidden="true"`；icon-only 控件必须有可访问名称。
- 交互目标最小 44×44px；控件之间至少 8px 间隔。
- hover、pressed、focus、disabled 必须有可观察区别；焦点环不能被移除。
- 动效只使用 opacity/transform，默认 160–240ms；退出动效比进入更短。
- `prefers-reduced-motion: reduce` 时关闭非必要位移和滚动揭示。
- 加载超过约 1 秒使用骨架或明确的处理中状态，不能留下空白区域。

## 6. 信息架构与导航

### 6.1 导航语义

| 导航项 | 路由 | 责任 | 不承载的内容 |
| --- | --- | --- | --- |
| 学习 | `/learn` | 唯一下一步、训练断点和最近能力 | 内容浏览、账号设置 |
| 阅读 | `/read` | 文章发现、阅读器、保存、标注和可选口语迁移 | 核心表达课程目录、直接能力评分 |
| 探索 | `/explore` | 沟通目标、表达资料库、已发布内容包 | 训练中的即时状态 |
| 对话 | `/chat` | Lucía、角色联系人、好友介绍和私信入口 | 八维能力统计 |
| 我的 | `/me` | 能力证据、活动、记忆、语音和数据控制 | 课程选择和对话列表 |

### 6.2 桌面端与移动端

- 桌面端：左侧品牌与五项导航，按“开始（学习、阅读）/发现（探索、对话）/账户（我的）”分组，内容区滚动；主题、语言和数据设置不放在导航中作为孤立 icon-only 按钮。
- 移动端：底部五项导航，固定栏预留安全区和内容底部 padding；“阅读”使用书页图标和文字，不能隐藏为更多菜单中的假入口。
- 375–767px：单列布局，主 CTA 固定在内容节奏中，不遮挡输入和键盘焦点。
- 768–1023px：单列或双列过渡布局，侧栏不强制出现。
- 1024–1439px：侧栏 + 1120px 内容工作区。
- 1440px 以上：内容宽度不继续无限扩大，使用留白和辅助信息平衡画面。

### 6.3 主题和账户入口

主题、界面语言和账户设置属于“我的 → 偏好设置”语义。Alpha 可以保留主题能力，但不再把它作为主导航中唯一的无文字操作。这样主导航只表达产品核心任务，减少孤立按钮。

## 7. 页面设计

### 7.1 学习首页 `/learn`

#### 目标

用户打开页面后不需要做模式决策，直接知道下一步。

#### 结构

1. 顶部问候：今天继续、简短状态和可选的进步入口。
2. 主任务卡：沟通目标、原因、当前微循环进度和默认主 CTA“继续学习”。
3. 最近获得的真实能力：显示能力描述和证据摘要，不显示虚假的总分。
4. 轻量提示：每句完成都会保存，随时停下不会丢失。

#### 行为

- 主 CTA 总是进入最近稳定断点，而不是重新选择内容。
- 没有可用训练时显示解释性空状态和恢复入口，不显示失效的“开始”按钮。
- “现在不方便说话”优先在训练工作台中出现；首页不默认展示模式选择器，但如果验证出明确需求，可在不阻塞“继续学习”的前提下提供可跳过的轻量入口。

### 7.2 训练页 `/learn/practice`

#### 结构

- 顶部：返回、当前沟通目标、`n / total` 进度。
- 情境区：人物、地点和交际任务；虚构信息必须明确属于角色世界。
- 输入区：播放、录音和打字 fallback；语音是主要动作。
- 提示区：意图 → 关键词/骨架 → 完整示范和自然替代表达，按级别展开。
- 反馈区：完整表达后才出现，默认只突出影响理解的关键问题。
- 底部动作区：每个状态只有一个下一步主动作。

#### 状态和唯一下一动作

| 状态 | 主动作 | 次级动作 | 禁止显示 |
| --- | --- | --- | --- |
| ready | 开始录音 | 现在不方便说话 | 提交、评分、完成 |
| recording | 停止录音 | 取消录音 | 纠错提示 |
| transcribing | 等待转写 | 取消并保留草稿 | 负面评分 |
| insufficient | 改用打字或重试 | 查看原因 | 下降的能力分数 |
| evaluating | 查看反馈（处理中） | 取消 | 旧代际结果 |
| feedback | 继续下一个表达 | 再听一次 | 同时出现多个主 CTA |
| error | 重试当前步骤 | 返回学习 | 假装已完成 |

录音、转写和评估均使用 `attemptId`/`generationId`，旧回调不得更新当前工作台。

### 7.3 探索页 `/explore`

#### 结构

- 页头：表达资料库、真实沟通目的说明。
- 沟通目标集合：开始交流、表达需要、维持对话、安静学习。
- 已发布内容包：仅展示审核通过、可导航的内容。
- 未发布内容：静态状态行，写明“内容整理中”，不使用卡片按钮样式。

#### 行为

- 集合行是链接，进入同一条训练路径并携带明确的 focus 参数。
- 内容包必须有版本和发布状态；未发布版本不能通过公开页面进入。
- 后续如果增加搜索，只有在有真实查询和结果状态后才显示输入框；本设计不预建假的搜索按钮。

### 7.4 阅读库 `/read`

#### 目标

让用户在不需要先做课程决策的情况下找到一篇真正能读的西语文章，并在下次打开时回到断点。

#### 结构

- 页头：阅读标题、搜索入口和“已保存”链接。
- 继续阅读：最近文章、段落位置、剩余预计时间和唯一主 CTA。
- 今日精选：少量编辑精选，卡片先说明“为什么值得读”，再展示难度、主题、来源和时长。
- 主题与筛选：生活、工作、文化、科技、旅行、新闻、观点；CEFR、阅读时长、内容形式和阅读状态。
- 明确的加载、空结果、无已发布内容、文章已退休和服务错误状态。

文章卡片的“打开”“继续”“保存”必须分别对应真实导航或状态变化；“整理中”“等待审核”等状态只显示为非交互标签。

### 7.5 文章阅读器 `/read/article/[articleId]`

- 正文使用语义化标题、段落和列表，宽度控制在每行约 65–75 个字符，来源、作者、日期和许可信息可追溯。
- 右侧（移动端底部抽屉）提供词语解释、中文辅助、TTS、速度、保存短语、高亮和笔记；辅助面板不替代正文阅读。
- 顶部显示阅读进度和返回书架；刷新、断网恢复和跨设备同步都不能丢失已确认的阅读位置。
- 文章末尾提供“用自己的话说说”入口，但明确标注为可选口语迁移；跳过它不会显示失败，也不会写入口语证据。
- 文章版本过期时显示重新定位/迁移提示，不静默覆盖高亮或进度。

### 7.6 对话页 `/chat`

#### 结构

- Lucía 置顶为主要好友。
- 每个角色卡显示头像、姓名、关系语义、最近话题和最近活动状态。
- 主 CTA 为“打开对话”；“先练一句”作为次级入口。
- 好友介绍请求独立成请求卡，接受和拒绝结果必须可观察。

#### 关系边界

- 角色位置、活动和线下行动不可被写成现实已验证事实。
- 角色是否为 AI 的说明在角色详情或直接问答中诚实呈现。
- 关系记忆只在完整聊天轮完成后提取，并显示其共享范围。

### 7.7 Lucía 对话页 `/chat/lucia`

- 顶部提供返回、角色身份和当前关系上下文。
- 中部是消息流，用户发送后立即显示自己的消息和处理状态。
- 底部输入区同时支持文字和语音，但不把语音按钮伪装成实时双向通话。
- 生成流必须收到显式 `done` 才进入完成状态。
- 用户取消可以保留已收到的自然部分，但不能写入完整长期记忆或口语证据。
- 学习摘要放在完整对话结束后，以可折叠区呈现，避免打断自然聊天。

### 7.8 我的 `/me`

#### 首屏

1. 能力总览：已验证维度、有效证据数量、口语覆盖范围。
2. 可信度提示：数据不足、代表性不足、待复核必须用文字说明。
3. 最近有效活动：仅用于活动热力图，不参与能力评分。
4. 下一项建议：链接到唯一下一动作，而不是显示多个训练入口。

#### 内容分组

- 当前能力和八维图。
- 维度详情和代表性证据。
- 有效学习热力图。
- 关系记忆与共享权限。
- 已保存语音和转写控制。
- 账号数据导出/删除和隐私说明。

能力图在没有足够证据时显示“数据不足”状态，不绘制误导性满量程雷达图。删除账号数据移至“数据与隐私”分组，并明确不可恢复、删除范围和清理失败可重试语义。

## 8. 交互真实性契约

### 8.1 元素类型规则

| 视觉元素 | 允许用途 | 验收规则 |
| --- | --- | --- |
| 主按钮 | 当前页面唯一主要动作 | 点击后有导航、状态变化或明确错误 |
| 次级按钮 | 可逆、低风险的辅助动作 | 不与主按钮争夺视觉权重 |
| 文本链接 | 页面导航或轻量切换 | 目标路由真实存在或有明确状态 |
| 状态标签 | 内容不可操作、未发布、处理中 | 不显示 pointer、hover 或箭头 |
| 禁用按钮 | 动作存在但前置条件不满足 | 同时显示原因，完成条件可理解 |
| icon-only | 高频且语义稳定的动作 | 可访问名称、可见焦点、至少 44px 命中区 |

### 8.2 不得出现的模式

- 没有 handler 的 `<button>`。
- 用灰色按钮表达“稍后可能有功能”，却没有解释。
- 异步失败后仍保留成功样式。
- 点击后没有 loading、成功或错误反馈。
- 同一页面同时出现两个以上视觉同权主 CTA。
- 把删除、撤销和普通进步操作使用相同颜色和同一层级。
- 通过颜色单独表达评分、数据可信度或错误。

### 8.3 状态卡统一模型

所有可加载模块使用统一状态模型：

```text
idle → loading → ready
                 ├→ empty
                 ├→ error (retryable)
                 └→ unavailable (not retryable)
```

- `loading`：骨架或带描述的处理中状态。
- `ready`：显示内容和可用动作。
- `empty`：说明为什么为空，以及下一步如何产生内容。
- `error`：显示稳定错误语义和真实重试动作。
- `unavailable`：说明当前 Alpha 限制，不显示可点击假入口。

## 9. 组件边界

第一阶段只建立能反复验证的组件，不预建通用后台框架：

- `AppShell`：响应式导航、内容宽度、安全区和跳过链接。
- `PrimaryAction`：每页唯一主 CTA，统一 loading/disabled/focus。
- `SecondaryAction`：低强调、可逆辅助动作。
- `StatusBadge`：非交互状态标签。
- `SurfaceState`：loading/empty/error/unavailable 统一呈现。
- `ProgressMeter`：表达微循环进度，不表达能力分数。
- `EvidenceCard`：展示能力证据、来源和可信度。
- `ConversationCard`：角色、最近话题和对话入口。
- `VoiceComposer`：录音、停止、打字 fallback、发送和取消状态。
- `PrivacyAction`：删除、撤销、共享权限等高风险动作的确认与反馈。

组件只渲染明确 DTO 和状态，不直接访问数据库，不承担评分或权限事实。

## 10. 响应式与可访问性验收

### 10.1 视口矩阵

必须检查：

- 320px：极窄移动端，没有横向滚动。
- 375px：主要手机基线。
- 414px：大手机和键盘出现时的输入区。
- 768px：平板/窄桌面过渡。
- 1024px：侧栏出现的桌面基线。
- 1440px：宽桌面留白和内容最大宽度。

### 10.2 可访问性

- 键盘 Tab 顺序与视觉顺序一致。
- 每个表单字段有可见 label 和错误描述。
- 动态状态使用合适的 `role="status"` 或 live region，不抢走用户焦点。
- 焦点不会被固定导航、底部 CTA 或键盘遮挡。
- 颜色不是唯一信息载体。
- 动态文字放大后不被固定高度卡片截断。
- 录音权限拒绝后始终提供可用的打字入口。
- 用户说话期间不出现纠错或负面反馈。

## 12. 测试与验收标准

### 12.1 设计系统验收

- 浅色和深色主题正文对比度符合 WCAG AA。
- 所有交互目标至少 44×44px，控件间距至少 8px。
- 没有 emoji 作为图标，没有不可见焦点，没有 hover-only 操作。
- `prefers-reduced-motion` 下页面仍可完成主流程。
- 320–1440px 没有横向滚动或固定栏遮挡内容。

### 12.2 路由与按钮验收

- 主导航五路由均可导航并保留当前项语义；阅读路由只返回已发布且版权字段完整的文章。
- 首页主 CTA 导向稳定训练断点。
- 未发布内容不出现可点击假按钮。
- 所有重试按钮都对应可重试操作。
- 删除、撤销和共享授权均有确认与结果反馈。
- 任何异常断流都不能显示为完成，也不能生成重复证据或记忆。

### 12.3 关键用户路径

1. 登录 → 学习首页 → 继续学习 → 录音 → 反馈 → 下一步。
2. 麦克风拒绝 → 打字 fallback → 标记口语待验证。
3. 训练中刷新 → 从稳定断点恢复。
4. 提示展开 → 证据强度按规则降低，不产生虚假能力提升。
5. Lucía 对话 → 流正常结束 → 关系记忆候选。
6. 流异常断开 → 重试 → 不重复生成记忆或证据。
7. 我的 → 查看能力证据 → 删除关系记忆或语音资料并确认结果。
8. 阅读首页 → 打开文章 → 点击词语/播放 TTS/保存短语 → 刷新恢复位置；跳过口语迁移不产生口语证据。

测试重点是状态、错误、恢复和权限，不用页面快照替代行为断言。

## 13. 性能与隐私约束

- 首页已登录内容尽量在 2 秒内可交互。
- 非关键图片使用 `next/image` 和延迟加载；声明尺寸避免布局跳动。
- 页面级 loading UI 使用 Next.js App Router 的 `loading.tsx` 或等价流式边界。
- 普通聊天不默认调用高成本发音评估。
- 普通录音评估完成后按策略删除；长期保存必须明确确认。
- 日志不记录原始音频、完整私密对话、令牌、API 密钥或长期签名 URL。
- UI 只显示经服务端校验的能力、证据、记忆共享范围和角色事实。
