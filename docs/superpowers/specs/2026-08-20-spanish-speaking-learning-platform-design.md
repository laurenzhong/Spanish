# 西班牙语沉浸式口语学习平台设计

- 日期：2026-08-20
- 状态：产品设计已批准；多平台架构已通过 ADR-0001 更新
- 首发形态：Next.js 完整 Web/PWA + Flutter iOS 客户端同步 Alpha
- 首个验证阶段：个人 Alpha
- 后续客户端：Android → Windows/macOS，具体发布顺序由真实需求决定

## 1. 产品摘要

本产品面向学过一定西班牙语语法和词汇、但在真实交流中听不懂、反应慢或无法自然开口的 A2–B1 学习者。首批用户以准备赴西班牙留学和生活的中文母语学习者为核心，但数据结构从一开始支持其他母语。

产品不以传统课程、词汇量或题目完成数作为中心，而是把用户已经认识的语言知识转化为能够在真实语境中快速调用的沟通能力。

产品由两个相互连接的核心体验组成：

1. **自适应沟通训练**：围绕打招呼、建立关系、表达需要、修复沟通等通用交际功能进行听说训练，并通过阅读和写作在不方便发声时继续学习。
2. **长期 AI 社交世界**：用户在马德里认识第一个主要好友 Lucía，并通过她自然认识其他长期角色。聊天表面上是持续发展的朋友关系，后台使用学习画像创造自然的练习机会并记录证据。

产品的核心承诺是：

> 帮助用户在真实西班牙语沟通中更快开口、表达得更自然，并清楚知道自己现在能做什么、下一步需要改善什么。

## 2. 目标与设计边界

### 2.1 产品目标

- 将被动语法和词汇知识激活为口语能力。
- 让用户在真实问题出现后更快开始回应。
- 提升发音清晰度、语流节奏、语境适切性和自由迁移能力。
- 通过可解释的学习画像证明真实进步，而不是只展示经验值或连续打卡。
- 同时支持 3–5 分钟碎片学习和 15–25 分钟完整训练，不要求用户提前选择时长。
- 在不方便发声的环境中，通过听力、阅读和打字输出维持沉浸学习。
- 通过长期、一致且具有共同记忆的 AI 角色提高自然交流意愿。

### 2.2 Alpha 暂缓的能力

以下能力属于完整产品愿景，但暂不进入个人 Alpha：

- 支付、订阅、调用额度和商业权益。
- 完整可视化内容管理后台。
- 实时双向语音通话。
- 大规模角色网络或角色商城。
- 复杂消息队列和独立微服务。
- Android、Windows、macOS 的完整发布打磨。
- 完整离线 ASR、复杂后台音频和商店商业能力。

Flutter iOS 客户端不再延后，从 Alpha 开始与 Web 同步开发。由于当前没有 Mac，iOS 编译、签名和真机音频验收在获得 Mac/Xcode 条件前不能视为完成。

### 2.3 下一份实施计划的边界

本设计描述完整产品方向，但下一份实施计划只覆盖个人 Alpha，并按“Web/Flutter 基础骨架、核心训练、Lucía 好友系统、扩展验证”四个可独立验收的子阶段执行。Android、Windows、macOS 发布、Beta 和商业化分别建立后续规格与实施计划，不能提前混入当前任务。

## 3. 目标用户与成功定义

### 3.1 首批目标用户

- 西班牙语约 A2–B1。
- 认识不少单词，也理解一定语法。
- 阅读能力明显强于听说能力。
- 造句困难，面对追问容易停顿或切回母语。
- 目标是赴西班牙学习、生活或长期交流。

### 3.2 产品结果层级

- 对外承诺：可以在真实场景中顺利开口。
- 学习结果：掌握跨场景可迁移的沟通能力。
- 核心指标：听到问题后能否快速开始自然回应。
- 基础保障：表达是否清楚到能被对方理解。
- 综合结果：听力、反应、发音、语流、准确性与迁移能力同步改善。

### 3.3 个人 Alpha 成功标准

个人 Alpha 不追求统计显著性，而是验证以下五件事：

1. **学习效果**：代表性问题的独立回答比例提高，平均开口反应时间下降。
2. **反馈可信**：系统能区分表达错误、自然替代表达、语音识别失败和证据不足。
3. **愿意继续交流**：用户不是为了完成任务才进入 Lucía 对话，并愿意自然持续多轮。
4. **系统稳定**：连续使用期间没有关键学习数据丢失、严重人物冲突或无法恢复的会话失败。
5. **跨端一致**：Web 与 Flutter 对同一用户、内容版本和学习证据展示一致，不因客户端不同产生重复证据或画像漂移。

建议的 Alpha 退出条件：

- 连续体验至少 3–4 周。
- 完成不少于 12 次核心训练。
- 完成不少于 8 次好友聊天。
- 至少出现两项可以通过再次测试复核的真实能力提升。
- 在没有连续打卡压力的情况下，用户仍愿意主动打开产品。

满足上述条件后，再邀请 20–100 名目标用户进入封闭 Beta。

## 4. 产品原则

### 4.1 开口优先

理解、阅读和语法解释最终都服务于真实表达。用户不能只通过浏览内容获得口语掌握状态。

### 4.2 语境优先

系统首先判断用户是否完成沟通目的、是否符合人物关系和上下文，而不是要求复现唯一预设句子。

### 4.3 证据优先

用户首先看到“现在已经可以做什么”，而不是经验值、题目数量或抽象总分。

### 4.4 低选择负担

首页默认突出“继续学习”，由系统提供最值得练习的默认建议；时长、训练模式或内容类型不应成为进入前置条件。若可用性验证表明用户需要调整，应通过渐进式、可跳过的入口提供，而不能让调整入口压过默认路径。

### 4.5 关系优先

AI 好友聊天的第一目标是自然回应和继续交流。教学目标只能影响话题机会，不能压过真实回应。

### 4.6 不打断表达

任何模式都不在用户说话过程中纠正。完整表达后再给反馈，默认只突出影响理解的关键问题和一个可选建议。

### 4.7 渐隐母语支架

初学新内容时可以使用母语翻译和解释，熟练后依次过渡到关键词、图片、人物与纯西语情境。

### 4.8 母语与本地化

- 用户资料保存所选母语和界面语言。
- 翻译、语法解释和常见错误提示按语言版本独立维护，不能只依赖运行时机器翻译。
- 语言无关的表达、标签、权值和学习证据只保存一份。
- 个人 Alpha 必须完成简体中文内容；本地化数据结构和语言选择能力同时建立。
- 英语及其他母语只有在对应翻译与教学说明通过审核后才向用户开放。

## 5. 信息架构与主要页面

### 5.1 底部导航

- **学习**：首页与自适应训练。
- **阅读**：西语刊物、生活和工作文章的发现、阅读、保存与可选口语迁移。
- **探索**：表达资料库、沟通能力与沉浸内容包；不承担个人文章书架。
- **对话**：Lucía 和后续长期角色的联系人与私信。
- **我的**：真实能力、八维画像、学习足迹和数据设置。

### 5.2 首页

首页默认不要求用户先选择学习时长、训练模式或内容类型，首屏优先显示：

- 当前最值得练习的沟通目标。
- 一句简短原因。
- “继续学习”主按钮。
- 最近获得的一项真实能力。
- 搜索现实中马上需要的表达作为次级入口。

可选的时长、模式或内容调整只能作为不阻塞进入的次级控件，并需要通过实际可用性验证后再决定是否显示。

### 5.3 自然停止点

- 每完成一个表达都保存有效进度。
- 每 3–5 个表达形成一个完整小循环。
- 用户随时退出，不显示“课程未完成”的惩罚性反馈。
- 有更多时间时，系统自然进入变式迁移和对话。

### 5.4 静默切换

用户无需提前选择“听说读写模式”。麦克风旁提供轻量入口“现在不方便说话”，切换后：

- 保留同一学习目标。
- 使用听力、阅读和打字输出继续训练。
- 不更新发音、语流或真实口头反应能力。
- 用户方便开口时安排少量口语验证。

## 6. 内容体系

### 6.1 第一层：通用沟通能力

课程最上层不是机场、酒店、学校等地点，而是跨场景通用的交际功能：

1. 开始交流：问候、称呼、自我介绍、主动搭话。
2. 建立关系：寻找共同点、寒暄、赞美和交朋友。
3. 表达自己：经历、兴趣、感受、偏好和观点。
4. 表达需要：请求、询问、求助、建议和协商。
5. 回应别人：同意、不同意、感谢、道歉、接受和拒绝。
6. 维持对话：追问、接话、换话题和表现兴趣。
7. 修复沟通：请求重复、确认理解、换种说法和争取思考时间。
8. 结束与延续：告别、邀请、交换联系方式和约下次见面。

### 6.2 第二层：人物关系与现实场景

每项沟通能力在不同对象和现实场景中练习，例如：

- 对朋友、同学、老师、陌生人和服务人员提出请求。
- 在校园、咖啡馆、租房、社交活动和日常生活中使用同一语块。
- 调整正式程度、语气和西班牙当地表达。

### 6.3 表达资料库与核心训练路径

现有 554 句话作为表达资料库保留，支持：

- 搜索和收藏。
- Web 或 Flutter 客户端朗读。
- 中文解释。
- 语法、搭配、逐词提示、意群和发音解析。

资料库不等同于正式课程。Alpha 从中筛选并重组 40–60 条表达，进入核心训练路径。

### 6.4 核心表达字段

每条正式训练表达至少包含：

- 原文与母语翻译。
- 沟通目的与微型学习目标。
- 目标语块和可替换槽位。
- CEFR 难度。
- 正式程度与人物关系。
- 地区标记：西班牙通用、拉美通用或特定地区。
- 使用频率：核心必会、常用或拓展。
- 语气效果与不适用情境。
- 语法、搭配、发音点、音节、重音和意群。
- 输入、输出、提示、变式和验证任务。
- 标签权值。
- 母语者审核状态和内容版本。

### 6.5 内容质量流程

- 核心表达、核心对话和语用说明必须由西班牙母语者审核。
- 语法、搭配和母语解释需要语言教学视角审核。
- AI 可以生成替换练习、对话变量和内容草稿。
- AI 生成内容必须经过规则校验、模型检查和人工抽样。
- 用户可以反馈不自然表达，进入内容复核队列。

## 7. 听说读写一体化语料系统

### 7.1 能力主次

- 听：强核心。
- 说：强核心。
- 读：静默环境下的沉浸输入与语法词汇支撑。
- 写：仅次于开口的输出方式，用于语境、语块、准确性和迁移证据。

四项能力共享同一个内容图谱，但分别更新不同技能证据。

### 7.2 沉浸式内容包

沉浸式内容包仍是训练闭环的核心语料单位；独立的“阅读”产品表面负责更大规模的文章库，两者通过主题、表达标签和可选口语迁移连接，但不共享同一套阅读进度。一个内容包包含：

- 120–350 词的故事、短文或对话。
- CEFR 难度与沟通主题。
- 完整音频和分段音频。
- 意群、目标语块、词汇和语法解析。
- 人物、情境和角色世界关联。
- 听力、口语、阅读和写作任务。
- 来源、作者、许可和版权状态。

### 7.3 四类活动

- **听**：隐藏文本听全文、分段听辨、语速变化、关键词捕捉和听写。
- **说**：跟读、影子训练、复述、回答问题和与角色讨论。
- **读**：渐隐翻译、点击朗读、语块高亮、语法解析和上下文猜词。
- **写**：给角色回复、改写句子、续写故事、摘要和观点表达。

### 7.4 阅读文章库

阅读库面向刊物、生活和工作场景，首批以原创、公共领域、开放许可或明确授权内容为主。文章保存来源、作者、原文链接、许可、署名、版权状态、版本、段落、CEFR 难度、主题、语域和预计阅读时间；未完成审核或版权字段的文章不得公开展示。

阅读器支持按需词语解释、中文辅助、TTS、保存短语、高亮、个人笔记、阅读进度和全文搜索。打开、阅读、词语查询、TTS、打字摘要等行为只产生阅读活动，不能直接更新 `evidence_events`、`mastery`、`confidence` 或发音/语流能力。用户主动完成文章后的自主口语任务时，才沿用现有训练、`attemptId`/`generationId` 和评估链路。

文章正文必须由服务端清洗并按版本发布；不抓取付费墙全文、不绕过访问控制、不把 AI 轻微改写当作原创。用户保存外部 URL 在版权和解析条件成熟前只保存来源与个人状态，不伪装成已导入全文。

### 7.5 与 AI 社交世界联动

原创故事可以发生在 Lucía 和其他角色的生活中。用户读过的故事随后能进入好友聊天，例如：

- 用户阅读 Lucía 在 Malasaña 遇到新朋友的故事。
- 写一条消息询问后续。
- 方便开口后进行复述。
- Lucía 在真实聊天中继续谈论这件事。

### 7.6 语料来源与版权政策

允许的来源：

- 原创或 AI 辅助、经人工审核的故事。
- 公共领域作品。
- 符合许可条件的 Creative Commons 内容。
- 通过合作、授权 API 或许可协议获得的媒体内容。
- 在适用范围内使用的必要短引文，并保留作者、来源和原文链接。
- 基于可靠来源自行撰写的事实摘要。

默认禁止：

- 抓取并重新发布付费墙文章。
- 未经授权复制完整受版权保护的外刊内容。
- 将模型改写视为自动获得版权。

正式公开上线前，媒体内容流程需要专业法律审查。

### 7.7 Alpha 内容量

在 40–60 条核心口语表达之外，Alpha 增加 8–12 个原创或开放许可的沉浸式内容包。

## 8. 统一学习闭环

每个微型学习目标使用同一骨架，并根据用户熟练度缩短或展开：

1. 情境输入。
2. 理解表达、语块、语气和意群。
3. 自主语音或打字输出。
4. 需要时使用三级渐进提示。
5. 更换人物、信息和条件进行变式迁移。
6. 进入结构化但有变化的对话。
7. 记录学习证据并决定下一步。

### 8.1 自适应入口

- 高熟练度标签：先给情境，要求直接输出。
- 中等熟练度：先给意图和关键词。
- 低熟练度或全新内容：先输入、解析和跟读。

### 8.2 三级提示

1. 意图提示。
2. 关键词或句型骨架。
3. 完整示范和不同语气变体。

系统记录用户使用到哪一级提示，并据此调整证据强度。

### 8.3 自由表达规则

- 学习阶段重点建立目标语块。
- 迁移和对话阶段接受所有自然、符合上下文的表达。
- 用户未使用目标语块但完成交际任务时，场景和自由表达能力可以提高，目标语块熟练度不直接提高。

### 8.4 反馈层级

默认反馈顺序：

1. 对方是否可以理解。
2. 是否完成交际目的。
3. 一个最关键的错误或自然度建议。
4. 可选的详细发音、语法、搭配与逐词分析。

严格纠音仍然等用户完整表达后再给反馈，每次最多突出 1–2 个关键问题。

## 9. 内容图谱、标签与权值

### 9.1 内容关系

内容按以下关系组织：

> 沟通能力组 → 微型学习目标 → 核心表达 → 变体与情境 → 验证任务

同一表达可以服务多个场景，同一沟通目的也可以由多个表达完成。

### 9.2 主要标签类型

- 沟通能力。
- 交际任务。
- 场景与人物关系。
- 目标语块和固定搭配。
- 语法点。
- 发音点。
- 正式程度和语气。
- 地区。
- CEFR 难度。
- 迁移类型。

表达与标签是多对多关系，每条关系带权值。

### 9.3 学习证据事件

一次用户输出至少记录：

- 用户、任务、内容和会话标识。
- 输出方式：语音、打字、跟读、选择或仅阅读。
- 是否使用提示及提示级别。
- 回应开始时间和总时长。
- 转写文本与识别置信度。
- 语境成功、自然度、准确性和可理解度。
- 发音、重音、语流和停顿数据（适用时）。
- 任务难度、评测可信度和供应商信息。
- 关联标签与标签权值。

### 9.4 加权更新

Alpha 使用可解释的有界更新，而不是不断累加总分：

> 证据强度 = 语境表现 × 独立程度 × 输出方式可靠度 × 任务难度 × 评测可信度

> 技能更新 = 内容标签权值 × 证据强度 ×（本次观察值 − 当前熟练度）

重复同一句、同一答案和短时间重复练习的边际证据快速降低，防止刷分。

### 9.5 不同输出方式的证据范围

| 输出方式 | 可以更新 | 不可以更新 |
|---|---|---|
| 自主开口 | 语境、语块、准确性、反应、发音、语流、迁移 | 无 |
| 自主打字 | 语境、语块、准确性、组织和迁移 | 发音、语流、真实口头反应 |
| 提示后输出 | 对应能力的较弱证据 | 不能视为完全独立调用 |
| 查看答案后跟读 | 模仿发音与初步记忆 | 不能证明自主表达 |
| 选择或仅查看 | 识别和理解 | 不能证明输出能力 |

## 10. 用户画像与掌握状态

### 10.1 八维口语能力

1. 听辨理解。
2. 即时反应。
3. 发音清晰。
4. 语流节奏。
5. 表达准确。
6. 语块调用。
7. 交际策略。
8. 迁移表达。

词汇量和语法知识不单独成为主轴，系统衡量的是它们能否在真实交流中被调用。

### 10.2 熟练度与可信度

每个用户技能状态至少包含：

- `mastery`：当前熟练度。
- `confidence`：系统对结论的可信度。
- `last_verified_at`：最近高质量独立验证时间。
- `evidence_count`：有效证据数量。
- `oral_coverage`：口语证据覆盖。

用户没有练习时不自动降低熟练度，但可信度逐渐降低并标记“需要验证”。

### 10.3 场景或能力状态

- 未开始。
- 学习中。
- 可以应对。
- 需要验证。

“可以应对”必须同时满足：

- 核心交际任务全部达到最低标准。
- 加权熟练度达到门槛。
- 没有影响交流的关键短板。
- 通过至少一个陌生变体或随机追问。
- 具有足够口语证据；只有打字证据时必须标明口语待验证。

### 10.4 抽样复核

复核不要求重做整个场景。系统抽取：

- 核心交际任务。
- 权值最高的技能点。
- 历史薄弱点。
- 长期缺少证据的能力。
- 一个陌生变体。

失败只影响相关节点，不直接否定整个场景。

## 11. 进步展示与留存

### 11.1 信息层级

进步页首先展示：

1. 新获得的真实能力。
2. 代表性表现证据。
3. 当前最值得改善的问题。
4. 场景与沟通能力状态。
5. 八维能力图。
6. 学习热力图。

### 11.2 八维能力图

- 实色：当前能力。
- 淡色或虚线：四周前能力。
- 数据不足：显示“数据积累中”，不绘制虚假精确结果。
- 点击某条轴：查看评分依据和代表性表现。

### 11.3 学习热力图

- 使用 Codeforces/GitHub 式小方块。
- 颜色深度表示当天有效学习时长。
- 点击某天查看练习场景、独立表达次数和新获得能力。
- 学习时长不参与能力分数。
- 不将连续打卡作为核心价值或惩罚机制。

## 12. AI 社交世界

### 12.1 核心概念

AI 对话不是题目界面的聊天皮肤，而是一张逐渐生长的长期关系网络。

第一个主要好友负责：

- 主动找话题和维持交流。
- 记住用户的兴趣、计划、心情和过去话题。
- 推荐本地美食、活动和地点。
- 根据用户自然透露的兴趣或需求介绍新好友。
- 在不破坏聊天的前提下创造学习机会。

### 12.2 主要好友 Lucía

个人 Alpha 暂定角色：

- 姓名：Lucía Martín。
- 年龄：24 岁。
- 城市：在马德里长大并生活。
- 专业：数字传播与新媒体硕士。
- 性格：主动、好奇、善于接话，但不会永远热情或无条件赞同。
- 社交功能：本地向导、主要朋友和其他角色的连接点。

人物设定使用版本化“人物圣经”。家庭、童年、语言、旅行和关系等背景可以持续补充，例如母亲为意大利人，但新增事实必须先通过冲突检查。角色已经向某位用户透露的事实不能无故改写。

### 12.3 城市策略

- 长期产品按城市建立不同的主要好友和本地角色网络。
- 同一角色不能根据不同用户随意改写长期居住城市。
- 个人 Alpha 固定使用马德里。

### 12.4 好友介绍机制

新角色不放入角色商城。Lucía 根据真实聊天自然提出介绍，例如：

> “我有个朋友 Nico 周末经常骑行，你们应该聊得来。要不要我把他介绍给你？”

用户同意后，新角色才进入联系人列表，并长期积累独立关系记忆。

Alpha 包含：

- Lucía。
- 一个兴趣好友，例如骑行或徒步伙伴。
- 一个根据实际使用需要确定的生活关系角色。

### 12.5 聊天界面

- 采用接近常用社交私信的结构，但不直接复制具体产品视觉。
- 显示头像、名字、状态和消息气泡。
- 默认语音输入，键盘为次级入口。
- 角色文字和语音消息自然混合。
- 地址、复杂信息和表达示范优先保留文字。
- 聊天页面不显示题号、目标句型、即时分数或课程进度。
- 语言反馈由用户主动打开“今天聊得怎么样”后查看。

### 12.6 个性化

用户可以提供 MBTI、星座、兴趣和当前心情，用于调整：

- 角色主动程度。
- 话题偏好。
- 幽默感和表达长度。
- 情绪回应方式。

这些信息不参与语言能力评分，也不能作为刻板推断用户人格的依据。

### 12.7 角色身份说明

- 首次进入时以极简方式说明这是由 AI 驱动的虚拟角色世界。
- 后续聊天中不反复强调 AI，保持沉浸。
- 用户直接询问时必须如实回答。
- 角色可以自然回答虚构设定中的年龄、专业、住所和经历。
- 角色不能把虚构房源、线下约见或现实行动描述成真正存在。

## 13. 角色记忆与信息边界

### 13.1 四类记忆

1. **人物固定事实**：角色的全局人物圣经。
2. **单独关系记忆**：只属于用户与某个角色的共同经历。
3. **用户可共享资料**：城市、兴趣和语言等，按许可用于介绍好友。
4. **教学画像**：只供推荐和评分，不作为角色之间谈论用户的社交信息。

### 13.2 共享原则

- 抱怨房东等私密内容默认只属于当前关系。
- 新好友只收到用户同意分享的必要背景。
- 系统区分“人物设定中存在”和“已经向当前用户透露”。
- 记忆冲突时暂停写入并进入复核，不用新的虚构信息掩盖矛盾。

## 14. 语音与 AI 处理

### 14.1 语音消息链路

1. Web 浏览器或 Flutter 客户端录制音频。
2. 使用短期签名权限上传临时存储。
3. 云端语音转写返回文本、词级时间和置信度。
4. 语境评估判断是否完成当前交流任务。
5. 角色规划器生成自然回复、追问或推荐。
6. 根据内容选择文字或语音输出。
7. 按需更新学习证据。
8. 普通原始录音删除。

个人 Alpha 采用说完后上传处理，不做实时双向语音通话。

### 14.2 发音评测

- 正式训练、严格纠音或抽样验证时调用。
- 普通好友闲聊不逐条进行高成本严格评分。
- 发音分析可以异步完成，不能阻塞聊天回复。

### 14.3 角色回复来源

角色回复规划器综合：

- 人物圣经。
- 当前角色与用户的关系记忆。
- 当前会话上下文和情绪信号。
- 后台教学画像。
- 经过验证的真实地点与活动信息。

系统先决定“朋友此刻为什么回复、想把话题带向哪里”，再生成符合角色的西班牙语。

### 14.4 供应商抽象

语音转写、发音评测、大语言模型、语音合成和地点数据全部通过服务端适配器接入，业务模块只使用统一内部接口。

具体供应商在实施计划中根据以下条件评估：

- `es-ES` 支持质量。
- 单词级时间、发音和韵律能力。
- 延迟和流式能力。
- 按量成本。
- 数据保留与地区合规选项。
- SDK 稳定性和替换成本。

## 15. 隐私、安全与可靠性

### 15.1 录音策略

- 普通练习录音在评测完成后删除。
- 长期保存转写文本、评分维度、提示依赖、回应时间和技能证据。
- 系统可以建议保留有代表性的里程碑录音，但必须由用户确认。
- 用户可以播放、下载或删除自己保存的录音。
- 使用匿名录音改进模型需要单独、明确的同意。

### 15.2 真实与虚构边界

- 人物故事允许虚构。
- 餐厅、活动、交通、房源和营业信息必须来自可验证来源。
- 信息无法验证时，角色只给一般建议或说明稍后再查。
- 不允许模型补齐地址、营业时间或真实房源。

### 15.3 错误降级

| 问题 | 内部处理 | 用户体验 |
|---|---|---|
| 麦克风无权限 | 不录音，不产生发音证据 | 切换键盘并说明如何恢复权限 |
| 转写置信度低 | 不判错，不写负面证据 | 角色自然请求再说一次 |
| AI 或语音服务失败 | 重试一次后降级 | 保留草稿，可继续打字或使用审核内容 |
| 地点信息无法验证 | 禁止补齐事实 | 只给一般建议或稍后查询 |
| 记忆冲突 | 暂停写入并复核 | 避免强行确认矛盾事实 |
| 处理延迟较高 | 聊天优先、分析异步 | 显示自然处理状态，不冻结界面 |

技术问题不能产生错误的用户能力扣分。

## 16. 技术架构

### 16.1 总体方案

采用单仓库、两条客户端代码线和一个远程模块化单体：Next.js/React 承载完整 Web 产品，Flutter/Dart 承载 iOS 并作为未来 Android、Windows、macOS 的共同客户端基础；Next.js Route Handlers 和服务端领域模块向两端提供版本化 API，不在 Alpha 提前拆微服务。

详细边界见 [Web 与 Flutter 多平台架构设计](2026-08-20-multiplatform-client-architecture-design.md) 和 [ADR-0001](../../adr/0001-nextjs-web-flutter-clients.md)。

### 16.2 技术栈

- **Next.js + React + TypeScript**：完整 Web/PWA、服务端接口和流式 AI 回复。
- **Tailwind CSS**：响应式基础样式；品牌和聊天体验使用自定义组件。
- **Flutter + Dart**：iOS 客户端，以及后续 Android、Windows、macOS 共同客户端代码线。
- **Supabase PostgreSQL**：内容图谱、证据事件、画像、角色和关系记忆。
- **Supabase Auth**：账号与会话。
- **Supabase Storage**：临时音频和用户确认的里程碑录音。
- **Drizzle ORM**：服务端类型安全查询和数据库迁移。
- **Zod**：API 和内容导入校验。
- **OpenAPI/JSON Schema + JSON fixtures**：TypeScript/Dart 数据协议和状态语义一致性。
- **CSV/JSON 内容源**：Alpha 内容维护与批量导入。
- **Vercel**：Next.js 托管和预览环境。

### 16.3 服务端领域模块

- 内容模块。
- 训练引擎。
- 证据评分模块。
- 用户画像模块。
- 推荐模块。
- 角色引擎。
- 记忆模块。
- 语音/AI/地点供应商网关。

模块共享代码仓库和数据库，但通过明确接口通信，不能越过边界直接修改其他领域状态。

### 16.4 客户端职责

- 展示与交互。
- Web 浏览器录音/TTS 与 Flutter 平台录音/TTS。
- 当前页面和未发送草稿的短期状态。
- 权限请求和降级入口。
- 按同一训练协议执行即时 UI 编排，并通过共同 fixtures 验证语义一致。

API 密钥、评分、记忆、角色规划和供应商调用全部在服务端。

Web 与 Flutter 不共享 UI 源码。Flutter 优先使用成熟插件；只有插件不能可靠覆盖 iOS 能力时才增加小型 Swift Platform Channel。当前没有 Mac，因此 iOS 编译、签名和真机验收需要后续 Mac/Xcode 环境。

### 16.5 数据访问与安全

- API 和供应商密钥只存在服务端。
- 用户数据使用 Supabase 行级权限隔离。
- 音频使用短期签名上传权限，并限制类型和大小。
- 记录用户、会话和供应商级调用次数、延迟和成本。
- 普通日志不写入原始私密对话或录音。

## 18. 测试策略

### 18.1 内容校验

- 必填字段。
- 标签引用。
- 权值范围与总和。
- 重复表达。
- 地区、语域和审核状态。
- 来源与版权状态。

### 18.2 评分单元测试

- 同一输入产生确定结果。
- 打字不能提高发音和语流。
- 低置信度转写不能扣分。
- 自然替代表达不判失败。
- 重复同一句不能无限刷分。
- 可信度下降不自动降低熟练度。

### 18.3 供应商契约测试

使用固定音频、文本和地点样本，确保不同供应商适配器返回统一内部格式。

### 18.4 端到端测试

手机视口覆盖：

- 初次诊断。
- 继续学习。
- 语音输出。
- 打字降级。
- 三级提示。
- 反馈与画像更新。
- Lucía 私信。
- 好友介绍。
- 阅读内容包与后续口语验证。
- 麦克风权限和服务失败。

### 18.5 角色质量评测

- 人物事实是否冲突。
- 是否出现明显教学腔。
- 是否忽视用户情绪而强推学习目标。
- 是否无关跳题。
- 是否泄漏其他关系的私密记忆。
- 是否编造真实地点、房源或线下行为。
- 是否能够自然持续多轮对话。

### 18.6 人工 Alpha 验证

由用户持续记录：

- 是否愿意聊下去。
- 哪些反馈不可信。
- 哪些任务显得死板。
- 哪些表达后来能够自然说出。
- 哪些视觉或交互产生负担。

## 21. 视觉设计研究

当前线框只确认信息层级和交互方向，不代表最终视觉风格。高保真 UI 前必须进行结构化竞品研究：

- 多邻国等语言学习产品：首页减负、动效、反馈和进度表达。
- 头部口语与 AI 陪练产品：语音入口、角色表现和对话持续性。
- 社交聊天产品：私信、语音气泡、联系人和好友介绍。

研究输出：

- 可借鉴的设计原则。
- 应避免的模式。
- 2–3 套原创视觉方向。
- 手机端交互原型。
