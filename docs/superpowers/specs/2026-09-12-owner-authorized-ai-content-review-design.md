# 个人产品阶段的所有者授权 AI 内容审核设计

日期：2026-09-12  
状态：待产品所有者书面确认后实施  
当前任务：`ALPHA-033`

## 1. 背景

项目已经从准备面向更广泛用户的 Alpha，收敛为首先服务项目所有者本人的个人学习产品。现有内容规则仍要求核心表达由西班牙语母语者审核、中文说明由具备教学视角的人审核，因此 `alpha.core@1` 和 `alpha.scenario-practice@1` 的正式表达与三个基础场景只能保持草稿，成为 `ALPHA-033` 的最后发布门禁。

产品所有者于 2026-09-12 明确决定：在项目仅供本人使用的产品阶段，所有正式内容由 Codex 负责审核，不再等待外部母语者或中文教学审核者。本设计把这项授权转化为可审计的内容治理规则，同时避免把 AI 审核描述为真人、母语者或教学专家签字。

## 2. 决定

个人产品阶段采用“所有者授权的双维度 AI 审核”：

- Codex 独立完成西班牙语语言维度审核。
- Codex 独立完成中文教学维度审核。
- 两个维度均通过、所有修改完成且自动校验通过后，内容才可以进入 `published`。
- 审核记录统一使用 `codex-ai-owner-authorized-review`，并在备注中记录产品所有者授权、审核模型身份、日期、范围和结论。
- 任何文档、界面、日志或交接都不得把该记录称为真人、母语者或教学专家签字。

该决定只适用于项目所有者本人使用的产品阶段。产品开始邀请、允许或面向其他真实用户使用前，必须新增 ADR 重新决定是否恢复外部母语与教学复核；不能仅沿用本授权扩大分发范围。

## 3. 方案选择

### 3.1 采用方案：复用现有状态机，明确审核维度

继续使用：

```text
draft → language-reviewed → pedagogy-reviewed → published → retired
```

其中 `language-reviewed` 和 `pedagogy-reviewed` 表示已经完成的审核维度，不再暗示审核者一定是人类。审核者身份由 review 记录表达。

优点：

- 不修改数据库枚举、DTO、API 或生产筛选逻辑。
- 继续保留先语言、后教学、再发布的明确门禁。
- 审核者身份和授权方式可由记录准确追踪。

### 3.2 未采用：新增 `ai-reviewed` 状态

该方案语义直观，但会要求修改数据库约束、内容 Schema、导入器、公共 DTO、测试和所有状态消费者；同时会把语言与教学两个审核维度压缩成一个状态。当前个人范围不足以支持这类迁移成本。

### 3.3 未采用：无审核轨迹直接发布

直接把草稿改成 `published` 无法证明审核范围、修订原因或责任主体，也会削弱未来重审能力，因此拒绝采用。

## 4. 适用范围

### 4.1 长期治理范围

在个人产品阶段，新增长期正式内容都遵循本设计，由 Codex 完成并记录两个审核维度。以下规则不因审核主体变化而放宽：

- 内容版本不可静默覆盖。
- 来源、许可和署名必须完整。
- AI 生成内容仍先进入 `draft`，不能生成后自动发布。
- 安全、角色身份、隐私和能力评分不变量继续由代码与审核共同保护。
- 结构或事务校验失败时不得部分导入。

### 4.2 `ALPHA-033` 本次实施范围

本次只审核：

- `alpha.core@1` 中的 11 条核心表达。
- `alpha.scenario-practice@1` 中的 15 条核心表达。
- `alpha.scenario-practice@1` 中的 3 个基础场景。

本次不重新审核：

- `alpha.core@1` 的阅读文章和旧场景。
- `readlang-public-v1` 文章。
- 本地 glossary。
- Lucía 人物圣经、关系记忆或对话回复。
- 私人 AI 生成的文章、场景或阅读选区。

这些内容以后按各自任务和既有来源、安全规则处理，不混入 `ALPHA-033`。

## 5. 审核标准

### 5.1 西班牙语语言维度

每条表达至少审核：

- 西语正文的语法正确性和自然度。
- es-ES 或 general 地区标签是否准确。
- 正式度、关系类型和语气效果是否匹配。
- 变体是否真正自然且与主表达存在有用差异。
- 交际意图是否允许自然替代表达完成，不绑定唯一参考句。
- 发音信息中的重音、音节、连读和音素描述是否准确。

每个场景至少审核：

- 开场、条件变化和角色回复是否自然。
- 服务关系、语域与任务难度是否一致。
- 场景变化是否给用户创造表达机会，而不是中途纠错或控制对话。
- 虚构地点、房源、价格、行政要求和现实行动是否始终被标为练习设定。

### 5.2 中文教学维度

每条表达至少审核：

- 中文翻译是否准确、自然且不过度缩窄语义。
- 交际意图、语法和语用说明是否适合中文母语学习者。
- 发音提示是否足够准确，不使用会误导音节或重音的简写。
- `avoidWhen` 是否描述真实使用限制，而不是混入系统评分规则。
- 性别、礼貌层级、地区差异和容易误用处是否显式说明。

每个场景至少审核：

- 三级提示是否从意图逐步过渡到表达支架，而非一开始暴露答案。
- 成功标准是否以交际任务完成为先。
- 条件变化、迁移任务和 CEFR 难度是否适合。
- 打字路径不会被当作发音、语流或真实口头反应证据。

## 6. 审核结论与阻塞级别

每个对象的每个维度使用以下结论：

- `approve`：当前候选满足该维度要求。
- `revise`：必须修改后重新审核。
- `reject`：不适合进入正式内容。

发现以下任一问题时不得发布：

- 西语语法错误、明显不自然或地区/语域误标。
- 中文错译、误导性的语法或发音说明。
- 会污染评分证据的任务或提示。
- 角色安全、虚构现实边界或隐私风险。
- 稳定 ID、版本、引用、来源或 Schema 不一致。

纯风格偏好可以记录为非阻塞备注，但必须说明为什么不影响正确性、自然度、教学效果或安全。

## 7. 版本与审核记录

### 7.1 版本策略

`alpha.core@1` 和 `alpha.scenario-practice@1` 保留为历史候选。正式审核发现需要修改的内容不在原版本上静默覆盖；实施时创建版本化后继 bundle，并对发生语义或教学字段变化的实体提升版本。

实施前必须检查数据库是否已导入 v1、是否存在学习断点、收藏或证据引用，再确定未修改实体是否复用 v1 或整体提升版本。无论选择哪种粒度，都必须满足：

- 旧引用仍可解析。
- 新发布内容指向明确版本。
- 已有学习证据继续绑定实际使用版本。
- 同一稳定 ID 和版本不能以不同内容哈希重复导入。

### 7.2 审核记录

每个正式对象至少保留两条可区分的审核记录：

- 语言维度：locale `es-ES`，reviewer reference `codex-ai-owner-authorized-review`。
- 教学维度：locale `zh-CN`，reviewer reference `codex-ai-owner-authorized-review`。

备注至少包含：

- “AI 审核，不代表真人或母语者签字”。
- 产品所有者于 2026-09-12 授权个人产品阶段使用。
- 审核对象稳定 ID 与版本。
- 发现的问题、修改摘要和最终结论。
- 审核时间。

原有 `codex-ai-temporary-review` 记录不改写成正式人工记录；可以保留为历史，也可以通过新增记录明确其已被本次所有者授权审核取代。

## 8. `ALPHA-033` 已知重点

正式审核必须至少处理以下预审问题，但不能只检查这些项目：

- `rental.se-permiten@1` 发音详情中的 `se permits` 拼写错误。
- `restaurant.tomare-eso@1` 在餐厅语境中的口语自然度。
- `campus.vengo-para@1` 中 `completar mi matrícula` 的西班牙高校行政语境。
- `campus.puedo-enviarlo@1` 中 `correo electrónico` / `email` 的语域差异。
- `rental.otra-hora@1` 在看房沟通中的动作与时间表达是否明确。
- `repair.podria-hablar-mas-despacio@1` 的 `avoidWhen` 混入系统评分规则。
- `navigate.creo-que-estoy-perdido@1` 的性别适配。
- 多条中文发音提示是否错误切分重音或音节。

审核不得因为该列表有限而推定其他字段正确。

## 9. 工作流与失败处理

1. 从权威 JSON 和 Schema 生成待审核清单。
2. Codex 完成语言维度审核，记录逐项结论和修改建议。
3. 对所有 `revise` 项创建版本化修订，并重新执行语言审核。
4. Codex 完成中文教学维度审核，记录逐项结论和修改建议。
5. 对所有 `revise` 项创建版本化修订，并重新执行受影响的两个维度审核。
6. 两个维度均通过后，更新 review 记录和内容状态。
7. 完整执行内容、类型、单元、契约、浏览器和构建门禁。
8. 所有检查通过后才执行事务导入；导入失败时不部分发布。
9. 使用真实账号确认 Explore、学习入口、断点和复盘读取的是预期版本。
10. 更新 `PROJECT_STATUS.md`，记录审核报告、内容 commit、导入结果和已知限制。

任何阶段出现无法确定的语言事实时，Codex 应继续查证权威语言资料或保持内容为 `draft`，不能以所有者授权替代正确性证据。收费 provider、真实数据库写入或其他有独立授权门槛的操作仍遵守原有规则。
