## 2026-10-13 当前范围（VOCAB-AUDIO-001）

产品本人明确选择单词统一使用浏览器西语 TTS；本节取代下方历史原声优先切片、媒体请求/裁剪及降级验收。手动朗读和已实现的点词自动发音均只传显示词本身，在点击处理器里同步发起 es-ES TTS。准备时显示“合成音 · 准备中…”且可停止；start 后显示“合成音”，成功结束复位；不支持/超时/合成失败在词卡旁给可重试错误。沿用浏览器西语声音偏好及有界回退。

2026-10-20 所有者修订：点击词卡「朗读单词」后不再显示“合成音 · 准备中…”/“合成音”状态行；加载、播放与停止只由按钮的停止标签、`aria-busy` 与 `aria-pressed` 表达，失败仍在词卡内显示可重试提示。本节其余音源、取消、互斥与不写证据的边界不变。

## 2026-10-12 历史设计与实施记录

## 1. 目标与边界

**目标**：让 `/read/vocabulary` 的每一个词都能听到发音，并且**优先听到真实母语语流**——词旁例子的原始音频片段，而不是合成音。

**边界（本设计不做）**：

- 不接入任何付费 TTS 供应商，不抓取第三方音频（理由与权利链见关联调研 §6）。
- 不做跟读、录音、发音评分；不写任何能力证据（§7）。
- 不做「点词即读」（LR 的 `speakWordOnClick` 默认开）：与我们的悬停词典抢同一次点击，且手机没有悬停。见 §3.1。
- 不改媒体播放页的播放器行为，不放宽媒体模块的可见性与发布门禁。

## 2. 事实基础（本次实测）

| 事实 | 数值 | 来源 |
|---|---|---|
| 词架词形总数 / 已发布语料中出现的 | 7,892 / 6,296 | 只读实测（本次与既有 `VOCAB-SHELF-001` 记录一致） |
| 例句来自**媒体**的词 / 其中仍有词级时间轴 | 5,383 / **5,309** | 只读 SQL 聚合（本次） |
| 例句来自文章（无音频）的词 | 913 | 同上（6,296 − 5,383） |
| **例句里逐词元匹配不到词架词形**的词 | **1,022 / 6,296 = 16.2%** | 只读实测 `.tmp-vocab-audio-form-probe.ts` |
| 例句里只作为「子串」命中的词 | 13 | 同上 |
| 例句中位长度 | 227 字符 | 只读 SQL（本次） |
| 例句**带截断省略号**的 | 6 条（反向证明 `clip` 在物化路径上不是补 `…` 而是取整段） | 同上 |
| 例句短于 40 字符 | 669 条 | 同上 |
| `media_segments` 总段数 / 有 `words` 时间轴 | 99,285 / 69,586 | 同上 |

三条直接决定设计的结论：

1. **原声覆盖是有限的、可以诚实报数的**：5,309 个词能拿到原声，其余 2,583 个词（1,596 个语料里根本没有 + 913 个来自文章 + 13 个子串边界）只能合成音。这个数字必须写进界面文案的依据，而不是假装全都能播原声。
2. **匹配必须走「折叠重音后的 token 相等」，不能走字符串包含**：实测例句里 `escuadrón`/`héroe`/`fotografía` 与词架词形 `escuadron`/`heroe`/`fotografia` 是同一 token 的不同写法（词架 key 本就是折叠重音的），而 13 条子串命中里混着「词架词形是另一个词的一部分」这种情况——用 `includes` 会把别人的音频播成这个词的发音。
3. **例句不能当句子读**：中位 227 字符、存在整段无句号的窗口、669 条短于 40 字符。所以「朗读例句」在本次设计里**只播原声片段**（有精确时间轴），**不做**合成音读整段（那会读出一段小作文）。合成音只读**词本身**。

## 3. 设计决定

### 3.1 入口：一个朗读按钮，两种形态

| 形态 | 位置 | 行为 |
|---|---|---|
| 悬停/聚焦弹层 | 卡片内，与两个标记按钮**同一个盒子**（不得引入新的死区，见 `VOCAB-HOVER-002`） | 朗读按钮 |
| 词详情卡 | 头部的「朗读」按钮（替换现在的「朗读单词」） | 同一个行为 |

- **不新增自动播放**：悬停只出释义，出声必须是一次显式点击。理由是它与我们现有的交互分工一致（悬停=看，点击=选），且避免用户扫过整页时被连续朗读。
- 触屏等价路径已存在：点词开卡片 → 点朗读。不新增长按手势（长按在 iOS 上会触发文本选择）。
- 词架仍然**只有 5 个常驻动画元素**的结构不变：按钮在浮层里，不在 7,892 个词块里（`VOCAB-JANK-001` 的结构不能被破坏）。

### 3.2 音源与降级链（四级，每一级都必须有可观察状态）

```text
点击朗读
  ├─ ① 文档里有该词的原声片段（折叠重音 token 命中 + 通过 wordTimingsForPlayback 校验）
  │      → 播 [词起始 − PRE_ROLL, 词结束 + POST_ROLL]，并显示「原声 · 来源标题」
  ├─ ② 命中但时间轴不合法 / 媒体资产不可用 / 已过期
  │      → 降级到 ③，并显示「原声不可用」
  ├─ ③ 没有原声（无例句 / 例句来自文章 / 词形匹配不到 / 词形匹配到多处且不唯一）
  │      → 浏览器 TTS 读这个词，显示「合成音」标记
  └─ ④ 浏览器不支持语音合成
         → 明确文案（沿用既有 `textToSpeechErrorMessage` 的措辞），按钮回到可点状态
```

| 参数 | 值 | 理由 |
|---|---|---|
| `PRE_ROLL_MS` | 120 | 起音辅音（`/s/`、`/f/`）在 VAD 边界上常被切掉 |
| `POST_ROLL_MS` | 250 | 留出收尾与重音回落，避免听起来像被掐断 |
| 片段过短保护 | 若 `词结束 − 词起始 < 60 ms`，改用整段句子时间轴（避免只播 40 ms 的爆音） | 时间轴本身来自 provider，短窗口是数据问题而不是播放问题 |
| 合成音语速 | 默认 `0.88`（沿用现状）；**慢速档 0.78**，一个开关控制全部朗读 | 现状 `rate` 散在各处（`0.88` / 阅读器设置项），本次收敛为词架自己的一个档位 |

**不做**「原声优先 / 只用合成音」的用户偏好开关：默认已经是原声优先，而如果原声有问题，正确的修法是修片段，不是给用户一个把好音频关掉的开关。**待定（不阻塞）**：若原声出现明显失真（例如 ASR 错误导致时间轴偏移），再加这个开关，届时需要单独决定。

### 3.3 取原声的路径（服务端解析，客户端只拿到一个片段引用）

- 客户端调 `POST /api/v1/read/word-audio`（`word` + `exampleText`，见 §3.4）。
- 服务端在 `lexicon-corpus` application 层解析：把 `exampleText` 映射回它来自的**已发布媒体版本**，取该段的 `words`，用媒体模块既有的 `wordTimingsForPlayback()` 校验（它已规定：时间轴与 `sourceText` 不一致时**失败关闭**，绝不用估算时间）。匹配规则是**在合并音后的 token 上相等**，且命中必须唯一；多处命中且时间不同 → 视为「无原声」（宁可合成音，也不猜）。
- 播放地址：复用媒体模块既有的 `getMediaPlayback(repository, stableKey, userId)`——它同时给出**已发布/清权/可用的播放资产 URL** 与已批准分段。**词句模块不自己拼 URL，也不放宽媒体门禁。**
- 响应只包含：`{ outcome: "clip" | "synthetic", clip: { url, expiresAt, startMs, stopAtMs, segmentStartMs, segmentEndMs, sourceTitle, stableKey } | null, reason }`。**不返回整条媒体的分段列表**：词架是 7,892 个词的页面，不能因为一个词的点击把一份序列化后的播放载荷（实测 0.42 MB）塞给浏览器。

### 3.4 数据：例句的来源身份必须落库

现状：`lexicon_form_frequencies` 只有 `(word, occurrence_count, example_title, example_text)`，物化之后**无法知道这条例子来自哪条媒体、哪一版、哪一段**。

- 新增迁移（`0044`）给该表加 4 列：`example_document_kind`（`media` | `article`）、`example_document_stable_key`、`example_document_version`、`example_segment_index`；`refresh-frequency-forms.ts` 的同一个聚合里带出（`min(array[...])` 的排序键必须一并改为包含这些列，否则「同一条例子」这个等价性会漂移——两个路径的等价性由既有测试锁定）。文章来源写 `article` 并允许 stable key/version 为空（文章音频不在本次范围）。
- **不新增第 5 列「例句里的词形」**：实测 83.6% 的例子逐 token 含该词，缺的都是重音差异；真正缺的是 16.2% 的语义缺口，多存一列也救不回来。
- 解析时**必须校验 `exampleText` 确实等于该版本该段落的 `sourceText`**：物化行可能是 36 小时陈旧窗口之前的版本，版本对不上就按「无原声」处理（`reason: "stale_reference"`），不能播一段已经不代表这句话的音频。

### 3.5 播放器：一个元素，显式生命周期

- 词架里**只有一个 `HTMLAudioElement`**（`useRef` + 单个实例），任何时刻只有一路声音；切词、离开、`Escape`、页面隐藏、卸载都停止它。这是对 LR `#llnClipPlayer` 的借鉴，但它那条「`stopAllPlayback()` 连视频一起暂停」的规则**不带进媒体页**。
- **不新建 object URL**（播放源是签名 https URL，由媒体资产层管理有效期），所以 `VOCAB-SHELF-001` 的「零 scroll 监听、零几何读取」不变：播放不读布局。
- 停止用 `requestAnimationFrame` 检查 `currentTime >= stopAtMs`（`timeupdate` 的 250 ms 粒度会切掉收尾），到点 `pause()`；`ended` 也要处理（片段可能就在媒体结尾）。
- **iOS Safari 的硬约束**：`audio.play()` 必须在用户手势的同步调用栈里。因此解析请求与 `play()` 的顺序必须是「先 `fetch` 解析 → 手势已经过去，用 `play()` 的 Promise 结果决定要不要提示」，而不是「先 await 再 play」。取数期间按钮显示「正在取原声…」；超过 400 ms 才显示文案，避免闪一下。
- 媒体横幅（视频/播客页）不受影响：词架不调用任何全局停止。

### 3.6 状态、错误、空态

| 状态 | 界面 |
|---|---|
| 取数中 | 按钮显示进度态，**不**改变卡片尺寸（避免卡片跳动把指针甩出去） |
| 播放中 | 按钮变为「停止」，`aria-pressed="true"` |
| 原声播放中 | 卡片里显示 `原声 · <来源标题>` |
| 合成音 | 卡片里显示 `合成音`（**不得**写成「母语者发音」或「标准发音」：那是我们的合成音，不是真人） |
| 无原声（常见） | 不逐词提示（16% 的词都如此，会变成噪声）；按钮本身就是合成音，标记已说明 |
| 原声不可用（取数失败/过期） | 当前单词侧栏通过 `role="status"` 显示「合成音」，不再弹整页降级提示；用户仍可停止后再次朗读重试（2026-10-13 产品本人要求精简提示，`VOCAB-UI-001`） |
| 浏览器不支持合成 | 沿用既有文案「当前浏览器不支持朗读，单词仍可正常学习。」 |
| 取数失败 | 降级成功时侧栏标记「合成音」；合成音也失败时在同一侧栏显示可恢复错误，不占用词表顶部 |

### 3.7 慢速开关

- 位置：词架控件区（与搜索同一行），`aria-pressed` 表示当前状态，无 JS 时默认正常语速仍然可用。
- 存储：`sueno:vocabulary-audio:v1:<scope>`（与标记同一套 scope 约定），只影响本机。
- 生效范围：**只影响词架**（浏览器 TTS 语速）。原声片段**不做变速**（`playbackRate` 会改变音质与音高，而原声的教学价值就在于真实语速；LR 的 `0.8` 是它自己的取舍，我们不抄）。

## 4. 模块边界与接口

| 层 | 新增/修改 | 约束 |
|---|---|---|
| `lexicon-corpus/domain` | `findWordClip(segment, word)`：纯函数，输入一段（含 `sourceText`/`words`）+ 词形，输出 `{ startMs, stopAtMs } | null` | 无 IO、无 React；匹配规则与失败关闭都在这里，可穷举测试 |
| `lexicon-corpus/application` | `resolve-word-audio.ts`：查来源 → 调 `media` 的 `getMediaPlayback` → 校验 → 返回 DTO | 只读；不写任何表；不产生证据 |
| `app/api/v1/read/word-audio/route.ts` | POST，Zod 校验 `word`(≤40) / `exampleText`(≤400) | 鉴权后返回；不暴露媒体目录；不记录完整文本到日志（只记长度与 outcome） |
| `lexicon-corpus/repositories` | `lexicon_form_frequencies` 四列 + 查询投影 | 与物化刷新同一 SQL 片段（`corpus-form-frequency.ts`），不得出现第二份可见性谓词 |
| `lexicon-corpus/ui` | `vocabulary-shelf.tsx`（按钮 + 播放器 + notice）、`vocabulary-shelf-controls.tsx`（慢速开关） | 7,892 个词块保持纯 HTML，不新增 per-word 组件 |
| `media` | **不改代码**，只被调用 | 若发现 `getMediaPlayback` 的返回对词架过重（一次性读 500 段），在 media 侧单独提任务，不在本设计里顺手改 |
| 契约 | `contracts/schemas/v1/word-audio-response.schema.json` + OpenAPI 条目 | 稳定错误码；`outcome` 只用 `clip` / `synthetic` |

## 5. 验证要求

1. **单元（domain）**：折叠重音命中；子串不算命中；一词多段且时间不同 → `null`；`words` 与 `sourceText` 不一致 → `null`（复用 `wordTimingsForPlayback` 的失败关闭语义）；短于 60 ms 的回退；pre/post roll 的边界值。
2. **单元（application）**：来源身份与当前已发布版本不一致 → `stale_reference`；媒体资产过期 → `unavailable`；文章来源 → `synthetic`；无 `DATABASE_URL` 时不联网、不抛未捕获异常。
3. **单元（route）**：未鉴权 401；`exampleText` 超长 400；响应体**不含** segments 数组（用断言锁住「不返回媒体目录」）。
4. **单元（UI）**：点击 → 播放（fake `HTMLAudioElement`）；播放中再点 → 停止；切到另一个词 → 原播放停止且只有一个 `play()`；原声失败 → 合成音兜底且提示可见；不支持合成 → 既有文案；慢速开关写入并按 `rate` 生效；**回归：浮层按钮仍在卡片盒子内**（既有断言不得放宽）。
5. **真实浏览器（`scripts/verify-vocabulary-page-browser.ts` 增补）**：用一个**已知有原声的例子词**点击朗读，断言 `audio.currentTime` 在 2 秒内前进且停在上界内；用一个**已知无原声的词**断言走合成音且界面显示「合成音」；断言播放期间**零 scroll 监听新增、零几何读取**（既有守卫）。
6. **门禁**：`pnpm typecheck`、聚焦 Vitest、改动文件 ESLint、相关 e2e、`pnpm build`；数据库迁移按仓库规则先 `db:generate` 再 `db:check`，并在目标库执行后核对 journal 一致性。

## 6. 性能与成本

- 点击一次 = 1 次解析（1–2 条语句）+ 1 次音频范围请求。**不预取**：7,892 个词的页面预取任何东西都会把带宽花在没被点的词上。
- 不做服务端音频缓存：播放 URL 是既有的媒体资产（Bunny），词架不引入第二份音频存储。
- 客户端**不缓存**解析结果（内存 Map 上限 20 条）：页面本身是一次性滚动浏览，缓存收益低于内存代价；这也避免把媒体 URL 长期留在内存。

## 7. 证据与隐私边界

- 朗读**不写** `evidence_events`、不改 `mastery`/`confidence`、不写画像或关系记忆。听音不是能力证据，跟读才是，而本设计不做跟读。
- 日志只记 `outcome`、耗时、`stableKey`、`segmentIndex`、词长/例句长度；**不记完整例句文本**（它可能来自受限来源），不记签名 URL。
- 播放地址沿用媒体资产的短有效期，不落库、不写 localStorage。

## 8. 为什么不新增 ADR

按 `AGENTS.md` §13 需要 ADR 的是：产品不变量 / Alpha 范围、模块边界与公共接口、数据模型与迁移策略、评分与画像语义、角色与隐私、供应商选择与保留方式。本设计触及的是**迁移策略**（给物化表加 4 列）与**模块间只读调用**（lexicon-corpus → media 的既有 application 接口）——前者是既有 ADR-0008 数据模型的直接延伸，后者不新建边界（media 一行未改，只是被调用）。**唯一可能的例外**是「朗读音源默认原声、不做供应商」这一条：它不是新决策，而是对既有事实（媒体已发布内容是我们自己的、清权的）的选择。

**若产品本人认为这条音源策略需要留档**，本次会补一份短 ADR（编号 0013），内容只写：音源默认原声、合成音仅兜底、不引入付费 TTS 与不抓取第三方音频这三条。**默认按不新增处理**，因为它不改变任何不变量。

## 9. 已知限制

1. 5,309 个词能拿到原声，其余 2,583 个只能合成音；界面必须诚实标注，不得暗示全部是真人发音。
2. 手机端（iOS Safari）的 `play()` 手势约束只有真实设备能验证；Playwright WebKit 通过不算真机通过。
3. 词架的合成音仍受浏览器音色可用性影响（iPhone 上可能没有西语音色）——本次不解决，因为它需要供应商，而产品已选择暂不引入。
4. 例句来自文章的 913 个词没有音频路径（文章没有时间轴）。
5. `exampleText` 是 180 字符裁剪窗口，可能从半个词开始；只用于**定位**（服务端 token 匹配）与**展示**，不用于朗读。
