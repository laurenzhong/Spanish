# Web 优先的个人学习产品与场景实战设计

- 日期：2026-09-11
- 状态：已完成逐节设计确认，等待书面规格复核
- 适用范围：个人 Alpha、响应式 Web/PWA、桌面浏览器与 iPhone Safari
- 相关决策：[ADR-0002：个人 Alpha 改为 Web/PWA 优先](../../adr/0002-web-pwa-first-personal-alpha.md)

## 1. 背景与决策

Sueño 当前首先服务项目所有者自己的西班牙语学习，而不是面向公开上架、获客或商业化。短期成功标准不是功能数量，而是能否快速形成每天实际可用、能够学到新知识并减少遗忘的学习闭环。

当前阅读功能已具备基本可用性；探索页缺少明确用途，长期 AI 角色仍存在自然度、Provider、记忆、角色特性和其他角色完成度问题。场景学习是当前最短的价值路径：把今天学到的表达放入可使用的环境，再通过变化条件和间隔复现转化为可调用能力。

本阶段只交付响应式 Web/PWA：

- 桌面浏览器作为完整学习工作台。
- iPhone Safari 和添加到主屏幕后的 PWA 作为手机入口。
- Flutter、原生 iOS/Android、商店发布和跨端 Dart 同步暂停，不删除已有代码。
- 继续使用私有云端数据、邮箱登录和服务端 Provider 密钥；后续关闭自由注册，只允许项目所有者的邮箱。

长期 AI 角色继续作为主要功能。角色回复自然度、Provider、长期记忆、人物特性和其他角色将进入独立设计流，不在场景实战中顺手修改。

## 2. 产品目标与非目标

### 2.1 目标

1. 让用户从阅读、收藏表达、最近错误或直接主题快速获得可练习场景。
2. 让已学表达在临时人物的多轮对话和条件变化中被主动提取。
3. 在用户完整表达之后判断沟通是否成功，并逐条标记需要调整的内容。
4. 默认保存完整文字对话，在当天、1、3、7 天用不同人物或条件复现。
5. 在桌面和 iPhone Safari 上都能完成搜索、准备、实战、复盘和恢复。
6. Provider 失败时保留学习进度并给出明确恢复动作。

### 2.2 非目标

- 公开内容平台、内容商城或开放角色创建。
- 支付、订阅、商业额度或公共用户增长机制。
- 实时双向语音通话。
- 将临时人物升级为联系人或长期关系。
- 保存普通练习的原始录音。
- 当前阶段重做长期 AI 角色系统。
- Flutter、原生移动端或商店发布。

## 3. 产品结构与优先级

保留五项导航，重新明确每一项的职责：

- **学习**：今日新任务、唯一下一动作和到期复现。
- **阅读**：网页、文本、PDF/EPUB、字幕及音视频转写形成的干净文本；继续完善发音和划词。
- **探索**：改造成“场景与表达库/场景工坊”，负责发现、搜索、生成和进入场景。
- **对话**：Lucía 等长期 AI 角色，负责持续关系而不是训练任务。
- **我的**：学习进度、Provider 状态与选择、数据和隐私设置。

首页仍必须根据真实学习状态提供唯一主动作：无记录时开始第一次练习；有稳定断点时继续学习；存在更优先的到期复现时由推荐器决定是否成为下一动作。页面不要求用户先选择时长、模式或内容类型。

## 4. 场景学习闭环

完整流程为：

> 获取场景句 → 试听与准备 → 临时人物多轮实战 → 条件变化 → 完整对话复盘 → 换场景间隔复现

### 4.1 获取场景与表达

探索页支持：

- 搜索和分类浏览。
- 根据主题生成私人场景。
- 从阅读内容、已保存表达或最近错误生成场景。
- 查看表达发音、翻译、自然变体、语气、槽位替换和收藏状态。
- 选择本次希望主动使用的表达，再进入实战。

私人 AI 生成场景可以立即使用，不进入公开内容发布审核。它必须保持用户私有、保存生成版本和来源，并通过结构与安全校验。

### 4.2 临时人物实战

- 每个场景使用服务员、房东、医生等临时不同人物。
- 临时人物只持有本次场景快照，不进入联系人，不积累长期关系记忆。
- 支持语音和文字；iPhone 底栏固定为“表达｜按住说话｜键盘”。
- 支持三级提示、暂停、恢复、重试和条件变化。
- 用户完整表达前不纠错，也不由教学目标强行控制人物回复。
- 条件变化由场景状态控制，例如菜品售完、时间改变或预算变化。

### 4.3 完整复盘

- 先显示沟通目的是否完成，不先给总分。
- 保存完整文字对话，错误和自然替代表达跟随原消息显示。
- 每条标记包含错误位置、原因、是否影响理解和更自然的表达。
- 支持播放自然表达和重新说一次。
- 技术失败、低置信度转写和打字不能污染发音、语流或真实口头反应证据。

### 4.4 间隔复现

- 默认安排当天、1、3、7 天复现。
- 复现时更换人物、地点、沟通条件或表达槽位，而不是原样重复。
- 复现从学习页唯一下一动作进入，也可从场景历史主动开始。
- 熟练度与可信度仍分离；学习时长只进入热力图。

## 5. 响应式界面设计

视觉采用暖米白、灰绿色和赤陶色的编辑式风格。页面保持单主列、清晰分隔和集中操作，避免大面积宣传标题、后台卡片堆叠、不等高双栏及右下角空白。

### 5.1 桌面

- 场景工坊以内容浏览和快速进入为主，不表现为配置后台。
- 场景详情使用单主列，表达选择、试听和开始实战沿阅读顺序排列。
- 实战页进入专注模式，目标进度为窄状态带，对话为主内容。
- 复盘页保留完整上下文，支持“全部/只看标记”切换。

### 5.2 iPhone Safari

- 采用 390px 基准验证，同时覆盖 320、375、414px。
- 顶部标题和状态保持紧凑，不使用占据首屏的大标题。
- 主要按钮最小触控区域为 44px。
- 固定底栏为 Safari 安全区留出空间，键盘切换位于右侧便于单手操作。
- 输入法弹出、视口回弹、滚动和前后台切换必须有真机验证。

本次已确认场景详情、临时人物实战和完整对话复盘的桌面与 iPhone 预览。

## 6. 模块边界

新增独立 `scenario-practice` 业务模块：

- `explore` 负责搜索、分类、来源筛选和进入场景。
- `scenario-practice` 负责场景准备、临时人物、多轮实战、条件变化、复盘和复现。
- `reading` 只提供文章版本、所选表达或文本引用。
- `training` 提供可复用的尝试、语音和稳定断点能力。
- `evidence` 与 `profile` 只接收服务端验证后的证据。
- `recommendation` 把到期复现纳入唯一下一动作。
- `conversation`、`characters` 和 `memory` 不参与临时人物会话。

`scenario-practice/domain` 必须保持纯 TypeScript。Route Handler 只做认证、Zod 校验、调用 application 用例和协议转换。React 组件不得直接访问数据库或写入能力事实。

## 7. 数据模型

复用现有 `scenarios`、`scenario_tasks`、`expressions`、`practice_sessions`、`practice_attempts` 和 `learning_breakpoints`，新增独立表：

### 7.1 `personal_scenarios`

- `id`, `user_id`
- 标题、CEFR、地区和场景骨架
- 来源类型与来源版本：主题、阅读、收藏表达或最近错误
- 选中表达、沟通目标和条件变化
- Provider、模型和生成版本
- `ready`/`archived` 状态与创建时间

私人场景不能通过公共内容查询返回。

### 7.2 `scenario_session_states`

- 与 `practice_sessions` 一对一关联
- 临时人物快照
- 当前沟通目标、已触发条件和当前轮次
- 当前 `generation_id`、`revision` 和稳定状态

它不保存人物关系阶段、人物圣经或长期记忆。

### 7.3 `scenario_turns`

- `session_id`, `user_id`, `turn_index`
- `speaker`: `user`、`temporary_character` 或 `condition`
- `modality`, `text`, `status`
- 可选 `attempt_id` 与 Provider 元数据引用
- 创建、完成和停止时间

只有完整文字轮次进入历史；未完成流不能标记为完成。

### 7.4 `scenario_turn_reviews`

- 关联用户完整轮次
- 沟通成功、错误范围、错误类别和解释
- 自然替代表达、提示等级、转写置信度
- 算法和 Provider 版本
- `ready`、`pending` 或 `unavailable` 状态

Provider 结果不能直接写入证据；application 规则必须重新校验。

### 7.5 `scenario_repetition_items`

- 原始场景或私人场景引用
- 表达与沟通目标快照
- `due_at`, `interval_step`, `status`
- 上次结果和下一次变体要求

所有私人表带 `user_id`、RLS、级联删除和服务端所有权检查。数据库变更只通过版本化迁移完成。

## 8. API

### 8.1 浏览与生成

- `GET /api/v1/scenarios`
- `POST /api/v1/scenarios/generate`
- `GET /api/v1/scenarios/:scenarioId`

### 8.2 实战

- `POST /api/v1/scenario-practice/sessions`
- `GET /api/v1/scenario-practice/sessions/:sessionId`
- `POST /api/v1/scenario-practice/sessions/:sessionId/turns`
- `POST /api/v1/scenario-practice/sessions/:sessionId/turns/:turnId/respond`
- `POST /api/v1/scenario-practice/sessions/:sessionId/turns/:turnId/evaluate`
- `POST /api/v1/scenario-practice/sessions/:sessionId/complete`
- `GET /api/v1/scenario-practice/sessions/:sessionId/review`
- `GET /api/v1/scenario-practice/due`

### 8.3 Provider 设置

- `GET /api/v1/providers/status`
- `GET /api/v1/me/provider-preferences`
- `PATCH /api/v1/me/provider-preferences`

Provider 状态响应只包含能力、选择、配置/健康状态和脱敏时间信息，不暴露密钥或原始供应商错误。

所有写接口使用用户会话、`Idempotency-Key`、`attemptId`、`generationId` 和必要的 `expectedRevision`。跨设备请求仍由服务端验证所有权与状态版本。

## 9. Provider 路由

定义能力专用接口：

- `ScenarioGenerationProvider`
- `ScenarioRoleplayProvider`
- `ScenarioEvaluationProvider`
- 现有 `TranscriptionProvider`
- 现有 `PronunciationProvider`
- 浏览器 `TextToSpeech`

临时人物接口不得复用长期角色的关系上下文接口。服务端 `ProviderRouter` 按能力选择用户偏好和健康 Provider：

1. 优先使用该能力的用户选择。
2. 未配置时选择第一个健康 Provider。
3. 非流式生成和评估失败时最多自动切换一次。
4. 流式回复尚未显示文本时可以切换；显示文本后失败必须显式重试，不能静默换模型。
5. 重试创建新 `generationId`；旧回调不得更新当前状态。
6. 每次调用记录 Provider、模型、延迟、请求 ID、结果和估算成本，不记录完整对话或原始录音。

生成输出必须通过 Zod；人物回复必须通过临时角色边界与现实声明门禁；评估必须以语境成功优先并接受自然替代表达。真实使用时 Provider 不可用就显示诚实错误；deterministic fake 仅用于开发和自动测试。

## 10. 状态机与恢复

主流程：

> 准备 → 等待表达 → 录音 → 转写确认 → 提交 → 人物回复 → 再次等待表达 → 完成 → 复盘

稳定状态包括等待表达、转写待确认、上一轮回复完成、暂停、可恢复错误、复盘生成中和复盘完成。录音、转写和流式生成是临时状态；刷新或设备切换只能恢复最近的服务端稳定断点。待确认转写只作为有过期时间的断点草稿保存，不进入 `scenario_turns`、历史或学习证据；取消后删除，原始音频始终不随断点保存。

关键规则：

- 麦克风拒绝立即提供键盘，不产生负面证据。
- 录音被中断时丢弃未完成音频并回到稳定状态。
- 低置信度转写要求确认或编辑，不能成为负面发音证据。
- 人物回复没有 `done` 时不保存半条完成消息。
- 评估失败不阻断继续对话，复盘显示待补充且不写证据。
- 保存失败时先恢复保存，不调用下一步 Provider。
- Provider 限流显示重试时间并允许切换。
- 多标签页或跨设备旧 revision 被拒绝并重新加载。
- 完成接口以事务冻结会话、生成复盘状态并建立复现计划。

## 11. 隐私与内容规则

- 完整文字对话默认保存，逐条标记错误。
- 录音只在当前尝试中短期存在，完成处理、取消、超时或离开页面后删除并释放资源。
- 当前切片不提供长期保存录音；未来必须单独明确确认。
- 私人生成内容可以立即使用，但不获得公开发布资格。
- 公共领域、开放许可或用户有权使用的材料可快速导入私人空间；仍保存来源、许可/授权和版本信息。
- 未确认可公开分发的第三方全文不能通过公共接口发布。
- 日志不得包含完整私密对话、原始录音、令牌、密钥或长期签名 URL。

## 12. 测试与验收

### 12.1 自动化

- 状态机覆盖合法、非法、取消、失败和过期回调。
- 提示只能逐级增加；自然替代表达可以完成任务。
- 打字、低置信度和技术失败不得形成负面口语证据。
- 场景生成、轮次提交、复盘完成和复现计划具有幂等性。
- 保存失败不能产生孤立人物回复。
- 数据库覆盖 RLS、跨用户拒绝、级联删除和事务边界。
- 临时人物不得创建联系人、关系记忆或人物事实。
- Provider fake 覆盖超时、取消、限流、鉴权、无效 Schema、异常断流和一次性切换。
- Playwright 覆盖桌面和 iPhone 视口的完整纵向路径、麦克风拒绝、刷新恢复、Provider 缺失和断流重试。

### 12.2 真机

真实 iPhone Safari 检查麦克风授权和中断、键盘弹出、底部安全区、长按录音、PWA 主屏恢复以及前后台资源释放。Playwright WebKit 通过不能代替该真机结果。

### 12.3 质量命令

每个实现任务至少运行相关测试、`pnpm lint`、`pnpm typecheck` 和 `pnpm test --run`。跨模块、迁移或发布候选还运行 `pnpm test:e2e`、`pnpm build` 和数据库迁移/RLS 检查。本阶段不要求 Flutter 检查，除非任务明确修改了暂停维护的 Flutter 代码。

## 13. 实施拆分

正式实施计划在本规格书面复核后生成，建议按以下任务拆分：

1. `SCN-001`：领域状态机、数据迁移、API 契约、Provider Router 和 fake。
2. `SCN-002`：一个真正可用的“餐厅点餐”文字/语音纵向闭环。
3. `SCN-003`：探索场景库、搜索、分类、生成及阅读/收藏/错误来源。
4. `SCN-004`：完整复盘、历史、当天/1/3/7 天复现和学习页推荐。
5. `SCN-005`：Provider 设置、自动切换、iPhone Safari/PWA 真机收敛和发布门禁。

每个分支只处理一个任务 ID，完成后分别提交、测试并更新 `PROJECT_STATUS.md`。先交付可亲自使用的纵向路径，再扩充场景数量和自动化来源。

## 14. 已知后续设计流

长期 AI 角色仍是主要功能，后续独立设计必须覆盖：

- 回复自然度与教学腔控制。
- 不同能力的 Provider 选择、观测和切换。
- 人物圣经、已透露事实、关系记忆和教学画像边界。
- Lucía 之外角色的独立特性与完成度。
- 对话连续性、人物主动性和真实/虚构安全门禁。

本规格只保证场景实战不会污染上述长期角色系统，不预先决定该设计流的具体实现。
