## 2026-10-13 修订：当前决定

产品本人反馈 suponer 单词发音播出媒体语句，并明确选择“单词统一用 TTS”。词汇页手动“朗读单词”与点词自动发音均在用户手势中同步调用浏览器 es-ES TTS，只传当前显示的单词；不请求 word-audio，不读取媒体 URL 或切片，也不展示媒体段落作为词音文本。准备状态可取消，只有 start 确认后显示正在朗读；成功结束复位，超时/错误可重试，切词/关闭/Escape/隐藏/卸载停止，旧 generation 回调失效。

例句继续遵循 ADR-0015：有可用授权录音播放 Tatoeba 完整原声，缺录音明确标注并用西语 TTS，原声失败不自动替换。词音与两种例句音互斥。不增加收费供应商、录音存储、学习证据或数据库变更。旧 word-audio 服务端接口/时间轴解析及迁移保留兼容，词架 UI 不再调用。

检查 suponer 时读库得到 400ms 词窗、带 roll 后 770ms；原生 Chrome 正确 seek/stop 约 770ms，未复现整句播放。这个检查不能证明切片独立发音正确：连读、邻词及 ASR 边界仍会影响听感。因此按产品选择统一 TTS，不虚称修复了 seek 故障。跨设备音色/西语声音可用性仍受浏览器影响，不称为标准发音。

本节取代下方原声优先的词音顺序、媒体切片播放器及“全部合成音被否掉”决定；下方保留 2026-10-12 决策历史。例句许可决定以 ADR-0015 为准。

## 2026-10-20 修订：词卡不再显示朗读状态文案

所有者要求词汇页点击「朗读单词」后不再显示「合成音」与「准备中」字样。词卡里的单词朗读（含点词自动发音触发的朗读）不再渲染状态行；加载、播放与停止只由按钮的停止标签、`aria-busy`、`aria-pressed` 表达，失败仍在词卡内显示可重试提示。音源与生命周期不变：仍经 ADR-0019 的统一 MiniMax 合成朗读，只读当前显示的单词，不请求媒体切片，不写能力证据。

§6 的「合成音必须标为『合成音』」在单词朗读控件上不再要求可见文案；其核心禁令不变——任何界面不得把这些声音写成真人、母语者或标准发音，Tatoeba 例句仍以按钮文案区分原声与合成朗读。

## 2026-10-12 决策历史

## Context

词汇页（`/read/vocabulary`）现在只有词详情卡里的一个「朗读单词」按钮，走浏览器 `speechSynthesis`。三个事实使这不够：

1. **音质与一致性不足**：音色来自访客设备，iPhone 上常常没有西语音色；同一页面在不同设备听起来不同，且不是任何意义上的发音基准。
2. **我们的语料本身就有更好的音源**：词架的例句来自已发布内容，其中 **5,309 个词的例句带毫秒级词时间轴**（`media_segments` 99,285 段中 69,586 段有 `words`）。这些内容是我们自己发布、自己记录来源与版权状态的（`copyright_status = 'cleared'`），也就是说**真实母语语流的权利链在我们自己手里**。
3. **第三方音频不可用**：对标的 Language Reactor 的三条音源（平台原声、云端合成音、浏览器本地）没有一条可以合法转授给我们——原声的权利在 YouTube/Netflix 等平台，合成音的权利在它的 TTS 供应商。详见调研 §6。

同时必须守住既有边界：朗读不是能力证据；词架是一个 7,892 个词块的页面，任何新增都不能破坏它的滚动性能与悬停可达性。

## Decision

### 1. 音源按固定顺序选择，共四级，每级都有可见状态

有原声播原声 → 原声不可用降级并说明 → 没有原声用浏览器合成音并标注「合成音」 → 浏览器不支持合成音给明确文案。**任何一级都不允许静默失败。**

### 2. 不引入付费 TTS 供应商，不抓取第三方音频

本次只用自己的已发布内容音频与浏览器本地合成。若将来需要「真人级合成音」，必须先单独决策供应商（含音色、条款、缓存与再分发许可），不能以复制他人产物绕过。

### 3. 匹配用折叠重音后的 token 相等，命中必须唯一

例句中的词形与词架词形常有重音差异（`escuadrón` ↔ `escuadron`），必须折叠后比较；同时**禁止字符串包含**（`includes("sol")` 会命中 `solo`，把别人的发音播成这个词的）。命中多处且时间不同、或时间轴不合法，一律判定「无原声」。

### 4. 时间轴只信 provider 数据

复用媒体模块既有的 `wordTimingsForPlayback()`：它与 `sourceText` 不一致时失败关闭，且明确禁止用 `estimateWordTimings()` 估算。不得新增第二套时间轴推断。

### 5. 播放一律经媒体模块既有的读取接口

词句模块不自己拼播放地址、不放宽发布与版权门禁：解析调用 `getMediaPlayback(repository, stableKey, userId)`。**客户端只收到一个片段引用，不收到媒体分段列表**（最重的一份播放载荷实测 0.42 MB）。

### 6. 诚实标注

合成音必须标为「合成音」，不得写成「母语者发音」或「标准发音」；原声必须标出来源标题；只有 5,309 个词能拿到原声这一事实不得被界面暗示为「全部真人发音」。

### 7. 朗读不写任何能力证据

不写 `evidence_events`，不改 `mastery` / `confidence`，不写画像或关系记忆。跟读（本设计不做）才有独立的证据语义。

## Consequences

### 正面

- 听到的是真实语流（连读、语调、真实语速），这正是合成音给不了的；且来源与权利链完整可查。
- 零新增供应商、零新增计费；播放地址沿用既有媒体资产与短有效期。
- 降级链显式，用户在「没有原声」时仍能听到发音，并知道自己在听什么。

### 成本与限制

- 需要一次迁移：物化表 `lexicon_form_frequencies` 增加例句的来源身份 4 列，否则物化之后无法定位音频。
- 原声覆盖有限：**5,309 / 7,892** 个词可拿原声，其余（语料里没有该词、例句来自文章、词形匹配不上）只能合成音。
- 每次点击多一次解析往返 + 一次音频范围请求；因此不预取、不做服务端音频缓存。
- 浏览器合成音在 iPhone 上仍可能没有西语音色（要解决必须引入供应商，本 ADR 明确排除）。
- iOS Safari 的 `play()` 需要用户手势，只有真机能验证；Playwright 通过不代表真机通过。

### 被否掉的替代方案

1. **全部用浏览器合成音**（现状）：零成本，但没有发音基准，跨设备不一致。
2. **引入服务端 TTS 作发音基准**：音质可控，但需要供应商决策与按次计费；且实测 MiniMax **没有西语系统音色**（`Spanish_*` 报 `voice id not exist`；英语音色读西语是否为合格基准未验证），因此本次不作为默认路径。
3. **抓取 Language Reactor 的音频**：权利链不成立（原声属平台、合成音属其供应商），违反 `AGENTS.md` §8；且它的词表音全是合成音，抓来也没有原声优势。
4. **悬停自动朗读 / 点词即读**（LR 默认行为）：与我们的悬停词典抢同一次点击，手机无悬停会误触；且扫过整页会连续出声。
