# ADR-0003：证据事件与技能快照的首个写入闭环

- 日期：2026-08-21
- 状态：已接受
- 关联任务：ALPHA-012

## 背景

训练状态机和 STT provider 已经能够产生一次经过转写与评估的尝试，但证据事件和技能快照还没有服务端写入用例。客户端不能成为能力事实来源，技术失败和低置信度转写也不能污染画像。

## 决定

1. 由纯 TypeScript 领域函数把一次评估转换为有界证据事件草稿。证据强度使用语境证据强度、独立程度、输出方式可靠度、任务难度和评测可信度的乘积；目标语块只有在实际使用时才更新。
2. 由 `recordEvidence` application 在一个 repository 事务中执行幂等检查、追加 `evidence_events`，并从该技能的全部历史证据重算 `user_skill_states`。
3. 语音证据要求转写置信度至少为 0.75。技术失败、取消、超时、空转写或低置信度转写返回无证据结果，不写负面能力证据。
4. 打字证据可以更新语境、任务和准确性相关技能，但不能更新 `fluency.*`、`pronunciation.*`、`reaction.*` 或 `oral.*` 技能。
5. 证据事件保存算法版本、内容版本、输入方式、提示级别、标签权值和可信度，但不保存原始转写正文。客户端只能通过后续服务端用例提交，不能直接写证据或快照。

## 取舍

- 快照是可重算的派生状态；重复提交不会增加 `evidenceCount`。
- 评分更新使用 `mastery + weight * (outcome - mastery)`，`confidence` 单独根据可靠证据增长，因此可靠的失败观察可以降低熟练度但提高结论可信度。
- 本任务只建立 application、repository 和 PGlite 集成验证，不接入训练 UI 或 Route Handler。后续任务再把已验证用例接入用户路径。

## 后果

- 真实数据库写入和画像更新共享事务边界，失败时不会只写一半。
- 现有 schema 足以承载首个闭环，不新增迁移。
- 未来加入聊天、阅读或更细的发音证据时，需要扩展统一输入 DTO 和口语技能分类，并继续保持服务端最终校验。
