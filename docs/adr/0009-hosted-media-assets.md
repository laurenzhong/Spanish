# ADR-0009: Host Authorized Media Assets

- 日期：2026-09-15
- 状态：Accepted
- 影响：media 播放资产、Language Reactor 播客可靠性、Storage 运维

## 背景

媒体目录此前保存第三方 enclosure 或签名播放 URL。本站代理可以隐藏来源并转发 Range，但不能在源站删除、签名过期或用户网络无法访问时继续播放。

## 决定

2026-09-16 下载工具补充决定：所有者明确指定今后视频下载统一采用 yt-dlp（含官方要求的 JavaScript runtime/EJS 依赖），不以浏览器抓取或录屏替代。Playwright 负责播放验收；授权原文件导入及自有存储完整性读取继续保留。优先最高原生分辨率，不将 AI 放大版当作原生画质；工具或来源不可用时报告失败，仍不绕过访问控制/DRM/平台下载限制。

1. 对明确授权且已发布的播客，下载时执行 HTTPS、主机、MIME、大小和响应完整性校验后，复制到专用 Supabase Storage bucket `media-audio`。
2. 公开已发布媒体使用稳定的 Supabase public object URL；`media_assets.playback_expires_at` 设为 `NULL` 只表示本站对象没有租约，不表示来源授权永久不可撤回。
3. Storage 对象路径使用 `media/{stableKey}/{version}/audio`，不包含邮箱、令牌或原始签名参数。原始第三方 URL 继续只保留在服务端数据库审计字段，不进入客户端和普通日志。
4. 上传失败不得更新数据库；数据库更新失败必须删除刚上传对象。撤下媒体时先移除公开投影，Storage 对象保留到明确的清理任务执行，以保留历史版本和可审计性。
5. 所有者已确认当前纳入范围的视频具备再分发权利且平台条款允许托管。已发布且版权状态为 `cleared` 的 YouTube 视频可以通过一次性服务端回填复制到专用媒体存储；使用受控 `yt-dlp`/ffmpeg 管线生成浏览器兼容 MP4，成功后把同一 `media_assets` 行切换为稳定本站 URL，失败时保留原官方嵌入，不自动发布或伪造托管成功。后续新增来源仍须在进入发布流程前记录相应授权。
6. 托管视频详情页使用 Plyr 包装的原生 `<video>` 播放器和现有字幕/进度工作台；官方嵌入只作为未托管视频的降级路径。对象路径使用 `media/{stableKey}/{version}/video.mp4`，不包含令牌或签名参数。

## 后果

### 2026-09-16：HOSTED-MEDIA-002 视频存储调整

所有者已批准视频改用 Bunny Storage + Pull Zone。长视频不再受 Supabase 当前套餐单对象上限约束，也不依赖 Bunny Stream 的尽力而为编码队列；服务端先生成 H.264/AAC MP4，再通过专用 Storage 密码上传，密钥不得进入浏览器。播客存储策略不在本切片中改变。

- `provider_key=bunny-storage` 且 `kind=video` 的稳定托管资产允许 `playback_expires_at=NULL`，由迁移 `0032_bunny_storage_video_expiry` 明确放行；不扩大普通 RSS 或其他供应商的免有效期范围，不修改 RLS。
- 使用版本与内容哈希命名的对象，迁移前校验完整来源，切换前校验 CDN 文件长度、SHA-256 和 Chrome 实际播放/seek；只条件更新仍指向原来源的已发布、已授权资产，不修改字幕或学习证据。
- 验证通过但数据库切换失败的对象保留在可恢复迁移清单中，不视为已完成；可复用同一对象重试，不能无记录地遗留。这是本迁移对前文“数据库失败立即删除上传对象”的受控例外。
- Supabase 原对象只在 Bunny 校验、网站播放验收、全版本引用核查都通过后按精确路径删除；任何剩余历史引用都阻止删除。
- 对精确引用同一 Supabase 视频对象、属于同一 stable key 且版权仍为 cleared 的历史视频资产，可以事务迁移其存储地址；不改变内容版本、字幕、availability 或学习数据。历史地址迁移先提交，再在排他写锁保护下复查零引用并删除原对象，避免删除失败/事务回滚产生指向已删除源的引用。其他媒体身份、权限或类型的引用一律阻止清理。
- 无到期时间仅表示没有签名租约；账户停用、欠费、对象删除、网络问题和授权撤回仍会影响可用性，不承诺永久在线。

本站播放不再依赖已托管媒体的第三方网络可达性，代价是下载流量、视频转码、Storage 容量和授权撤下运维。托管不是自动获得版权；每个对象必须能追溯到已审核版本和授权记录。若下载源当前网络不可达，回填任务只能报告失败，不能通过代理绕过平台访问限制。

### 2026-09-16：方案二的播客迁移切片

继续执行所有者“视频和播客全部迁移”的授权，将当前已发布且 cleared 的两条播客也复制到同一 Bunny Storage + Pull Zone，保留原 MP3 字节，不做有损重编码。0033 仅将 Bunny 的无租约范围扩展到 audio；普通 RSS 策略和 RLS 不变。下载必须校验来源/重定向白名单、MIME、完整大小和解码；上传后核对全文件哈希并验证实际播放/seek 后才能条件切换。源不可用时保留原资产，不冒充成功。Supabase 音频原对象只有在网站验证及全版本引用检查后才清理；不删除第三方服务器上的文件。
