# ADR-0002：个人 Alpha 改为 Web/PWA 优先

- 日期：2026-09-11
- 状态：Accepted
- 影响：个人 Alpha 客户端范围
- 关系：在个人 Alpha 范围内取代 ADR-0001 的 Flutter 同步实施决定；ADR-0001 保留为历史记录

## 背景

产品当前首先服务项目所有者自己的学习，不再以公开上架、获客或短期商业化为目标。现有阅读 Web 功能已经可以使用，但探索、场景迁移和长期 AI 角色仍需要大量产品与可靠性工作。同步维护 Next.js Web 与 Flutter 会把有限时间分散到跨语言 UI、契约和平台构建，而当前最直接的使用设备是电脑浏览器和 iPhone。

响应式 Web/PWA 可以在同一代码路径覆盖桌面浏览器和 iPhone Safari，并继续复用现有 Supabase、Next.js Route Handlers、训练、证据、阅读、对话和 Provider 模块。它也允许先解决学习价值与 Provider 可靠性，再决定是否恢复原生客户端投入。

## 决定

1. 个人 Alpha 只要求 Next.js 响应式 Web/PWA，覆盖桌面浏览器与 iPhone Safari。
2. Flutter、Dart、原生 iOS/Android、商店发布和跨客户端一致性工作暂停；已有 `apps/mobile` 代码保留，不删除、不继续同步功能。
3. iPhone 通过 Safari 和添加到主屏幕后的 PWA 使用；麦克风、键盘、安全区、前后台和音频生命周期需要真实 iPhone 验证。
4. PostgreSQL 继续作为学习证据、画像和关系记忆的权威来源；PWA 不是离线权威客户端。
5. `/api/v1`、稳定错误码和明确 DTO 继续保留，以免未来恢复 Flutter 或增加其他客户端时重新设计服务端边界。
6. Flutter 测试不再是普通 Web 任务或个人 Alpha 发布候选的必需门禁；只有明确修改 `apps/mobile` 时才运行相应检查。
7. 未来恢复原生或 Flutter 客户端前，必须根据实际个人使用结果、PWA 能力缺口和维护成本重新评估并新增 ADR。

## 替代方案

### 继续 Web 与 Flutter 同步

保持长期多平台方向最一致，但当前需要重复实现页面、状态编排和测试，延迟真正可用的学习功能。

### 立即开发原生 iOS

可以获得更深的平台能力，但需要 Mac/Xcode、签名与独立 UI 代码线，也不能解决当前探索和学习闭环问题。

### 使用 Capacitor 包装 Web

可以较快进入商店，但商店发布不是当前目标，且仍增加原生包装、审核和生命周期维护成本。

## 后果

- 当前功能和视觉只需在一个 Web 代码路径实现，能更快形成可日常使用的学习闭环。
- iPhone 能力受 Safari/PWA 限制，后台录音、通知和离线行为不能按原生应用假设。
- 现有 Flutter 代码会暂时落后于 Web；文档和状态页必须明确它是暂停维护，而不是同步完成。
- 保留版本化 API 和服务端模块边界，使未来恢复多客户端仍有清晰迁移路径。
- 个人 Alpha 的真机门禁从 iOS 编译/签名改为 iPhone Safari/PWA 行为验证。
