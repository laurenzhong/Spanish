# ADR-0018：独立媒体系列目录与单集导航

- 日期：2026-10-15
- 状态：Accepted（2026-10-16，所有者要求“实现整个需求”）；实施按切片推进。
- 文档任务：MEDIA-SERIES-000
- 关联：[系列设计](../superpowers/specs/2026-10-15-media-series-and-episode-navigation-design.md)、[实施计划](../plans/2026-10-15-media-series-implementation-plan.md)。

## 背景

媒体库已有大量同来源内容，但频道不等于系列，单集卡片缺少系列身份与选集。所有者认可系列/单集结构，并明确要求视频结束后在下方展示当前系列的其他视频。仅按来源名称聚合不能表达多个系列、可靠顺序和归属修正。

## 决定

1. 系列属于 `media` 模块，使用独立目录与成员关系，第一版一个媒体最多归属一个系列、一个系列一种媒体类型。来源与主题继续独立保存。
2. 系列关联稳定媒体 ID，以独立 revision 和追加审计修订，不改写已发布媒体版本、字幕、内容哈希、进度或历史学习证据。
3. 所有者通过鉴权、allowlist、RLS、事务、幂等与 CAS 维护归属；采集仅提交待确认建议，不直接写媒体表，不获得额外发布权限。
4. 保留学习页单集直接入口，增加系列入口、系列页与选集。只有当前可见、清权且可播放的当前版本进入集数、邻接和推荐。
5. 当前视频的有效 ended 事件触发下方最多六条同系列其他视频；固定排序、显式点击、无自动连播。推荐与进度写入独立，不产生能力证据。
6. 后续只在“换一批”增加来源内系列轮换，保留完整候选与稳定分页；普通排序不变。元数据采集建议另立切片。
7. 不引入通用 CMS、新服务、课程体系或原生客户端。

## 替代方案

- 只使用 sourceName：改动小，但名称不是身份，一个频道的多个系列仍混杂，无法可靠排序。
- 把 seriesId 写入不可变媒体版本：关系明确，但仅整理目录也要重新发布大量内容并影响历史引用；选择独立、可审计目录。
- 默认全改为系列卡：减少重复，但增加开始学习的中间步骤，与当前单集直接进入的体验冲突；系列浏览作为补充入口。

## 后果

新增目录迁移、窄查询、权限与审计测试；系列归属需证据和持续维护。目录关系可修订，历史评分与字幕仍由原媒体版本解释；若未来评分依赖系列，必须另行设计冻结引用，不能直接复用动态目录。浏览游标需考虑目录 revision 与可见成员变化。推荐不阻塞播放器，失败时保留原播放与字幕路径。
