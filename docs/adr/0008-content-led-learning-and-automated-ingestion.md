# ADR-0008：内容驱动学习入口与自动采集审核链路

- 日期：2026-09-12
- 状态：Proposed；产品方案已口头确认，等待书面规格复核后 Accepted
- 影响：一级导航职责、学习入口、内容域、自动化运行方式、能力画像
- 关联规格：[自动内容供应与词句学习重构设计](../superpowers/specs/2026-09-12-automated-content-supply-and-lexical-learning-redesign.md)

## 背景

现有“学习”页以“开始第一次练习”“继续学习”和独立表达训练为中心。产品本人实际使用后认为该结构任务感过强、可用性差，并且与“探索”中的场景练习重复。与此同时，产品缺少持续的视频、播客和文章素材供应，词汇、短语、跨来源语料和相关能力考察也没有稳定的产品位置。

Language Reactor 调研说明，原生内容中的片段、词语和上下文可以形成高效的学习工作台，但其高密度工具、词频主轴和标词状态不能直接作为 Sueño 的能力模型。Sueño 仍需保持语境成功、输出方式隔离、低置信度保护、`mastery`/`confidence` 分离和角色记忆边界。

每日内容获取包含来源增量、去重、下载或读取、字幕/正文处理、可选 ASR、审核、发布和语料索引。把这些长任务直接放进普通 Vercel 请求会产生超时、重试和费用重复风险；为个人 Alpha 拆分消息队列或微服务又明显过度。

## 决定

1. 保留“学习、阅读、探索、对话、我的”五项一级导航，但重新定义职责。
2. `/learn` 直接成为视频与播客资料库。移除现有 Hero、开始/继续任务 CTA 和独立表达训练入口；用户打开后直接选择内容。
3. `/read` 承载文章、词汇、短语、文字考察和跨来源语料查询。词句考察不要求口头回答。
4. `/explore` 继续负责场景库、私人场景和临时人物多轮实战；`/chat` 继续负责长期 AI 角色。
5. 移动端不在页面顶部常驻头像；底部“我的”是稳定账户入口。桌面账户入口可以保留在侧栏上下文中。
6. 新增 `content-acquisition`、`media` 和 `lexicon-corpus` 三个业务模块。文章复用现有 article 模型；视频和播客共享 media 模型；旧 `content_packs` 冻结为历史兼容载体，不继续扩展为通用媒体库。
7. 文章与媒体不强行共用一个实体表，而是通过版本化 `ContentDocumentRef`、片段和 `SourcePosition` DTO 向词句/语料模块提供统一定位语义。
8. 自动内容供应只运行白名单来源：YouTube 官方 API/RSS、播客 RSS、文章 RSS 和经记录的专用适配器。不得绕过访问控制、付费墙、DRM 或平台限制。
9. 每日自动化只把内容推进到候选审核库。来源/权利、`es-ES` 内容、`zh-CN` 教学和结构校验全部通过后，仍需所有者显式发布。
10. 业务逻辑保存在模块化单体内，以 TypeScript CLI 暴露；个人 Alpha 使用定时 CI runner 每日触发，有界工作记录保存在 PostgreSQL。不新增微服务、复杂消息队列，也不让 Vercel Route Handler 承担长任务。
11. 无字幕媒体只有在来源、相关性、语言、时长、权利和预算门禁均通过后才执行 ASR。ASR 结果始终是草稿，临时音频在完成、失败、取消或超时后立即删除。
12. 画像主展示改为“词汇与短语、交流运用、语音表达、跟读表现”四个板块。旧八维历史保留并通过版本化映射迁移；无法可靠映射的数据不伪造。
13. 纯观看、阅读、查词、收藏、播放进度和词频不构成能力证据。文字词句考察只更新词句板块；文字对话不能更新语音；跟读不能替代自主表达。

## 替代方案

### 保留任务式学习首页，另加“影音”一级导航

能够保留现有实现，也能让视频与播客有独立入口，但会形成六项导航并继续让两个主要入口竞争“学习”的含义。移动端更拥挤，且不能解决当前学习页已经被确认失败的问题。

### 把视频、播客和文章全部放进阅读

内容模型表面统一，但“阅读”很难自然表达视频/播客的消费意图，媒体资料库也会挤压文章、词汇和语料结构。用户已经确认视频和播客应共同占据学习页，因此不采用。

### 把新媒体继续建模为 `content_packs`

短期迁移少，但现有 content pack 以训练活动和步骤为中心。继续加入频道、节目、episode、播放资产、时间片段和大规模语料索引会让模块失去单一职责，并把旧训练 UI 的假设带入新学习页。

### 由 Vercel Cron 在 Route Handler 内完成全链路

部署简单，但抓取、媒体处理和 ASR 容易超过请求时限，失败恢复和费用幂等也更难。Route Handler 继续用于短请求和所有者操作，长任务由可替换的定时 runner 调用同一 application/CLI。

### 自动处理后直接发布

能最快扩充资料库，但来源、字幕、翻译、语言质量和 AI 输出都可能出错，也违反现有未审核内容不得生产发布的规则。自动化只到候选库。

## 后果

### 正面

- 用户进入学习页后立即接触内容，消除任务 Hero 和模式选择成本。
- 视频与播客共享工作台，同时保持文章模型稳定。
- 每日增量供应减少手工寻找和预处理成本，所有者仍掌握最终发布权。
- 词句对象可以跨文章、视频和播客追溯上下文，文字考察与口语证据保持分离。
- 三个新模块各自拥有清晰职责，仍在单仓库和模块化单体内运行。

### 代价与风险

- 现有 `/learn`、八维画像、UI-014 至 UI-017 和 `ALPHA-033` 计划需要重排。
- 新增来源适配器、运行记录、媒体版本、语料索引和清理任务，提高数据库与运维复杂度。
- 定时 CI runner 需要独立管理数据库凭据、Provider 密钥、预算和失败告警。
- 来源撤下、平台条款变化和字幕失效会成为长期运行问题，必须支持撤下和重新处理。
- 自动 ASR、翻译和词形分析带来可控但真实的成本，默认测试仍只能使用 fake。

## 执行约束

- 本 ADR 在书面规格批准后转为 `Accepted`，并与 `AGENTS.md`、`README.md`、`PROJECT_STATUS.md`、架构、内容、测试和实施计划同步更新。
- 在详细实施计划获批前，不替换页面、不创建迁移、不运行公网采集、不调用收费 Provider。
- 当前 `codex/ui-014-reading-density` 的未提交改动必须完整保留；协调者在新队列登记时再决定复用、拆分或延期。
- 第一个实现任务必须是 `ACQ-001` 的领域、契约、数据库和 fake 基础，不能同时实现真实发布、全部来源和前端资料库。
