# 内容制作与审核规范

- 适用范围：核心表达、场景任务、沉浸式内容包、阅读文章、人物圣经和教学解释
- 目标语言：西班牙语，个人 Alpha 优先 `es-ES`
- 首个母语教学版本：简体中文 `zh-CN`

## 1. 内容原则

- 内容必须服务于真实沟通目的，而不是只展示语法知识。
- 允许多种自然表达，不把唯一参考句当成唯一正确答案。
- 高频、可迁移的语块优先于低频场景名词。
- 西班牙本地表达要标记地区和语域，避免把某一地区说法描述为全世界唯一标准。
- 解释按需展开，不能在用户开口前制造过高认知负担。
- AI 可以生成草稿和变式，但不能自动获得“已审核”状态。

## 2. 内容层级

```text
沟通能力组
  → 微型学习目标
    → 核心表达
      → 表达变体与替换槽位
        → 场景任务与验证任务
```

沉浸式内容包可以关联多个学习目标和表达，但必须指定主目标。

阅读文章是独立于沉浸式内容包的内容类型。文章可以关联主题、表达和角色世界，但阅读进度与训练任务进度分开保存；文章阅读行为不直接构成口语能力证据。

## 3. 核心表达最小字段

每条正式训练表达必须包含：

- 稳定 `externalId` 和版本号。
- 西班牙语原文。
- 简体中文自然翻译。
- 沟通能力组和微型学习目标。
- 交际意图说明。
- 目标语块。
- 可替换槽位和至少两个变体。
- CEFR 难度。
- 人物关系、正式程度和语气效果。
- 地区标记。
- 使用频率。
- 不适用或容易冒犯的情境。
- 意群、重音、音节和发音提示。
- 语法与固定搭配解析。
- 标签及标签权值。
- 输入、输出、提示、迁移和验证任务。
- 审核状态、审核人和审核时间。

推荐源文件格式为 JSON。示意：

```json
{
  "externalId": "maintain.ask-follow-up.001",
  "version": 1,
  "locale": "es-ES",
  "text": "¿Y tú, qué sueles hacer los fines de semana?",
  "translations": {
    "zh-CN": "那你呢，你周末一般做什么？"
  },
  "goalId": "maintain-conversation.ask-follow-up",
  "chunks": ["¿Y tú?", "¿Qué sueles hacer", "los fines de semana?"],
  "targetChunks": ["¿Y tú?", "soler + infinitivo"],
  "slots": [
    {"key": "time", "examples": ["los fines de semana", "por las tardes"]}
  ],
  "register": "neutral-informal",
  "region": ["es-ES", "general"],
  "cefr": "A2",
  "frequency": "core",
  "reviewStatus": "reviewed",
  "tags": [
    {"id": "strategy.follow-up", "weight": 0.45},
    {"id": "chunk.y-tu", "weight": 0.25},
    {"id": "grammar.soler-inf", "weight": 0.2},
    {"id": "fluency.turn-taking", "weight": 0.1}
  ]
}
```

真实 Schema 以 `src/modules/content/schemas/content-bundle.ts` 中的 Zod 定义为权威；生成的跨端结构契约位于 `contracts/schemas/v1/content-bundle.schema.json`，文档示例不能替代校验。

## 4. 标签与权值

标签分为：

- 沟通能力。
- 交际任务。
- 目标语块和固定搭配。
- 语法。
- 发音。
- 正式程度、语气和关系。
- 地区。
- CEFR 难度。
- 迁移类型。

权值规则：

- 单个标签权值范围为 `0 < weight <= 1`。
- 同一表达用于技能更新的主标签权值总和为 1。
- 元数据标签可以不参与技能更新，但必须显式标记 `scoring: false`。
- 不能为了让一个表达“覆盖更多能力”而平均分配大量微小权值。
- 高权值必须对应该表达真正要求用户调用的能力。

## 5. 任务设计

一条核心表达至少包含：

1. 情境输入。
2. 不展示答案的独立输出任务。
3. 三级提示。
4. 至少一个替换信息的变式。
5. 至少一个改变人物或关系的迁移任务。
6. 一个可用于抽样复核的陌生变体。

提示规则：

- 一级只提示意图。
- 二级给关键词或句型骨架。
- 三级给完整示范和一个自然替代。
- 提示不能暗示只有示范句才正确。

## 6. 意群与发音信息

- 意群按自然语义和口语节奏切分，不能机械逐词切分。
- 标出重读词、弱读、连读、音节和容易受母语影响的点。
- 默认只给最影响理解的发音提示。
- 严格纠音内容可以更详细，但每次反馈仍限制关键问题数量。
- 浏览器 TTS 只作为发音输入，不视为母语者审核替代品。

## 7. 沉浸式内容包

每个 Alpha 内容包包含：

- 120–350 词的故事、短文或对话。
- 完整音频和分段音频。
- 主沟通目标和关联表达。
- 段落、意群、词汇和语法解析。
- 听力、口语、阅读和写作活动。
- 来源、作者、许可和版权状态。
- 与角色世界的关联方式。

Alpha 首个 Web 内容包可以使用浏览器现有的 `speechSynthesis` 生成全文或分段播放，
不提交或长期保存音频文件；TTS 不构成母语者审核，也不产生口语能力证据。内容包的
听力、阅读、打字和迁移断点只保存在带内容版本的客户端本地存储中，不写入
`evidence_events`、`mastery` 或 `confidence`。需要生产发布时，内容包必须先从
`draft` 进入审核和发布状态。

活动必须区分证据强度：

- 阅读和选择只能证明识别或理解。
- 打字可以证明语境、准确性和组织能力。
- 跟读只能证明模仿和初步记忆。
- 自主开口和陌生变体才提供强口语证据。

## 8. 内容来源与版权

### 8.1 阅读文章字段

每篇可公开阅读的文章至少包含：

- 稳定 `articleId`、`version` 和规范化内容哈希。
- 标题、摘要、西语正文、语言和段落/意群结构。
- 作者、原文 URL、来源名称、发布日期和整理日期。
- `sourceType`、`license`、`attribution`、`copyrightStatus`。
- CEFR 难度、主题、地区、语域、内容形式和预计阅读时间。
- 音频、中文摘要、词语辅助和文章图片等资产的可用性与来源。
- 可关联的表达、标签、沟通目标和文章后的口语迁移类型。
- 审核状态、审核人、审核时间、版本变更原因和审核备注。

文章正文必须按段落保存，供阅读位置、高亮范围和可访问的语义结构使用；客户端不直接执行未经服务端清洗的 HTML。

允许：

- 原创内容。
- AI 辅助、经人工审核的原创内容。
- 公共领域内容。
- 遵循许可条件的 Creative Commons 内容。
- 通过明确授权、合作或授权 API 获取的内容。
- 必要的短引文，并保存作者、标题、来源链接和使用理由。
- 基于可靠来源自行撰写的事实摘要。

禁止：

- 复制付费墙或受版权保护的完整文章。
- 抓取后仅做轻微改写并当作原创。
- 删除署名或违反 Creative Commons 附加条件。
- 使用来源不明的社交媒体、课程或教材内容。
- 认为“AI 改写”会自动消除版权义务。

每个内容包保存：

- `sourceType`
- `author`
- `sourceUrl`
- `license`
- `attribution`
- `copyrightStatus`
- `reviewNotes`

每篇阅读文章同样保存上述来源与版权字段。`published` 只允许原创、公共领域、符合开放许可或有明确授权的内容；付费墙全文、绕过访问控制的抓取和来源不明的复制内容一律拒绝导入。

## 9. 人物圣经

人物内容分为：

- 不可变核心事实。
- 可以扩展但必须版本化的背景事实。
- 性格和语言风格。
- 已知人物关系。
- 可以向用户逐步透露的信息。
- 不能声称为现实存在的虚构行为。

更新人物事实时必须检查：

- 是否与已有事实冲突。
- 是否与已经向任何用户透露的事实冲突。
- 是否改变角色年龄、城市、专业等核心身份。
- 是否会造成危险、欺骗或现实资源幻觉。

关系记忆不写回人物圣经。

## 10. 审核流程

状态：

```text
draft → language-reviewed → pedagogy-reviewed → published → retired
```

要求：

- 核心表达和语用说明必须经西班牙母语者审核。
- 中文解释必须经具备教学视角的人审核。
- 版权字段未完成不能进入 `published`。
- AI 生成变式必须通过 Schema、重复和禁用词检查，再进行人工抽样。
- 修改已发布内容必须增加版本并记录变更原因。

个人 Alpha 在缺少外部审核人时，可以由项目所有者明确授权临时 AI 审核。该审核必须使用 `codex-ai-temporary-review` 标识，并在 `content_reviews.notes` 中说明其临时性质；它只用于当前个人 Alpha，不得被描述为母语者或教学专家签字，进入更大规模发布前仍需补齐真人复核。

## 11. 自动校验

内容导入前至少检查：

- 必填字段和枚举。
- 稳定 ID 与版本唯一性。
- 标签和学习目标引用存在。
- 权值范围和总和。
- 重复或高度相似表达。
- 翻译、解析和提示语言完整。
- 地区、语域和 CEFR 一致性。
- 审核状态与审核信息。
- 来源、许可和署名。
- 文章段落、正文清洗结果和内容哈希（适用于阅读文章）。
- 人物事实冲突。

校验失败时整个导入事务回滚，不允许部分发布。

当前命令：

```powershell
pnpm content:validate -- content/bundles/alpha-core-v1.json
pnpm content:import -- content/bundles/alpha-core-v1.json
```

导入以 bundle 稳定 ID、bundle 版本和规范化 SHA-256 哈希登记。相同版本相同哈希为幂等重试；相同版本不同哈希为冲突。版本化表达、场景、内容包和角色不能被其他 bundle 静默接管。

## 12. Alpha 内容验收

Alpha 首批内容满足：

- 40–60 条正式训练表达覆盖八类沟通能力。
- 每类至少有一个可独立验证的微型目标。
- 8–12 个内容包中至少 3 个与 Lucía 的角色世界有关联。
- 所有已发布内容都有简体中文版本。
- 所有核心表达已完成母语者审核。
- 所有内容包版权状态清楚。
- 首批阅读文章的来源、许可、署名、版本和审核状态完整；阅读行为不写入口语证据。
- 固定测试集包含自然替代表达、常见错误和低置信度转写样本。
