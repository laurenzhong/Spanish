## 1. 内容原则

- 内容必须服务于真实沟通目的，而不是只展示语法知识。
- 允许多种自然表达，不把唯一参考句当成唯一正确答案。
- 高频、可迁移的语块优先于低频场景名词。
- 西班牙本地表达要标记地区和语域，避免把某一地区说法描述为全世界唯一标准。
- 解释按需展开，不能在用户开口前制造过高认知负担。
- AI 可以生成草稿和变式，但不能自动获得“已审核”状态。

## 2. 内容层级

```text
沟通能力组
  → 微型学习目标
    → 核心表达
      → 表达变体与替换槽位
        → 场景任务与验证任务
```

沉浸式内容包可以关联多个学习目标和表达，但必须指定主目标。

阅读文章是独立于沉浸式内容包的内容类型。文章可以关联主题、表达和角色世界，但阅读进度与训练任务进度分开保存；文章阅读行为不直接构成口语能力证据。

视频与播客使用独立 `media` 版本，不继续扩展历史 `content_packs`。文章和媒体通过版本化文档引用、片段和来源位置进入同一词句/语料索引；语料索引不是正式内容事实来源，可以从已审核版本重建。

## 3. 核心表达最小字段

每条正式训练表达必须包含：

- 稳定 `externalId` 和版本号。
- 西班牙语原文。
- 简体中文自然翻译。
- 沟通能力组和微型学习目标。
- 交际意图说明。
- 目标语块。
- 可替换槽位和至少两个变体。
- CEFR 难度。
- 人物关系、正式程度和语气效果。
- 地区标记。
- 使用频率。
- 不适用或容易冒犯的情境。
- 意群、重音、音节和发音提示。
- 语法与固定搭配解析。
- 标签及标签权值。
- 输入、输出、提示、迁移和验证任务。
- 审核状态、审核人和审核时间。

推荐源文件格式为 JSON。示意：

```json
{
  "externalId": "maintain.ask-follow-up.001",
  "version": 1,
  "locale": "es-ES",
  "text": "¿Y tú, qué sueles hacer los fines de semana?",
  "translations": {
    "zh-CN": "那你呢，你周末一般做什么？"
  },
  "goalId": "maintain-conversation.ask-follow-up",
  "chunks": ["¿Y tú?", "¿Qué sueles hacer", "los fines de semana?"],
  "targetChunks": ["¿Y tú?", "soler + infinitivo"],
  "slots": [
    {"key": "time", "examples": ["los fines de semana", "por las tardes"]}
  ],
  "register": "neutral-informal",
  "region": ["es-ES", "general"],
  "cefr": "A2",
  "frequency": "core",
  "reviewStatus": "reviewed",
  "tags": [
    {"id": "strategy.follow-up", "weight": 0.45},
    {"id": "chunk.y-tu", "weight": 0.25},
    {"id": "grammar.soler-inf", "weight": 0.2},
    {"id": "fluency.turn-taking", "weight": 0.1}
  ]
}
```

真实 Schema 以 `src/modules/content/schemas/content-bundle.ts` 中的 Zod 定义为权威；生成的跨端结构契约位于 `contracts/schemas/v1/content-bundle.schema.json`，文档示例不能替代校验。

## 4. 标签与权值

标签分为：

- 沟通能力。
- 交际任务。
- 目标语块和固定搭配。
- 语法。
- 发音。
- 正式程度、语气和关系。
- 地区。
- CEFR 难度。
- 迁移类型。

权值规则：

- 单个标签权值范围为 `0 < weight <= 1`。
- 同一表达用于技能更新的主标签权值总和为 1。
- 元数据标签可以不参与技能更新，但必须显式标记 `scoring: false`。
- 不能为了让一个表达“覆盖更多能力”而平均分配大量微小权值。
- 高权值必须对应该表达真正要求用户调用的能力。

## 5. 任务设计

一条核心表达至少包含：

1. 情境输入。
2. 不展示答案的独立输出任务。
3. 三级提示。
4. 至少一个替换信息的变式。
5. 至少一个改变人物或关系的迁移任务。
6. 一个可用于抽样复核的陌生变体。

提示规则：

- 一级只提示意图。
- 二级给关键词或句型骨架。
- 三级给完整示范和一个自然替代。
- 提示不能暗示只有示范句才正确。

## 6. 意群与发音信息

- 意群按自然语义和口语节奏切分，不能机械逐词切分。
- 标出重读词、弱读、连读、音节和容易受母语影响的点。
- 默认只给最影响理解的发音提示。
- 严格纠音内容可以更详细，但每次反馈仍限制关键问题数量。
- 浏览器 TTS 只作为发音输入，不替代独立的语言审核。

## 7. 沉浸式内容包

每个 Alpha 内容包包含：

- 120–350 词的故事、短文或对话。
- 完整音频和分段音频。
- 主沟通目标和关联表达。
- 段落、意群、词汇和语法解析。
- 听力、口语、阅读和写作活动。
- 来源、作者、许可和版权状态。
- 与角色世界的关联方式。

Alpha 首个 Web 内容包可以使用浏览器现有的 `speechSynthesis` 生成全文或分段播放，
不提交或长期保存音频文件；TTS 不构成语言审核，也不产生口语能力证据。内容包的
听力、阅读、打字和迁移断点只保存在带内容版本的客户端本地存储中，不写入
`evidence_events`、`mastery` 或 `confidence`。需要生产发布时，内容包必须先从
`draft` 进入审核和发布状态。

活动必须区分证据强度：

- 阅读和选择只能证明识别或理解。
- 打字可以证明语境、准确性和组织能力。
- 跟读只能证明模仿和初步记忆。
- 自主开口和陌生变体才提供强口语证据。

### 7.1 私人 AI 场景与学习材料

个人 Alpha 可以从主题、阅读版本、收藏表达或最近错误生成仅属于当前用户的私人场景。私人生成内容通过 Schema、来源、角色边界和安全校验后可以立即用于学习，不需要先进入公共内容的人工发布流程；它仍保持 `private`/`draft` 语义，不能被公共内容 API 查询，也不因此获得公开发布资格。

生成接口不接受客户端把阅读正文、错误评分或正式表达内容冒充权威来源。阅读与复盘来源必须使用当前用户拥有的记录 ID，正式表达必须使用稳定 key 与版本；服务端只向 Provider 投影完成当前任务所需的短文本。生成结果必须包含可开始的临时人物、开场、沟通目标、提示、条件变化和表达，并保留来源类型、来源引用、模型版本、请求 ID、延迟和估算成本。相同幂等键与相同规范化输入复用结果，同键不同输入拒绝；Provider 失败、取消或 Schema 不合格时不得写入半成品。

公共领域、开放许可或用户有权使用的材料可以快速导入私人学习空间，但仍保存来源、许可或授权、内容版本和生成模型信息。无法确认公开分发权的第三方全文不得发布给其他用户。AI 生成的表达、纠错和变体不能直接写入正式内容或学习证据，必须经过服务端规则验证。

## 8. 内容来源与版权

### 8.0 自动采集候选

自动内容供应只读取项目所有者明确启用的白名单来源：YouTube 官方 API/RSS、播客 RSS、文章 RSS 和有记录的专用适配器。每个来源必须保存适配器、语言/地区、频率、速率限制、允许字段、权利策略、启用状态和增量游标。

每日自动化只创建或更新候选草稿，不能自动发布。候选先通过来源 ID、规范化 URL 和内容哈希去重，再依次执行相关性、语言、长度/时长、质量和权利初筛。权利不明时只保留允许取得的最小元数据，不下载大型媒体或抓取全文。

没有可用字幕的媒体只有在来源、相关性、语言、时长、权利和预算门禁全部通过后才能执行 ASR。来源人工字幕优先于自动字幕，自动字幕优先于 ASR。所有自动转写、翻译、切句、词形归一和词句说明都是草稿；低置信度片段必须在审核时明确标记。

候选状态、权利状态、审核状态和发布状态分开保存。只有候选处理完成、权利已验证、`es-ES` 内容审核与 `zh-CN` 教学审核均通过、结构校验成功且所有者显式执行发布时，才能创建不可变正式版本。

候选审核记录绑定具体 candidate revision。请求修改、拒绝和后续批准必须保留已有备注；重新处理产生新 generation/revision，旧版本批准不能沿用。候选生成者信息、Provider 输出或客户端提交的角色字段都不能自动生成批准。当前个人 Alpha 的工作台明确显示审核身份为 DSH AI（所有者授权），新记录使用 `dsh-ai-owner-authorized-review`，历史 `codex-ai-owner-authorized-review` 记录保持不变；批准后仍需单独点击发布，且缺少类型专用正式 publisher 时保持草稿并明确报告不可发布原因。

文章 RSS 来源只有在 `rights_status=verified` 且 `rights_policy.contentMode=full_text` 时才允许抓取正文。策略还必须记录许可类型、署名、可核验的 HTTPS 许可证据、feed/文章主机 allowlist、CEFR、主题、地区、语域、格式和口语迁移默认值。文章 feed 与正文页的 HTTPS 请求不得跟随到 allowlist 之外的主机，也不得绕过 Content-Type、响应体积或字符编码限制；付费墙、登录墙、正文缺失和许可字段不完整的条目不能进入可审核草稿。

采集后保存的是规范化 URL、纯文本段落、摘要、作者、发布日期、抓取时间和确定性内容哈希，不保存或向客户端返回可执行 HTML。新候选经过确定性校验后才推进到 `review_ready`。显式发布会在 article 模块的单一事务中保存正式版本、来源候选 revision、变更原因以及 `es-ES`、`zh-CN` 两份审核记录；同一候选 revision 的相同哈希幂等返回已有版本，不同哈希必须冲突，不能覆盖历史版本。撤下保留内部版本与审核审计，但公开目录和详情查询立即不可见。

YouTube 来源必须使用 `adapter_type=youtube`、`source_kind=video-channel`、官方 `UC…` channel ID、`language=es`、`rights_status=verified`，并在 `rights_policy` 中保存 `contentMode=official_embed`、`license`、`attribution`、HTTPS `licenseEvidence`、CEFR、主题、允许地区以及最短/最长时长。`YOUTUBE_DATA_API_KEY` 只放服务端环境，不得写入来源策略、候选 metadata、日志或客户端响应。Creative Commons 策略还要验证每条视频的官方许可字段；`licensed` 策略必须由来源记录中的授权证据覆盖频道及拟发布内容。

频道 Atom feed 只负责增量发现，Data API 再确认频道、公开状态、可嵌入状态、声明语言、区域限制和时长。当前真实适配器不读取非公开字幕或下载接口，因此默认候选为 `captionStatus=unavailable` 且片段为空；这类内容可以在三维审核后以“仅播放”方式发布。以后从平台允许渠道取得的人工/自动字幕仍必须标记 `platform_manual`/`platform_auto`，解析成最多 500 段、不重叠且不越过视频时长的毫秒时间轴，再独立审核后发布。

播客来源必须使用 `adapter_type=podcast-rss`、`source_kind=podcast-feed`、credential-free HTTPS feed URL、`language=es` 和 `rights_status=verified`。`rights_policy` 必须声明 `contentMode=enclosure_playback`、许可、署名、HTTPS 许可证据、feed/episode/audio/transcript 主机 allowlist、允许的音频 MIME、enclosure 与 transcript 体积上限、播放校验有效期、CEFR、主题及最短/最长时长。发现阶段只对 enclosure 发起 `HEAD` 并逐跳校验 HTTPS、主机、重定向、Content-Type 和 Content-Length，不下载完整音频；URL 不进入普通日志。

播客 episode 先按 GUID 和规范化 URL 去重，再用排除抓取时间、播放到期时间与流程备注的确定性哈希识别重发和内容变化。只有来源明确声明的西语 `text/vtt` 可进入候选；解析成功的时间轴标记 `platform_manual` 或 `platform_auto`，必须不重叠、不越界且不超过 500 段。缺失、永久失效或非法 transcript 诚实降级为无逐句文本候选；临时网络、`429` 或 `5xx` 失败必须保留游标重试，不能把临时失败固化成无 transcript 版本。`PODCAST-001` 不下载音频、不接 ASR、不生成翻译；这些处理只属于后续 `MEDIA-002`。

### 8.1 阅读文章字段

每篇可公开阅读的文章至少包含：

- 稳定 `articleId`、`version` 和规范化内容哈希。
- 标题、摘要、西语正文、语言和段落/意群结构。
- 作者、原文 URL、来源名称、发布日期和整理日期。
- `sourceType`、`license`、`attribution`、`copyrightStatus`。
- CEFR 难度、主题、地区、语域、内容形式和预计阅读时间。
- 音频、中文摘要、词语辅助和文章图片等资产的可用性与来源。
- 可关联的表达、标签、沟通目标和文章后的口语迁移类型。
- 审核状态、审核人、审核时间、版本变更原因和审核备注。

文章正文必须按段落保存，供阅读位置、高亮范围和可访问的语义结构使用；客户端不直接执行未经服务端清洗的 HTML。

允许：

- 原创内容。
- AI 辅助、经人工审核的原创内容。
- 公共领域内容。
- 遵循许可条件的 Creative Commons 内容。
- 通过明确授权、合作或授权 API 获取的内容。
- 必要的短引文，并保存作者、标题、来源链接和使用理由。
- 基于可靠来源自行撰写的事实摘要。

禁止：

- 复制付费墙或受版权保护的完整文章。
- 抓取后仅做轻微改写并当作原创。
- 删除署名或违反 Creative Commons 附加条件。
- 使用来源不明的社交媒体、课程或教材内容。
- 认为“AI 改写”会自动消除版权义务。

每个内容包保存：

- `sourceType`
- `author`
- `sourceUrl`
- `license`
- `attribution`
- `copyrightStatus`
- `reviewNotes`

每篇阅读文章同样保存上述来源与版权字段。`published` 只允许原创、公共领域、符合开放许可或有明确授权的内容；付费墙全文、绕过访问控制的抓取和来源不明的复制内容一律拒绝导入。

### 8.2 视频与播客字段

`YOUTUBE-EXACT-001`：YouTube来源策略可选`allowedVideoIds`（1–2个11字符ID，大小写精确匹配，不接受URL/空白/重复）。存在该字段即只做指定ID的官方元数据查询，空数组或无效值不会退回全频道。仍要求配置的频道与API返回频道相同，来源已有许可、署名和verified条件不会被此字段补齐，也不获得字幕取得、云处理、分发或发布许可。频道默认CEFR仍是来源选材信号；不同官方等级可分别配置单ID来源并逐项审核，不得靠一份默认值声明两条都已核实。当前稳定key历史上转小写，故单份ID列表拒仅大小写不同的组合；跨来源既有key碰撞未在本任务迁移，实际导入前须核查已有身份。本任务没有写入任何真实配置。

`MEDIA-RIGHTS-001`新增处理授权边界：来源 `rightsPolicy.mediaProcessing` 为可选严格对象，必须包含 `version:1`、非空且不重复的 `allowedOperations`（`acquire-audio`/`asr`/`translate`）、`audience`（`owner-private`/`shared-learning`）、`thirdPartyProcessing` 布尔值、无凭据HTTPS `evidenceUrl`、明确的 `expiresAt`（UTC ISO日期或null表示无约定到期）。它记录经核验实际用途的许可依据，不要求所有合法私人翻译都另求作者许可；不能从许可证标签、verified或temporaryMediaProcessing推定填写为允许。新字段不能作为自动发布批准，也不替代取得渠道、白名单、平台条款、预算和双维审核。

当前候选进入通用学习资料库流程，固定要求 `shared-learning`；未核验为私人空间前，`owner-private`不能授权该流程。ASR预检取得音频和ASR，确实要翻译时另需translate；已有字幕只补缺译文时不需要音频/ASR许可，但仍需翻译及第三方处理许可。旧来源未配本对象时继续保留发现与播放兼容，暂停新增翻译/ASR；完整已有时间轴不凭空要求新的处理许可。到期、源/候选权利变化、来源revision变化或任务过期均停止，临时资产清理照常执行。不自动迁移或扩大真实来源用途；本轮没有录入任何真实授权。字段只描述当前处理范围，不推出索引或发布权。

每个正式媒体版本至少包含：

- 稳定 `mediaId`、版本、类型（video/podcast）和规范化内容哈希。
- 标题、摘要、目标语言、地区、CEFR、主题、语域、发布日期和时长。
- 频道/节目、作者或发布者、来源页面、平台来源 ID、许可/授权、署名和权利证据。
- 播放方式、资产类型、可用性和撤下状态；客户端不获得长期有效私有资产 URL。
- 按时间排序的西语片段、可选 `zh-CN` 翻译、说话者、`startMs/endMs`、字幕来源和置信度。
- 内容、语言、教学和权利审核记录，以及版本变更原因。

YouTube 只允许精确匹配 `https://www.youtube-nocookie.com/embed/{videoId}` 的官方隐私增强嵌入，只读取平台允许取得的元数据/字幕，不下载视频或音频。候选内容哈希排除抓取时间与流程备注，避免相同内容因每日抓取产生伪变更；标题、摘要、播放身份、时长、许可或字幕内容改变时仍会形成新哈希。播客正式版本额外保存 feed URL、episode GUID、enclosure URL 哈希和带到期时间的音频资产；完整播放 URL 不进入目录卡片或普通诊断日志。enclosure 只有在权利策略允许且校验仍有效时才能发布播放，过期后服务端停止返回；重新校验与续期由后续可靠性任务处理。来源失效、节目/episode 下架、嵌入受限、许可撤销或权利存疑时停止公开投影和语料查询，并保留必要审计记录。

### 8.3 词汇、短语与语料

Tatoeba 例句录音依 ADR-0015 单独保存许可与署名，不继承句子许可；官方音频导出空许可禁止站外使用，未知许可亦拒绝。当前 `CC BY-NC` / `CC BY-NC-ND` 仅限所有者非商业 Alpha，ND 完整原样播放，不裁切/变速。现有例句不因新增音频被覆盖；官方撤下/失效给可重试不可用状态，可重新构建元数据撤除地址。

无可用授权录音的句子可按所有者 2026-10-13 明确授权提供浏览器 TTS，使用原来的西语文本和句子署名，按钮标注“合成朗读例句”，例句旁不单列“暂无录音”提示（2026-10-18 所有者要求移除该行）。它不是 Tatoeba 录音，不能附加不存在的录音作者或把合成播放当作口语/跟读证据。有原声的句子播放失败时仍给重试提示，不自动替换成合成音。

- 正式词元和短语必须保存语言、词性/类型、地区、语域、核心释义、自然变体、来源和审核版本。
- 不可靠的词形归一保持 `pending`，不能猜测 lemma 后合并同形异义词。
- 短语包含语用目的、可替换槽位和多个真实上下文，不只是脱离语境的字符串。
- 每个语料出现位置冻结 article/media 版本、片段、左右上下文和段落或毫秒位置。
- 用户的“已熟悉/想复现/暂不学习”只是私人意图，不自动成为正式内容或能力结论。
- 文字考察优先使用选择、判断和语境填空，少量完整输入只验证文字主动提取；题目与答案规则版本化并接受语义等价答案。

## 9. 人物圣经

人物内容分为：

- 不可变核心事实。
- 可以扩展但必须版本化的背景事实。
- 性格和语言风格。
- 已知人物关系。
- 可以向用户逐步透露的信息。
- 不能声称为现实存在的虚构行为。

更新人物事实时必须检查：

- 是否与已有事实冲突。
- 是否与已经向任何用户透露的事实冲突。
- 是否改变角色年龄、城市、专业等核心身份。
- 是否会造成危险、欺骗或现实资源幻觉。

关系记忆不写回人物圣经。

## 10. 审核流程

内容状态使用代码和数据库的实际枚举：

```text
draft → review → approved → published → archived
```

审核记录状态为 `pending`、`changes_requested` 或 `approved`。语言与教学维度通过 review locale 区分，不是内容状态。

要求：

- 当前仅供项目所有者本人使用的产品阶段，核心表达和语用说明由代理平台 DSH 完成 `es-ES` 语言审核，中文解释由 DSH 完成 `zh-CN` 教学审核。
- 已发布 expression 和 scenario 必须同时具有上述两个 locale 的 approved review；新记录统一使用 `dsh-ai-owner-authorized-review`（可带 `:actor[:runId]` 溯源段），备注明确 AI 身份、所有者授权、范围、修改和结论。
- domain、learning goal 和 content pack 至少具有一条 approved owner-authorized review；其中的西语和教学内容仍需纳入审核报告。
- 版权字段未完成不能进入 `published`。
- Explore 场景与表达库在生产环境只投影 `published` 的正式公共内容；开发或测试中的草稿预览必须有明确标识，不能改变内容审核状态或被描述为已发布。
- AI 生成变式必须先作为草稿，通过 Schema、重复和禁用词检查，再由 DSH 作为独立审核步骤逐项复核；生成不能自动等于审核通过。
- 修改已发布内容必须增加版本并记录变更原因。
- 自动采集、ASR、翻译或词句抽取的生成步骤与两个审核步骤必须是独立记录；不得因均由同一代理平台执行而省略独立复核。
- 所有者的“批准审核”和“发布”是两个显式动作；publisher 必须在发布事务中再次校验权利、审核、结构、内容哈希和 revision。

项目所有者已于 2026-09-12 授权上述个人产品阶段的正式 AI 审核。代理平台于 2026-10-10 从 Codex 迁移到 DSH：历史 `codex-ai-temporary-review` 和 `codex-ai-owner-authorized-review` 记录是追加式审计证据，禁止改写、迁移或回填，已发布 bundle、数据库记录和 `docs/reviews/` 报告保持原值；发布门禁同时接受历史身份与当前身份，权威定义在 `src/modules/content-acquisition/domain/review-identity.ts`。新的正式记录使用 `dsh-ai-owner-authorized-review`。产品开始邀请、允许或面向其他真实用户使用前，必须新增 ADR 重新决定是否恢复外部母语与教学复核，不能自动沿用本授权。

## 11. 自动校验

内容导入前至少检查：

- 必填字段和枚举。
- 稳定 ID 与版本唯一性。
- 标签和学习目标引用存在。
- 权值范围和总和。
- 重复或高度相似表达。
- 翻译、解析和提示语言完整。
- 地区、语域和 CEFR 一致性。
- 已发布表达和场景的 `es-ES` / `zh-CN` 双维度审核状态与审核信息。
- 来源、许可和署名。
- 文章段落、正文清洗结果和内容哈希（适用于阅读文章）。
- 人物事实冲突。
- 媒体片段时间范围、排序、重叠、字幕来源、置信度和资产可用性。
- 词元/词形状态、短语槽位、语料位置引用和撤下来源不可公开查询。
- 候选来源白名单、去重键、权利状态、两个审核维度和发布 revision。

校验失败时整个导入事务回滚，不允许部分发布。

当前命令：

```powershell
pnpm content:validate -- content/bundles/alpha-core-v1.json
pnpm content:import -- content/bundles/alpha-core-v1.json
```

导入以 bundle 稳定 ID、bundle 版本和规范化 SHA-256 哈希登记。相同版本相同哈希为幂等重试；相同版本不同哈希为冲突。内容字段和子项完全一致时，后继 bundle 可以在同一事务中单向推进既有实体状态；状态降级、归档后恢复或借状态推进修改不可变内容必须拒绝。

## 12. Alpha 内容验收

Alpha 首批内容满足：

- 40–60 条正式训练表达覆盖八类沟通能力。
- 每类至少有一个可独立验证的微型目标。
- 8–12 个内容包中至少 3 个与 Lucía 的角色世界有关联。
- 所有已发布内容都有简体中文版本。
- 所有核心表达已按当前产品阶段完成可追踪的语言与中文教学双维度审核；审核身份不得误述。
- 所有内容包版权状态清楚。
- 首批阅读文章的来源、许可、署名、版本和审核状态完整；阅读行为不写入口语证据。
- 固定测试集包含自然替代表达、常见错误和低置信度转写样本。
- 每日自动化从至少一个视频频道、一个播客 RSS 和一个文章 RSS 形成可去重候选，且不会自动发布。
- 至少一篇文章、一个视频和一个播客完成来源、处理、双维度审核、显式发布和撤下验证。
- 候选草稿最后活动后保留 30 天；拒绝候选的大型产物 7 天后删除；ASR 临时音频在成功、失败、取消或超时后立即删除。
